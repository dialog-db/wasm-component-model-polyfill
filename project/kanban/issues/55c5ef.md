## What to build
The fourth feature is correctness across the whole async model rather than new mechanism: `error-context.new`, `error-context.debug-message`, `error-context.drop`, transfer of an error-context between components, and `error-context` as a value type; `task.cancel` and the cancellation edge cases (delivery, exclusive locks, cancellation during a copy); the rules under which a built-in's trap poisons an instance; and deadlock detection with the trap the spec prescribes. State how each trap message matches Wasmtime's wording, as the synchronous trap work did.

Two inputs from the checkup of 2026-09-21. The may-leave flag exists twice today, as the adapters' core global and as `InstanceRecord::may_leave`, and the host-import, `resource.new`, and `resource.drop` trampolines check neither; card `7feb91` unifies it, and the poisoning rules this design states must assume that one flag. And a failure that belongs to no call, such as a host task that fails after a pending poll, surfaces today as the error of whichever driver is polling, where Wasmtime poisons the store; card `6c8808` settles the interim rule, and this design is where the store-level poison, if that is the answer, is described in full.

Name the corpus files this phase owns (for example `cancel-delivery.wast`, `cancel-and-exclusive-lock.wast`, `builtin-trap-poisons-instance.wast`, `trap-if-done.wast`, `trap-if-block-and-sync.wast`, `trap-if-sync-and-waitable-set.wast`, `trap-if-transfer-in-waitable-set.wast`, `deadlock.wast`, `self-switch-traps.wast`, `big-interleaving-test.wast`, `error-context-trap-in-post-return.wast`) and any that stay deferred with the reason.
