## What to build
`transfer_borrow` (`src/executor/intrinsics.rs:455-456`) and `lift_handle` (`src/abi/lift.rs:407-414`) treat a borrow leaving the instance that defines the resource as a rep in hand: `if src.defining { index }`, with no table lookup and no lend. The reference's `lift_borrow` (`definitions.py:1458-1464`) always does `cx.inst.handles.get(i)`, traps on a non-resource entry, and `add_lender(h)`; only `lower_borrow` (`:1762-1765`) short-circuits to the rep when the receiving instance is the resource's implementation. Wasmtime's `resource_transfer_borrow` (`crates/wasmtime/src/runtime/component/instance.rs`, around lines 425-447) lifts on the source unconditionally and special-cases the destination only. The polyfill's own `transfer_own` at `intrinsics.rs:437-440` goes through `remove_own` with no defining shortcut, so the two paths disagree with each other, and `resource.new` in the defining instance inserts into its table and returns the index (`src/executor/trampoline.rs:236-241`), so index and rep differ from the first handle. An outer component that defines `R` (rep 42 at index 1), instantiates an inner component `(with "r" (type $R))`, and passes its handle to the inner's `borrow<R>` export hands the inner 1; a method the inner then calls lowers back into the outer with 1 as the rep, and the owner was never lent, so the outer can drop it during the call. Neither corpus has the outer-defines, inner-borrows shape. Drop the defining shortcut on both lift sites, keep it on the lower side, and add the fixture.

## Acceptance criteria
- [ ] A fixture where the defining component passes its own handle as `borrow<R>` to a nested component that calls a method on it proves the method sees the rep, not the index, on both targets.
- [ ] While that borrow is out, a `resource.drop` of the owning handle in the defining instance traps with the borrowed-resource cause.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
