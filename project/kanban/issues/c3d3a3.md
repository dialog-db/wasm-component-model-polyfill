## What to build
The conformance harness's `Module` arm (`tests/conformance.rs` around lines 157-170) inserts into `self.named` and registers with the linker only when a `(component $A ...)` succeeds, so a definition that fails leaves an earlier `$A` and its linker registration bound — the same defect the `ModuleDefinition` arm had before it was fixed to remove the binding before compiling. Remove the earlier name and its registration before compiling, so a failed definition leaves neither behind, and rerun the harness on both targets to see whether any corpus directive changes outcome; refresh the expected-failure lists and README table if one does.

## Acceptance criteria
- [ ] A failed `(component $A ...)` leaves `$A` unbound and unregistered; a harness unit test proves a later directive naming it fails with no definition.
- [ ] The expected-failure lists and README table match the harness on both targets.
- [ ] `lint` passes and `tests all` is green on both targets.
