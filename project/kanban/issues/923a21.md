## What to build
From the review of card 576452 (landed as `481dc3af6`), finding F1. Today a task ends when its implicit thread exits. Its queued `ThreadStart` items are then dropped silently (`src/concurrency/scheduler.rs:1088` `discard_task_items`; the item is `for_task` at `src/executor/thread_builtins.rs:172-177`), and `exit_implicit_thread` raises `NoResult` and checks borrows even when a pending thread could still call `task.return` (`src/executor/async_lift.rs:99-107`). The limitation is documented at `async_lift.rs:18-26`.

The reference unregisters the task only when its last thread ends (`definitions.py:453-457`), and Wasmtime traps `NoAsyncResult` only when `threads.is_empty()` (`crates/wasmtime/src/runtime/component/concurrent.rs:2349`). PDD022 states the same rule: the no-result failure applies only "if the task has no other thread and has not resolved". So a task that resolves, then exits its implicit thread with a ready explicit thread, loses that thread's work; and `task-return-traps.wast:56`/`:91` pass because the message and outcome match, not because the reference path runs.

Keep the task alive until its last thread ends: an explicit thread started with `thread.new-indirect` and made ready runs after the implicit thread exits, may call `task.return`, and the no-result check and the borrow check run when the last thread ends.

## Acceptance criteria
- [ ] A task whose implicit thread exits before an explicit ready thread has run keeps running that thread; the thread's work is observable.
- [ ] An explicit thread may call `task.return` after the implicit thread exited; the task then resolves without a no-result failure.
- [ ] The no-result failure and the borrow check happen when the task's last thread ends, as in `definitions.py:453-457`.
- [ ] `task-return-traps.wast:56` and `:91` pass through the reference path; say how that was checked.
- [ ] `tests all` and `lint` are green.
