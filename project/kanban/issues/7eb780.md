## What to build

Step 3 of the migration (switch). In one change, point the seam at `wcmp-wasm-core` on both targets: the Wasmtime backend natively and the browser backend on the web. A split makes the polyfill build against two runtime layers at once, which costs more than it saves.

The changes that cross the seam land here:

- **Engine.** The polyfill's `Engine` takes the backend that the host gives (`Engine::with_backend`). There is no default backend on any target. The polyfill holds the backend behind dynamic dispatch, and its public types carry no backend type parameter. Update the tests, benches, smoke apps, and scenario runners to name their backend.
- **Asynchronous instantiation** on both targets.
- **Host suspension.** The scheduler's JSPI provider becomes the host-suspension provider, used on every backend that declares `host_suspension`. The provider, the switch module, and the scheduler stay in the polyfill.
- **Trap kinds.** The polyfill reports traps through `TrapKind`. The Component Model trap kinds stay in the polyfill.
- **Host functions** go through the new layer's host functions (the browser's generated wrappers).

The switch is where most Zena scenarios move past `parse`. Regenerate the records then; an outcome may move from fail to pass, never from pass to fail.

## Acceptance criteria
- [ ] The polyfill depends on `wcmp-wasm-core` and no longer uses `wasm_runtime_layer` on either target.
- [ ] `Engine::with_backend` is the only way to make an engine, on every target.
- [ ] No outcome in the conformance record or the Zena record moves from pass to fail, on any lane. The regenerated records are committed.
- [ ] No public signature of the polyfill names a runtime layer type. The public API check holds this.
- [ ] The canonical ABI makes the same number of memory accesses for lists of lengths 1, 100, and 10,000, lifted and lowered, on the Wasmtime and browser backends.
- [ ] The string and list benchmarks run before and after the switch. No native result is slower beyond the suite's noise, and each web result is the same or faster. The card records both runs.
- [ ] `tests all` passes.
