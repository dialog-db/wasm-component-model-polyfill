## What to build
`src/backend.rs` describes the browser's refusal of a re-entrant host call as reaching "the very import the block is inside" and calls it the one shape of component that fails only in the browser. It is broader: a nested turn also refuses any task that calls a host function already on the stack, including the blocking built-in's own trampoline, so two tasks of one instance both blocking in `waitable-set.wait`, or two synchronous lowers of the same host `async` import, fail in the browser and succeed natively. Card `0a7c63` makes the cause reach the host; this card states the rule where a reader looks for it: the module doc of `backend.rs`, the target paragraph of `tests/corpus/README.md`, and the Target Differences section of PDD020, in the form "without a suspend provider, a nested turn cannot enter any host function already on the stack".

## Acceptance criteria
- [x] The three documents state the rule, and PDD020 is formatted with `markdown format`.
- [x] A web test pins one shape (two tasks of one instance blocking in the same built-in) as refused with `SchedulerCause::ReentrantHostCall`, and the same component passes natively.
- [x] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.


## Review notes
- 2026-09-22T08:03:13Z from the review of 0a7c63 (`a6b05f4`): the breadth statement must say the refusal is per `canon resource.drop` definition, not per resource type — two separate `(canon resource.drop $r)` definitions over one type are not refused (`backend.rs:27-33`, `error.rs:853-868` overstate in the safe direction); an import from an outer nesting level still on the stack is refused (`suspend_seam.rs`); and a vendored ordering hazard: `refuse_reentrant_call` (`rust/vendor/js_wasm_runtime_layer/src/func.rs:136`) records the cause only when `pending_host_error` is empty, so a guest that caught an earlier host-function exception and then re-enters loses the cause everywhere.
