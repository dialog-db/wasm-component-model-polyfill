## What to build
Prove, and fix where a proof fails, that the thread built-ins run under a provider on both targets. A switch under a provider names the next thread, and the frame that resumed the current thread runs it before anything else. Under JSPI, a thread that a nested start began and that switches to a suspended thread before it first suspends follows the rule of the JSPI provider: the trampoline's thread suspends as well, and only the reference's threads run in the interval.

The thread directives:
- Component Model corpus: `during-sync-call-exclusive-resume.wast`, `self-switch-traps.wast`, `switch-to-ready-callback.wast`, `trap-if-sync-and-waitable-set.wast`, `reentrance.wast:557` and `:701`, and `values/post-return.wast:4`.
- Wasmtime corpus: `join-during-sync-read.wast`, `thread-transparency/reentrancy.wast`, and the two directives of `task-return-traps.wast` that extract a table (21, 58).

The cascade lines of each owned file go with it. `reentrance.wast:548` and `:891` fail for another cause; they keep that cause and stay in the shared list.

## Acceptance criteria
- [ ] With a provider, `self-switch-traps.wast`, `switch-to-ready-callback.wast`, `trap-if-sync-and-waitable-set.wast`, `during-sync-call-exclusive-resume.wast`, `join-during-sync-read.wast`, `thread-transparency/reentrancy.wast`, and `values/post-return.wast` pass on both targets.
- [ ] With a provider, `reentrance.wast:557` and `:701` and the two table directives of `task-return-traps.wast` pass on both targets, and `reentrance.wast:548` and `:891` keep their other cause.
- [ ] Each thread directive that fails without a provider sits in `expected-failures.no-provider.txt`, set by a live run.
- [ ] `lint` passes and `tests all` is green in all four states. A directive that starts passing under a provider leaves the shared list. A line that still fails without a provider sits in `expected-failures.no-provider.txt` with the stack-switch reason. Every line whose reason this card changes is refreshed from a live run.
