## What to build
When a blocking built-in's nested turn goes idle with its condition unmet, the suspend seam fails with the idle-store cause, whose message is Wasmtime's "deadlock detected" and whose documented rule is that nothing left in the store can ever meet the condition. That rule is untrue in one shape the corpus shows: a synchronous callee runs inline above its caller's frame, and the caller *could* meet the condition once control returns to it (`stream-zero-ops.wast:201`, and `streams-massive-send.wast` once futures land). There the real cause is that only a stack switch can reach the frame below, which is what the stack-switch cause exists to say.

Decide which cause such a block should report, and make the cause and its documentation tell the truth. If the seam can tell that a frame below the blocked one belongs to a task that could still progress, report the stack-switch cause there; if it cannot, restate the idle-store rule so it no longer claims that nothing can meet the condition. Compare with Wasmtime at the corpus commit, where the same shapes run on fibers and do not deadlock. Keep the corpus lines' reasons consistent with the result, refreshed from a live run.

## Acceptance criteria
- [ ] The cause reported for a block that only a frame below could release is decided and stated, with the reason, in the seam's documentation and the `Error` docs.
- [ ] A repository test proves the chosen cause for that shape, and the idle-store cause is still proved for a truly idle store.
- [ ] Every corpus line whose reason changes is refreshed from a live run on both targets.
- [ ] `lint` passes and `tests all` is green on both targets.
