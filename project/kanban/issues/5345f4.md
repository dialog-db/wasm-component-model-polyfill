## What to build
`StoreContext::run_turn` (`src/store/store_context.rs` around line 635) now calls `open_entry_gate()` once more after `poll_host_tasks`, so a task a host task's body released or queued past the gate becomes ready before the turn reports Waiting or Idle. The change landed with the asynchronous-lower card because the `call_concurrent` review found that a gated start queued from a host task's body under a plain `Driver` would otherwise park without a wake; its reviewer judged it correct but no test reaches it (every host-task body in the tests touches nothing of the store). Add the test: a host task whose body, through the accessor, makes a `call_concurrent` into an instance a callback task holds, and asserts the turn that polls the body reports Progress and the released start runs in the next turn behind the items `poll_host_tasks` queued. State the rule on `run_turn`'s doc. A genuine deadlock — the waiting task holds the instance the gated start needs — is not closed by this and belongs to a design decision; note it, do not solve it here.

## Acceptance criteria
- [ ] A test proves a gated start queued from a host task's body runs without a driver re-poll, and in arrival order behind the turn's other released items.
- [ ] `run_turn`'s doc states when the gate is opened within a turn.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
