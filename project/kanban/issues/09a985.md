## What to build
The corpus README defines `cascade` as a consequence of an earlier failure in the same file and `deferred-feature` as a feature the polyfill does not implement yet. The expected-failure list (`tests/corpus/expected-failures.txt`) records many bookkeeping failures — `no definition named ...` and `no instance to invoke` after a definition failed — under `deferred-feature` (about 178 and 341 lines respectively, against 36 and 65 under `cascade`); the harness fix that unbinds a failed definition recorded its eight new lines under `cascade`, and the reviewer of that card judged the legacy lines the mislabelled ones. Normalise the list so every bookkeeping consequence of an earlier failure in the same file is `cascade`, refresh the README baseline table's category counts from a live run on both targets, and amend the README prose (around lines 22-29) so the paragraph on the async rows accounts for the cascade lines it now carries.
