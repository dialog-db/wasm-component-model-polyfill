## What to build
The convention "no `pub(crate)`; control the API from `lib.rs` re-exports" cannot hide methods or fields on a re-exported type. `Store` exposes `context`, `store_data`, `store_data_mut`, `id`, `tables`, `tables_handle`, `lock_tables`, `scheduler`, `scheduler_mut`, `turn_in_flight`, `has_pending_work`, `turn`, `inner`, and `inner_mut` (`src/store/store.rs:69-137`), each documented as workspace-internal; `StoreContext` exposes `turn`, `nested_turn`, `run_in_turn`, `start_host_task`, `push_host_task`, `scheduler_mut`, `lock_tables`, `runtime_mut`, `register_resource`, `abandon_export_task`, and more. The values they return (`Scheduler`, `HandleTables`, `StoreData`, the runtime-layer store) are unnameable outside the crate but fully usable by method syntax. `ResourceHandle` has public `type_id`, `index`, and `rep` fields (`src/resource/handle.rs:31-45`), and `Instance` (`src/instance/instance.rs:78-108`), `Module::inner`, `CoreExtern::inner`, `CoreInstance::inner`, and `LinkerInstance::registration` are public too. Safe host code can therefore forge a handle and release it through `Store::resource_drop`, call `scheduler_mut().take_host_tasks()` from inside a `HostCall` and drop every pending host call, or run a turn from a trampoline; each is also a semver commitment. The reviewer of card `c723cc` flagged the same class for `Store::register_resource`.

Inventory every `pub` item reachable from the re-exports that the docs call workspace-internal, then apply the pattern the owner chose below, and make `ResourceHandle` opaque with accessors.

## Owner decisions (2026-09-21)
Internal API lives on a separate struct that is not re-exported: `StoreInternal<'a, T>` over `&'a mut Store<T>` takes `scheduler_mut`, `lock_tables`, `tables_handle`, `turn`, `inner_mut`, `store_data_mut`, and the rest; `StoreContextInternal<'b, 'a, T>` over `&'b mut StoreContext<'a, T>` takes `turn`, `nested_turn`, `run_in_turn`, `start_host_task`, `push_host_task`, `register_resource`, `abandon_export_task`, and the rest. Every method keeps its signature; the borrows it returns are tied to the wrapper's borrow as they are tied to `&mut self` today. The one rule that makes the pattern hold: no `pub` method on an exported type may return the wrapper, or the leak this card closes is back. Crate code obtains a wrapper through an associated function on the unnameable type (`StoreInternal::of(&mut store)`) or through an extension trait in a private module, which cannot be imported outside the crate, so `store.internal()` resolves only inside it. `ResourceHandle`'s fields go private with read accessors, and the crate builds one through an unnameable parts struct rather than a public constructor. `pub(crate)` is acceptable for an item only with a written explanation, on the card, of why the wrapper pattern does not fit it. The integration-test probes of the internal surface (24 sites in nine files, and the hand-built bogus handle in `tests/baseline_resources.rs`) move into unit tests inside the crate, which the web lane already runs in a browser.

## Acceptance criteria
