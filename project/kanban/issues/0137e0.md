## What to build

The spec removed the `cancellable` immediate (component-model #716). Wasmtime
50 removed it too (`b016297de`). wasmparser 0.261 rejects the byte when it
parses a component (`canonicals.rs:467-479`). wit-component 0.261 no longer
accepts `[cancellable]` imports. The polyfill kept the immediate because
Wasmtime 49 and the toolchain still read it. Now every source agrees, so the
polyfill removes it.

Remove the immediate from the translator, the IR, and instantiation. Remove
the rules that only a cancellable built-in uses: `WaitableSetOrCancel`,
`cancellable_yield`, `takes_cancel_at_once`, `take_pending_cancel_of`, the wake
loop in `cancel.rs`, and `switch_to_parked_thread`. If a piece stays, the code
says why.

One rule is still spec behavior: a built-in never takes a pending request, and
only a callback gets the task-cancelled event. That rule keeps a test.

The smoke worker stops its guest thread with a cancellable yield
(`wcmp-smoke/src/lib.rs:3040-3145`). It must learn of the cancel through the
task-cancelled event of a callback-lifted task instead.

This card lands in the same series as 2397ff. The workspace does not build or pass on Wasmtime 50 without it.

## Acceptance criteria

- [x] No `cancellable` remains in the translator, the IR, or the built-ins.
- [x] `tests/baseline_cancellable.rs` is gone, and `baseline_cancel.rs` keeps
      the rule that a built-in never takes a request.
- [x] The smoke worker shows cancellation with the provider on and off, and
      `wcmp-smoke` drops its `wasmparser` dependency if nothing else uses it.
- [x] `notes/feature-support.md` no longer says the immediate is honored.
