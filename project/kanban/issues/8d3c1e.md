## What to build
Close the gaps the independent review of card 7bf3c5 found in the Zena test host's clock (landed as `02e9db7fe`, `tests/zena/host.rs`). None blocked the card.

- **Long waits in the browser.** A browser `wait-for` longer than 2^31-1 ms (about 24.8 days) overflows `setTimeout` and fires at once (`host.rs:309-317`). The native host clamps. Clamp or chain the browser timer.
- **Timers after cancel.** On cancel or store drop, the browser timer is never cleared and later fires into an orphaned promise (`host.rs:315-325`). It is harmless but should be cleared.
- **Clock fallback.** The `Date::now` fallback at `host.rs:300` is not monotonic. Say so, or remove the fallback if it cannot be reached.
- **Dependencies.** `Cargo.toml:82-83` repeats `js-sys` and `wasm-bindgen` under the wasm32 dev-dependencies, against the comment at `Cargo.toml:53`. Reconcile the two.
- **Tests.** Add a test that cancels a wait, one that drops the store mid-wait, and a stand-in that keeps a stdout stream open across an async sleep, as scenario 6 does.

## Acceptance criteria
- [ ] A browser wait longer than 2^31-1 ms does not fire early.
- [ ] Cancelling a wait or dropping the store clears the browser timer, and a test covers each on both targets.
- [ ] A stand-in with stdout open across an async sleep passes on both targets.
- [ ] `tests native debug` and `tests web debug` pass.
- [ ] `lint` passes.
