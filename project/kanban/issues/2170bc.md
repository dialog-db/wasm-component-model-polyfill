## What to build
Let the store cap the number of its live records. The records it counts are tasks, subtasks, threads, host tasks, waitable sets, and the shared records of streams and futures. Error-context records join the count on the card that makes an error context cross between components.

- A new record past the cap fails with Wasmtime's "resource table has no free keys" (`crates/wasmtime/src/runtime/component/resource_table.rs:20-75` at `v49.0.0-rc.1`), as a structured cause of `wcmp::Error`.
- A cap lower than the current count evicts nothing. Only new records fail.
- The default cap is 1,000,000 records, Wasmtime's default.
- Only the store's internal API changes the cap. No public method does. The conformance harness is an integration test and cannot see the private `internal` module (`src/lib.rs:208-239`), so decide how the harness reaches the setter without widening the public API, and state the choice in the card's review notes.

The conformance harness registers `set-max-table-capacity` in its `wasmtime` instance (`tests/conformance.rs:939`, which registers only `gc` today), as Wasmtime's wast runner provides it (`crates/wast/src/wast.rs:258-270`). `wasmtime/async/cancel-starting-subtask-does-not-leak.wast` then links. It cancels and drops a held-back call 1,000 times under a cap of 100, so it passes only once `subtask.cancel` of a starting callee runs too. Whichever of the two cards lands second removes its lines 9 and 103 from the expected-failure list.

## Acceptance criteria
- [ ] A repository test proves that a new record past the cap fails with "resource table has no free keys", that a cap below the current count evicts nothing, and that the default cap is 1,000,000.
- [ ] The conformance harness provides `wasmtime.set-max-table-capacity`, and `cancel-starting-subtask-does-not-leak.wast:9` no longer fails at link; its line passes, or its reason is refreshed to the `subtask.cancel` failure.
- [ ] No public method changes the cap; `api` shows no new public item for it.
- [ ] `lint` passes and `tests all` is green on both targets, any directive that starts passing has its line removed from the expected-failure list, and every line whose reason this card changes is refreshed from a live run.
