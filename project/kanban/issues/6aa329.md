## What to build

PDD028, "Host Data Projection" and "Access and Accessor", with the revisions it makes to PDD020 and PDD021. The runtime types that generated code registers through, after Wasmtime's `has_data.rs:288-305` and `concurrent.rs:216-520` at `v49.0.0-rc.1`. No macro work.

- **`HasData` and `HasSelf<T>`.** `HasData: 'static` with one generic associated type `Data<'a>`. `HasSelf<T: ?Sized>` projects to `&'a mut T`. No value of a `HasData` type exists.
- **`Access<'a, T, D = HasSelf<T>>`.** Holds the store context and a projection `fn(&mut T) -> D::Data<'_>`. `get` gives `D::Data<'_>`, `data` and `data_mut` give the host data, and `store` gives the store context as `HostCall::store` does. A host function can build one from the `HostCall` of a call, so a `store`-flag registration needs no new kind of host function.
- **`Accessor<T, D = HasSelf<T>>`.** Today's token (`rust/wcmp/src/concurrency/accessor.rs`) gains a projection. `with` runs a closure that receives an `Access<'_, T, D>` and keeps returning `Result<R>`: a reach from inside another reach, or outside a poll of the store, fails with today's PDD020 error. `getter` gives the projection, and `with_getter::<D2>` gives an accessor of the same store with another projection. `Accessor` stays `Clone`.
- **`AsAccessor`.** The trait of any accessor, whatever its projection. `Accessor` and a reference to an `AsAccessor` implement it.
- **Call sites.** `TypedFunc::call_concurrent`, `Func::call_concurrent` (and `call_concurrent_values`), and `close_with` and `guard` on `StreamReader` and `FutureReader` take an `impl AsAccessor`. The guarded readers carry the accessor they were given. Move every caller.

Re-export the new types flat from `lib.rs`, one public type per module.

## Acceptance criteria
- [x] A host function registered through a hand-written projection to a view type with two borrows of the host data (a context and a `ResourceTable`) reaches both borrows, on both targets.
- [x] `Accessor::with` hands its closure an `Access` whose `get` gives the projected view, and a reach from inside another reach still fails with the PDD020 error.
- [x] `with_getter` gives an accessor of the same store with another projection, and a host future that holds it reaches the new view after an await, on both targets.
- [x] `TypedFunc::call_concurrent` from inside `run_concurrent`, with an accessor whose projection is not `HasSelf`, returns the export's result.
- [x] `close_with` and `guard` accept an accessor of a non-`HasSelf` projection, and a guarded reader closes its end on drop as before.
- [x] `lint` passes, and `tests all` is green on both targets with the conformance summary unchanged.


## Delivery notes

Delivered on the host (no sandbox) in `feat(accessor): Give the accessor a projection of the host data`. `Access` holds a `StoreContext` by value; a synchronous host function builds one with `Access::new(call.into_store(), getter)`, so `HostCall` gained `into_store`. `Accessor::with` hands its closure an `Access`, so every `accessor.with(|store| …)` caller moved to `access.store()` or `access.data*()`. `GuardedStreamReader`/`GuardedFutureReader` now take the accessor type `A: AsAccessor` as Wasmtime's do. Tests: `rust/wcmp/tests/baseline_projection.rs` and two guard cases in `src/baseline/host_end_lifecycle.rs`. `lint` and `tests all` green.
