## What to build
Typed calls for a closed set of signatures, and scenarios 2, 3, and 4.

- **Typed calls.** An expectations entry can ask for a typed call. The runner supports it for scalars and `string` only, through the polyfill's `TypedFunc` and, in the Wasmtime run, Wasmtime's `TypedFunc`. A contributor still writes no Rust code per scenario.
- Scenario 1 gains a typed call on its scalar export.
- Scenario 2: a string in and a string out, called untyped and typed.
- Scenario 3: classes and arrays, used inside the program only.
- Scenario 4: exceptions, one caught inside the program and one uncaught. The uncaught call is made twice; the second entry has no outcome, so the Wasmtime run decides whether the instance still answers.
- Regenerate and commit the record lines.

## Acceptance criteria
- [ ] Scenario 1 calls its scalar export with `TypedFunc`, and scenario 2 calls its string export with `TypedFunc`. The typed call and the untyped call give the same results on every subject that reaches the call.
- [ ] Scenario 4 makes its uncaught call and then a second call on every subject. The `web` and `native` subjects pass only when each call fails or succeeds as it did in the Wasmtime run.
- [ ] The record holds lines for scenarios 2, 3, and 4, and `tests zena` passes the gate.
- [ ] `tests native debug`, `tests web debug`, and `lint` pass.
