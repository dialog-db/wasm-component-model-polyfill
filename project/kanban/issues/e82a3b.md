## What to build
The review of card `0a7c63` accepted that every guest-call site names the re-entrant cause and left findings that need one card. First, the end-to-end tests: only the destructor site has a browser test; a real realloc refusal, a post-return refusal (`src/abi/context.rs:336`) and a host-release refusal (`src/store/store_context.rs:234`) have none, and the unit test at `context.rs:644` synthesizes `Error::Scheduler`, so it exercises `reentrant_refusal`'s second branch rather than the backend-type branch a real browser refusal carries; `BoundaryContext::unlabelled`'s refusal branch and the `ResourceDestructor::Host` arm are untested too. Second, the native test at `tests/baseline_reentrant_drop.rs:139` asserts two destructor runs, which a sequential drop would also produce; a depth probe (a guest global set before the inner drop and read by the inner run) proves the inner ran nested inside the outer. Third, `backend::reentrant_refusal`'s `Error` branch matches only a top-level `Error::Scheduler(ReentrantHostCall)`; a host destructor that returns it nested under `Error::Abi` is still flattened. Fourth, returning the cause discards the accumulated context (`DESTRUCTOR_FAILED`, the ABI position and value type), so the host learns the cause but not the site; decide whether the refusal carries its site. Fifth, a vendored ordering hazard, pre-existing: `refuse_reentrant_call` in `rust/vendor/js_wasm_runtime_layer/src/func.rs:136` records the cause only when `pending_host_error` is empty, so a guest that caught an earlier host-function exception and then makes the re-entrant call loses the cause at every site; decide whether the refusal overrides a pending error and record the patch in `PATCHES.md`.

## Acceptance criteria
- [ ] A browser test each proves a realloc refusal, a post-return refusal and a host-release refusal reach the host as `Error::Scheduler(SchedulerCause::ReentrantHostCall)`.
- [ ] The native re-entrant destructor test proves nesting, not only the count.
- [ ] A host destructor's nested `ReentrantHostCall` is unwrapped, proved by a test; the refusal names its site or the doc states why it does not.
- [ ] A guest that caught an earlier host exception and then re-enters still yields the re-entrant cause, or the design states the limit; `PATCHES.md` records any vendored change.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
