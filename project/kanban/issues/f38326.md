## What to build
Replace the `Error::Unsupported` placeholder in `Func::call` (`src/instance/func.rs`) and the typed call: a host call into an export whose options are `async_` is a task, created with `create_export_task` as today, whose `TaskStart` item pushes the task as the current scope, lowers the arguments through one `BoundaryContext` (a realloc it calls is its own task), marks the task started, calls the core function, pops the scope, and hands the returned status word to a `handle_status_word`. Start it with `start_export_thread(task, instance, async_function = true, needs_exclusive = true, item)`, so the item waits at the entry gate while the instance's backpressure is set or its exclusive thread is held, and the call's `Driver` resolves when the task's result is set, returning the lifted value; the core function may still be on the stack below `task.return`, and then the driver sees the result in the same turn after it returns. When the driver's turn finds the task at the gate or waiting and nothing else ready, it fails with the deadlock cause. There is no post-return for an asynchronous task. The status word's low four bits are the code and its high bits a waitable set index; a code above two traps with the unsupported-callback-code cause. Exit calls `exit_implicit_thread`: a task that has not returned fails with the no-result cause, otherwise its record leaves the store as a synchronous task's does. Yield releases the exclusive thread and pushes a `Callback` item with the none event on the low-priority queue (`Scheduler::push_low_priority`), so it runs after every other ready item and after the driver returned control to the host executor once, natively by self-wake and in the browser across a macrotask hop. Wait looks up the set in the instance's handle table (trapping when the entry is not a set), releases the exclusive thread, and either pushes the callback item with the set's first event in join order on the high-priority queue, or sets the implicit thread's readiness to a new `Readiness::WaitableSet` (`src/concurrency/readiness.rs`) and counts the waiter with `begin_wait`; when a later turn fills an event in a waitable of the set (`TaskTables::set_pending_event`), the scheduler ends the wait and queues the callback item with that event. Running a callback item checks the instance's exclusive thread: held by another, the item is deferred until the holder releases; otherwise the item takes it, pushes the task scope, calls the callback with `(code, payload1, payload2)`, pops, and handles the word. An error a callback item raises fails the driver whose turn ran it, not the call that started the task, which is Wasmtime's rule for a task that keeps running after it returns. Dropping the call's future cancels nothing: the task stays in the store and its item runs in the next turn of any driver, whether a later call, an instantiation, or `run_concurrent`. Every case has the same result on both targets. No corpus directive reaches the yield or wait word from the host, so those cases are repository tests on components written by hand; a test seam fills an event by inserting a subtask waitable in the set through the store's records.

## Acceptance criteria
- [ ] A callback export that calls `task.return` and returns the exit word in its first call resolves the call with the lifted result, leaves the task resolved and removed, and releases the instance's exclusive thread; `TypedFunc::call` on the same export returns the result with no change to the host's code.
- [ ] An export that calls `task.return` and returns the yield word resolves the call at `task.return`; its callback receives the none event in a later turn, after every other ready item and after the driver returned control to the executor once, with the context slots the export set, and returns exit.
- [ ] An export that returns the wait word on a set with no event fails the call with the deadlock cause and Wasmtime's message; `drop-deadlock.wast` passes whole for the gate variant of the same failure.
- [ ] A test seam fills an event in a waitable of the set and the callback receives that event with the waitable's index and payload; a second wait on a set that already holds an event runs in the next turn without an idle.
- [ ] A code above two fails with the unsupported-callback-code cause, and the set index is read from the high bits of the word.
- [ ] The first directive of `task-return-traps.wast` passes: exit without `task.return` fails with the no-result message; its other directives keep their deferred lines with the stackful-lift and thread-built-in reasons.
- [ ] An export that calls `task.return`, returns the yield word, and whose callback then traps resolves the call with its result, and the next driver of the store fails with the trap; dropping the call's future leaves the task in the store to run in the next turn.
- [ ] `tests all` passes on both targets, and any async directive that starts passing has its line removed from the expected-failure list.
