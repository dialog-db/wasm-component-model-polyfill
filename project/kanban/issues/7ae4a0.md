## What to build

Step 1 of the migration (build beside). Add the faithfulness suite: the official WebAssembly specification test suite ([spec tests](https://github.com/WebAssembly/testsuite)) at a pinned revision, run on one backend through the `wcmp-wasm-core` trait. This card runs it on the Wasmtime backend.

- **Pin.** Add the test suite as a pinned input (for example a flake input), as the project pins its other test corpora.
- **Runner.** Run each `.wast` script through the trait only, not through Wasmtime directly, so every backend can use the same runner. Run the Wasm 2.0 scripts (the floor) and the scripts of each capability the backend declares.
- **Expected failures.** Each backend has a list of expected failures. Each entry cites a defect of the engine (an issue or a source line). An entry without a citation fails the check. If a feature has failures that no engine defect explains, the backend does not declare that capability.
- **Menu command.** A menu command runs the suite per backend, and `tests all` runs it.

## Acceptance criteria
- [ ] The spec test suite is pinned to one revision.
- [ ] The runner uses the `wcmp-wasm-core` trait only.
- [ ] The Wasmtime backend passes the floor scripts and the scripts of each capability it declares, apart from the cited expected failures.
- [ ] An expected-failure entry without a citation fails the check.
- [ ] A menu command runs the suite, and `tests all` includes it.
- [ ] `lint` passes.
