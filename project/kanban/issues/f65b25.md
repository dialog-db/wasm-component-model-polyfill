## What to build
The translator (`src/executor/translate.rs`, the refusal at line 914) accepts `task.cancel` and `subtask.cancel` and gives each a trampoline (`src/executor/ir.rs`, `src/executor/instantiate.rs`, `src/executor/trampoline.rs`) that checks the instance's may-leave flag and then fails with `Error::Unsupported` when a guest calls it. The cancelled event is never delivered. This is the one exception to the rule that the translator refuses what is not built, and it exists so a guest whose binding layer links either built-in, as wit-bindgen's Rust runtime does in every `async` export and every awaited import, instantiates and runs every path that does not cancel. The `subtask.cancel` component of `task-builtins.wast` and the fifth component of `cancel-sync-and-waitable.wast` now instantiate, and the latter's directive fails at the call. Every file deferred for cancellation keeps its reason: a directive that only defines or instantiates a component linking either built-in starts to pass and loses its line, and a directive that reaches the call fails with the unsupported error, so its line's reason changes to that failure. The files are `big-interleaving-test.wast`, `cancel-and-exclusive-lock.wast`, `cancel-delivery.wast`, `cancel-subtask.wast`, `cancel-host.wast`, `cancel-sibling-subtask.wast`, `cancel-starting-subtask-does-not-leak.wast`, `yield-when-cancelled.wast`, and the two cancel directives of the Component Model `reentrance.wast`. `cm/values/post-return.wast` was rejected for `task.cancel`; it is now rejected for `thread.index`, and its lines' reason changes to the thread built-ins. Refresh every changed line from a live run on both targets.

## Acceptance criteria
- [ ] A component that imports `task.cancel` and `subtask.cancel` instantiates, and a call to either fails with `Error::Unsupported` after the may-leave check, proved by a repository test.
- [ ] The `subtask.cancel` component of `task-builtins.wast` instantiates and its definition line leaves the list; the fifth component of `cancel-sync-and-waitable.wast` instantiates and its directive's reason becomes the unsupported failure.
- [ ] The lines of every cancellation file named above change as The Corpus section of the design states, and `cm/values/post-return.wast` carries the thread built-in reason.
- [ ] `lint` passes and `tests all` is green on both targets, any async directive that starts passing has its line removed from the expected-failure list, and every line whose reason this card changes is refreshed from a live run.
