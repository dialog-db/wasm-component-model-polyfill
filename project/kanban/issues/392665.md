## What to build
From the 2026-10-13 review of db2bc9. Nothing automated checks that `testWorkspace` unsets `WCMP_ZENA_REGENERATE`, `WCMP_ZENA_WEB_RUN` and `WCMP_ZENA_REPORT` (`flake.nix`, the `unset` line). Removing that line fails nothing in `tests all` or `lint`, and an inherited `WCMP_ZENA_REGENERATE` would again turn the Zena gate into a write. db2bc9 checked this by hand only.

Add a cheap check, for example a flake check or a shell test that runs the `tests zena` entry with the variable exported and a wrong stage in a copy of the record, and expects failure. Or have the Rust gate test refuse to write the record unless a variable that only `tests zena regenerate` sets is present.

## Acceptance criteria
- [ ] Removing the `unset` from `testWorkspace` (or its equivalent) fails `lint` or `tests all`.
- [ ] `lint` passes.
