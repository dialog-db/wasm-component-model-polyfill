## What to build

Step 1 of the migration (build beside). Create the crate `wcmp-wasm-core` in this workspace: the trait over Wasm Core that every backend implements, and the types the host sees. The polyfill does not change and does not depend on it yet.

- **Types.** `Engine`, `Store`, `Module`, `Instance`, `Func`, `Memory`, `Global`, `Table`, `Tag`, `Extern`, and `Val`, following Wasmtime's core API in name and ownership. Where the PDD leaves a choice open, Wasmtime's choice decides. No linker: an instantiation takes the imports as an ordered list of externs, as `wasmtime::Instance::new` does.
- **Dynamic dispatch.** The engine holds its backend behind dynamic dispatch. No public type carries a type parameter for the backend, so one binary can hold two backends at once.
- **Type model.** The full Wasm 3.0 boundary type model: `ValType`, `RefType { nullable, heap }`, and `HeapType` with every abstract heap type plus `Concrete(TypeHandle)`. A `TypeHandle` is opaque, printable, and comparable within one engine. The layer does no subtype checks.
- **Lexicon.** The capability names of the PDD's table, as a runtime value fixed for the life of an engine (not marker traits). Each Wasm feature name matches the name in `wasmparser`'s feature set. `fuel`, `epoch_interruption`, and `resource_limits` are reserved.
- **Trap kinds.** `TrapKind` with Wasmtime's names for the core traps, `OutOfFuel` and `Interrupt` reserved, `Host(error)`, `UncaughtException(exnref)`, and `Other(message)`. Each kind's message is Wasmtime's message.
- **Errors.** Structured errors, never a panic: `Unsupported` with a capability name, a compile error with the engine's message, a link error, a trap, and an out-of-bounds memory error.
- **Signatures without bodies.** Asynchronous `Module::compile` and `Instance::instantiate`, a synchronous compile, the untyped guest call (argument and result slices), host function registration (`Fn`, with a context that reaches the store), the memory methods with 64-bit offsets (`size`, `grow`, `read`, `write`, scalar loads and stores for u8/u16/u32/u64, closure-scoped `with_bytes`, and `Memory::copy`), and host suspension (`call_resumable` returning `Finished` or `Suspended(handle)`, `handle.resume`). The outcome type leaves room for a later `OutOfFuel` outcome. A method that needs a capability exists on every backend; a backend without the capability returns `Unsupported`.

The crate builds for native and `wasm32`, inherits its dependencies from `[workspace.dependencies]`, and follows the code conventions (one public type per module, no `pub(crate)`, re-exports from `lib.rs`).

## Acceptance criteria
- [ ] `wcmp-wasm-core` builds for native and `wasm32` with the workspace version, and `cargo package` succeeds for it.
- [ ] No public type of the crate has a type parameter for the backend. A test holds two different backend values (test doubles are fine) in one binary.
- [ ] The type model expresses every Wasm 3.0 value type, including `Concrete` heap types, and `TypeHandle` is opaque, printable, and comparable.
- [ ] A test checks that each lexicon name for a Wasm feature matches the `wasmparser` feature of the same name.
- [ ] `TrapKind` has every name in the PDD's list, with `OutOfFuel` and `Interrupt` reserved.
- [ ] The resumable-call outcome type is non-exhaustive, so a third outcome can be added later.
- [ ] Every fallible method returns a structured error. No `todo!()` or panic sits on a public path.
- [ ] `lint` passes.
