## What to build
Give the host two items to control the suspend provider, spelled in the style of the existing `EngineConfig` setters (`src/engine_config.rs`):

- A setting on `EngineConfig` that turns the provider off. The engine then uses nested turns whatever the probes find. A test lane uses it to measure the fallback on a target that has a provider. A host uses it to choose the synchronous order of nested turns, or to avoid a provider that fails on one engine version.
- A read-only query on `Engine` (`src/engine.rs`) that answers which provider it selected: the stack-switching provider, the JSPI provider, or none, as a public enum. A host uses it to explain a stack-switch failure to a person. The harness uses it to select the expected-failure lists.

The polyfill selects the provider once, when an `Engine` is constructed, and keeps the answer for the life of the engine. `Engine::new` stays synchronous. No probe exists yet, so the query answers none on both targets. The selection has the order PDD022 fixes (the switch probe, then JSPI, then none), with the opt-out ahead of all three. Wasmtime has no counterpart, because its fibers always exist, so the names are the polyfill's own. Follow the code conventions: one public type per module, re-exported from `lib.rs`.

## Acceptance criteria
- [ ] With the provider turned off through `EngineConfig`, the engine's query answers none, on both targets, proved by a repository test.
- [ ] The query answers none by default on both targets today, and the answer is fixed at `Engine::new`.
- [ ] The setting and the query are documented, and `public-api.txt` is updated.
- [ ] `lint` passes and `tests all` is green on both targets, any directive that starts passing has its line removed from the expected-failure list, and every line whose reason this card changes is refreshed from a live run.
