## What to build
The vendored browser backend builds the shim for a host function of more than eight parameters with `Function::new_with_args`, which is `new Function` (`rust/vendor/js_wasm_runtime_layer/src/func.rs`, `variadic_wrapper`; `PATCHES.md` entry 8). The prepare-call intrinsic takes eight fixed arguments plus the caller's flat arguments, so every call between components that passes an argument crosses the limit, and a page whose `script-src` lacks `'unsafe-eval'`, the common hardened setting, cannot instantiate any `wac` composition: the smoke test's composition step would fail on such a page. Ship the shim as a `wasm_bindgen(inline_js)` snippet instead, which is evaluated as page script and needs only `'wasm-unsafe-eval'` like the rest of the module, record the change under entry 8, and add the arity limit and the CSP consequence to the upstream filing the owner's card `4599cd` makes.

## Acceptance criteria
- [ ] The composition step of `smoke web` passes on a page whose policy is `script-src 'self' 'wasm-unsafe-eval'` without `'unsafe-eval'`, or a web test installs an equivalent policy and proves it.
- [ ] `PATCHES.md` entry 8 records the snippet and no longer names `new Function` as the mechanism.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
