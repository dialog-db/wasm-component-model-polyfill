## What to build
Make each component instance's handle table the `handles` table of the reference's `ComponentInstance`: every handle a guest holds is an index into it, whatever the kind. `HandleTables` in `src/resource/tables.rs` already keeps one table per instance shared by its resource types, so the work is the entry kinds. Extend `HandleKind` in `src/resource/handle_kind.rs` so an entry is one of: an owned resource (type identity, rep, and the count of borrows lent from it), a borrowed resource (type identity, rep, and the scope the borrow is owed to, as today), a subtask (the index of the subtask record in the store), a waitable set (the index of the set record in the store), or a reserved kind for a readable or writable stream end, a readable or writable future end, and an error context, which later features define. Restructure `HandleEntry` so the resource fields (`rep`, `type_id`, `guest_defined`) belong to the resource kinds only, and keep `lookup` and `remove_own` returning a `HandleLookupError` when a resource lookup finds an entry of another kind. Keep index zero unallocated, the free list, and deterministic reuse within one instance. Keep the transfer rule as `transfer_own` and `transfer_borrow` in `src/executor/intrinsics.rs` implement it (an owned transfer removes the entry from the source table and inserts it into the destination table, so the index changes; a borrow transfer inserts a borrow entry for the duration of the call) and fix that module's stale header comment, which still says one table per resource type and a transfer that keeps its index. Keep the store's host tables separate from the instance tables; their indices never reach a guest.

## Acceptance criteria
- [ ] Two handles of different resource types in one instance take consecutive indices from one allocator, proved by a test.
- [ ] An owned handle transferred between two composed instances leaves the source table and takes an index in the destination table, proved by a test.
- [ ] A subtask entry and a waitable set entry can be inserted, looked up by kind, and removed, and a resource lookup of such an entry fails with a `HandleLookupError`.
- [ ] The `linking` directory of the Component Model corpus, the composition tests of the Wasmtime corpus, and the fixtures pass unchanged on both targets.
