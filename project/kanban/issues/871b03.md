## What to build
Close the non-blocking gaps the independent review of card aea6dd found in the run-time link (landed as `83fa59cd1`).

- **Untested failure paths.** No test covers a cancelled link call, an exporter that traps, or a store dropped mid-call. The reviewer traced them: a trap ends the driver and fails the importer's call; a cancelled subtask drops the `call_concurrent` future and the exporter's task runs on unobserved. Add a test for each on both runners.
- **Stage attribution.** The polyfill types the forwarder with the exporter's `FunctionType`, so a type disagreement fails at `link`; Wasmtime's `func_new_concurrent` is dynamically typed, so the same disagreement fails at `call`. The polyfill can also report `instantiate` where Wasmtime reports `link` when an exporter fails to instantiate. Each subject keeps its own record line, so the gate still holds, but the fault is misattributed. Document the difference, or align the stages.
- **Wiring checks.** `Link::check` runs after every component parses, so on the polyfill (which stops at `parse` on Zena output today) only the Wasmtime subject catches a wiring typo. The polyfill runs `wiring.order` before compile and parse, Wasmtime after parse. Check wiring names against the scenario's WIT world before any stage, the same way on both runners.

## Acceptance criteria
- [ ] Cancelling a link call, a trapping exporter, and a dropped store each have a test on both runners.
- [ ] The stage a link type disagreement gets on each runner is documented or aligned.
- [ ] A wiring typo fails the same way on every subject, before any stage.
- [ ] `tests all` and `tests zena` pass.
- [ ] `lint` passes.
