## What to build

A design for keeping a crash of a host to the guest it served.

In the browser a panic of host code is an `unreachable`, which JavaScript sees
as a `RuntimeError`. It ends the WebAssembly instance it happened in, and that
instance holds the polyfill, the host, and the embedder's own code alike. In the
`wasi:webgpu` spike (`~/Git/github.com/cdata/wasi-webgpu-test`) a guest could
abort the host through the ported host's code (conversions that panic, an
`unwrap`, a short copy). In a worker, the page started a new worker, so only
that guest ended. On the main thread, the page itself had to reload.

The design should cover:
- **One host instance per guest, with the supervisor outside it.** How an
  embedder instantiates the polyfill, its host, and a guest in a WebAssembly
  instance of their own, made from one compiled module, and what it must do
  when that instance aborts: never call it again, let go of its suspended JSPI
  stacks and its JavaScript-side state, and make a fresh one.
- **What is safe after a `RuntimeError`**, and what the polyfill guarantees
  about state outside the dead instance.
- **A host panic as a trap of the guest.** Whether, with `panic=unwind` on
  WebAssembly (the exception-handling proposal), the polyfill can catch a panic
  around each host call and trap the calling guest, and what it must then treat
  as poisoned. Check the state of Rust's and wasm-bindgen's support first.

## Acceptance criteria
- [ ] A PDD covers the three, with its test cases.
- [ ] The PDD states what an embedder must do, and what the polyfill provides.
