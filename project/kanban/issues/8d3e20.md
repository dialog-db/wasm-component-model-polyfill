## What to build
`rust/wcmp/tests/corpus/README.md` is outside the `markdown` formatter and flake check: the include list in `flake.nix` (the `katsuobushi.lib.markdown` call) names only `CLAUDE.md`, `project/design/**/*.md`, and `project/kanban/README.md`, so `markdown format` never touches the corpus README and its table padding is hand-maintained. Worse, nothing checks the README's baseline table against the live conformance run: during the PDD019 thread three of eight cards were bounced by a reviewer for a stale table (`45740e`, `741912`, `553bb9`), the implementors had each run `tests all` green, and only a human diff caught it. Two changes. First, add the corpus README to the markdown include list so `markdown format` formats it and the `markdown` check gates it; run the formatter once and commit the result. Second, make the conformance harness compare the README's baseline table with the summary it computes: `it_reports_conformance_progress` already prints the table and writes it as JSON; parse the README's table rows (directives, passed, pass %, and the per-category counts) and fail with a message naming each differing cell when they disagree with the native run, so a stale baseline fails `tests native debug` the way a stale expectation line does. Decide whether the browser projection is checked the same way and say so in the README.
