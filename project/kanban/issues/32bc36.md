## What to build
Close the findings the review of card 05862b left open. Each is a gap between the landed poisoned-store behavior and its card.

1. **A link error on a core module's instantiation must not poison the store.** `Module::instantiate` poisons when a module that declares a `start` section fails to instantiate (`src/module.rs:120`). A wrong-kind or wrong-type import surfaces as the same substrate failure (`src/module.rs:75-77`), so a start-bearing module with a mistyped import poisons, and so does a data or element segment failure of such a module. Wasmtime type-checks imports first (`crates/wasmtime/src/runtime/instance.rs:122`, `:206` at `v49.0.0-rc.1`) and sets its trapped flag only inside `invoke_wasm_and_catch_traps` (`func.rs:1478`), that is, only when `start` actually ran. Poison only when the `start` function itself traps: check import types before instantiating, or learn from the substrate whether `start` ran.
2. **Cascade lines carry the cascade category.** `big-interleaving-test.wast` 1664 and 1675 (`tests/corpus/expected-failures.txt`) now fail as cannot-enter cascades of line 1651 but keep the `deferred-feature` category, against the rule at `tests/corpus/README.md:93-96`. Give them the cascade category, or state why not.
3. **Restore what the reworked tests stopped proving.** `provider_threads.rs:1914` dropped its fifth case while its comment (`:1920-1923`) still says one thread's host error does not leak into another's; restore the case in a store of its own or correct the comment. `tasks.rs:345` no longer shows the guest drop running the destructor.
4. **Missing tests.** A refused guest `Store::resource_drop` leaves the handle gone and a retry fails with the unknown-handle cause; a deadlock of the driver poisons; `Module::instantiate`'s import-count and wrong-store failures do not poison.
5. **Docs.** The `Func::call` doc (`src/instance/func.rs:181-194`) says nothing about a stale or invalid host handle poisoning the store, as any lowering failure does.
