## What to build

PDD026, "The Compiler Component: What It Is" and "Where It Runs". The host framework part that runs the compiler component in each context.

- The demo build ships the compiler component and the demo's source bundle: the toolchain bundle, plus the demo's WIT and authoring library files as they come to exist.
- At start, each context (the page and the service worker) fetches the compiler component and the source bundle, and instantiates the compiler on the polyfill with the browser backend. The page compiles on its main thread. The compiler is larger than 8 MB, so the backend's asynchronous compile path applies.
- The host framework answers `read-source` from the bundle and from the sources of the compile in progress. A compile can place extra files at paths beside its entry module, so that glue imports an author's source by a relative path.
- `stdout` and `stderr` go to the browser console. `wasi:clocks/monotonic-clock` uses `performance.now()`.
- One Rust call compiles a source against a WIT document and a world, and returns the bytes or the diagnostics. It also returns the compile time.
- Instantiating a returned component is a second call that returns the instantiate time. The drawer later shows both times.

No context caches compiled bytes.

## Acceptance criteria
- [ ] The compiler component compiles in the browser. A test on the page instantiates it on the polyfill and compiles a small program. The returned bytes instantiate on the polyfill, and a call to their export returns the expected value.
- [ ] The same compile succeeds in the service worker.
- [ ] A compile of a program with an error returns diagnostics that name the file and the line.
- [ ] A compile that imports a file placed beside the entry module succeeds.
- [ ] `tests all` and `lint` pass.
