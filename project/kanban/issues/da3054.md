## What to build
Write the PDD for a minimal WASI host: a companion to the polyfill that supplies the WASI interfaces real components import, on both targets, through the polyfill's `Linker`.

**Why.** PDD000 and PDD003 keep WASI worlds out of the polyfill, and that stays right for the core crate. But the use case in PDD000 ("plugins written in any language") depends on WASI. Most toolchains import WASI interfaces even for pure computation. Rust `wasm32-wasip2` with std imports `wasi:cli`, `wasi:io`, `wasi:clocks`, `wasi:random`, and `wasi:filesystem` preopens. Zena's component target imports p2 stdio (`wasi:cli/stdout`, `wasi:io/streams`, `wasi:io/error`) and p3 `wasi:clocks` with async timers. Today a host must write every one of these by hand. The conformance harness cannot run its own `wasi:http` fixture because nothing supplies `wasi:http/types` (README, Conformance).

**Reference.** Wasmtime's `wasmtime-wasi` crate is the shape to mirror, per PDD000's goal that the API feels like Wasmtime's: `WasiCtx`, `WasiCtxBuilder`, `WasiView` and `WasiCtxView` (`crates/wasi/src/ctx.rs`, `view.rs`), `p2::add_to_linker_sync` and `p2::add_to_linker_async` (`crates/wasi/src/p2/mod.rs`), and `p3::add_to_linker` plus one `add_to_linker` per interface (`crates/wasi/src/p3/`).

The PDD must settle these questions:

1. **Relationship to PDD000 and PDD003.** Keep their non-goal for the core crate and state that this is a separate companion. Decide whether that needs a revision of either document.
2. **What "minimal" covers.** Name the interfaces and versions in scope, both p2 (0.2.x, semver-compatible) and p3 (0.3.x), and derive the list from the concrete clients: Zena's component target, a Rust `wasm32-wasip2` std guest, and the wasi-http fixture's needs. State what is deferred. Candidates to defer are sockets, a real filesystem, and `wasi:http`, unless the PDD decides to include `wasi:http/types` for the fixture.
3. **Capabilities.** Nothing is ambient by default. The host grants each of these through the builder: args, environment, stdio sinks and sources, clocks, randomness, preopens.
4. **Browser mapping.** Say how each interface is backed in the browser and natively with one implementation where possible:
   - clocks: `performance.now` and `Date.now`
   - timers: `setTimeout`-backed host futures
   - randomness: `crypto.getRandomValues`
   - stdout and stderr: a host-supplied sink, the console by default
   - stdin: empty or host-supplied
   - filesystem: none, or an in-memory tree
   - `wasi:cli/exit`: a structured error the host can read
5. **p2 blocking calls.** `wasi:io/poll`, `blocking-write-and-flush`, and `subscribe-duration` block. Say how they run as synchronous lowers of async host functions under a suspend provider, and what the host sees without one (nested turns, then the stack-switch or deadlock cause).
6. **p3 streams and futures.** Say how p3 interfaces such as stdout's `write-via-stream` use `StreamProducer` and `StreamConsumer`, and how host timers become futures.
7. **API shape and dependencies.** Decide how far to mirror `wasmtime-wasi` names and signatures. The polyfill has no `ResourceTable` or `Resource<T>` and no `bindgen!` yet (3200e7). Decide whether to write the host by hand against `func_wrap` and `HostResource` now, or to wait for or shape the bindgen and derive design. State what changes when bindgen lands.
8. **Commands.** Decide whether to include a helper that calls `wasi:cli/run.run` and turns an exit code into a result, as Wasmtime's command support does.
9. **Testing.** Compare every in-scope interface against Wasmtime with `wasmtime-wasi` running the same guest natively. The guests are a Rust `wasm32-wasip2` std guest (args, env, clocks, random, stdio) and the Zena scenarios of 48c67c. Name the corpus fixtures that start to link once the host exists.

The PDD follows `project/design/README.md`: plain English, the six sections, Goals and Non-goals that express scope, and Test Cases that a later card can lift as acceptance criteria. Do not name later PDDs. Engineering planning decides crate names and layout.

## Acceptance criteria
- [ ] The PDD is formatted with `markdown format` and passes the `markdown` flake check.
- [ ] It states the relationship to the WASI non-goals of PDD000 and PDD003, and the corpus reads consistently afterwards.
- [ ] It lists the in-scope interfaces with versions, each traced to a client that imports it, and lists the deferred ones.
- [ ] It answers questions 3 to 8 above, each with its reason and, where it follows `wasmtime-wasi`, a citation.
- [ ] Its Test Cases cover:
  - a Rust `wasm32-wasip2` std guest printing, reading args and env, reading clocks, and drawing random bytes, on both targets, with output matching `wasmtime-wasi`
  - a Zena component's p2 stdio and p3 timer imports linked by the host
  - a p2 blocking call under a suspend provider and without one
  - a guest denied a capability the builder did not grant
  - `wasi:cli/exit` reaching the host as a structured result
- [ ] The owner accepts the PDD before any implementation card is filed.
