## What to build
The may-leave flag exists twice. `src/executor/instantiate.rs:227-233` mints one core global per component instance for the fused adapters, which read and toggle it themselves. The built-ins read `InstanceRecord::may_leave` (`src/concurrency/instance_record.rs:53`), which only `BoundaryCall` sets around a realloc and a post-return (`src/abi/boundary_call.rs:136-141, 201-202`). Nothing syncs the two, and nothing in `src/executor/trampoline.rs` or `src/executor/intrinsics.rs` reads either: the host-import trampoline, `resource.new`, and `resource.drop` check no flag at all. The reference traps in `canon_lower` (`definitions.py:2189`), `canon_resource_new` (`:2257`), and `canon_resource_drop` (`:2266`) when `may_leave` is false; Wasmtime's lowered-import trampoline traps `cannot leave component instance`. Today a `cabi_realloc` or a `post-return` that calls a host import runs it, and a guest-to-guest call from a post-return the polyfill ran passes the adapter's check because the adapter's global is still 1. The corpus directive that expects the trap, `cm/values/post-return.wast:202-220`, is listed as `cascade` behind that file's `task.cancel` rejection, so the gate cannot see the gap.

Then add the check to the host-import trampoline, `resource.new`, and `resource.drop`, with Wasmtime's wording. Wasmtime's compiler checks the calling instance's flag for every `resource.new` and `resource.drop` like any other built-in (`crates/cranelift/src/compiler/component.rs`, `check_may_leave`), and for the drop of a resource another component defines it checks the defining instance's flag as well before the destructor runs (around lines 1134-1140); both checks go in.

## Owner decisions (2026-09-21)
The adapters' core global is the flag. The fused adapters are generated code the polyfill cannot change, so the built-ins read the instance's flags global through the runtime layer, every `BoundaryCall` transition writes that global around a realloc and a post-return, and `InstanceRecord::may_leave` goes away. One flag, the one the generated code already uses.

## Acceptance criteria
- [ ] A host import called from `cabi_realloc` and one called from `post-return` each trap with `cannot leave component instance` on both targets, proved by tests.
- [ ] `resource.new` and `resource.drop` called from the same contexts trap the same way, and a guest-to-guest call from a post-return the polyfill ran traps too.
- [ ] `InstanceRecord::may_leave` is removed, and one test proves a `BoundaryCall` transition is visible to a built-in through the instance's flags global.
- [ ] `lint` passes and `tests all` is green on both targets; any `post-return.wast` line whose reason changes is regenerated.
