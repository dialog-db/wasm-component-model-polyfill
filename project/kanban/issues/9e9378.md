## What to build

PDD028, "Imports" for async functions. A WIT `async func` import becomes a `HostWithStore<T>` method registered through `func_wrap_concurrent` (Wasmtime `tests/expanded/smoke_concurrent.rs:181-209` at `v49.0.0-rc.1`).

- **Trait method.** Every async function gets the `async` and `store` flags. Its method takes `&Accessor<T, Self>` and returns `impl Future<Output = R>`, with `wcmp::Result<R>` under `trappable`.
- **`Send`.** Natively the future and the traits are `Send`. In the browser they are not required to be. Express the bound with one marker trait whose definition differs per target, as PDD018 does for host futures, so the macro emits the same tokens on both targets. A browser host awaits JavaScript promises and holds JavaScript objects.
- **Registration.** `func_wrap_concurrent`, using `with_getter` to hand the method an `&Accessor<T, D>` for the registration's projection. Resource methods and static functions declared `async func` follow the same rule.

## Acceptance criteria
- [ ] An async import awaits a host future that is pending once, and the guest receives the result, on both targets.
- [ ] In the browser, the future awaits a JavaScript promise and holds a value that is not `Send`, and the generated code compiles and runs.
- [ ] The projection reaches a view: a host crate implements the generated traits on a view type with two borrows of the host data and registers with its own `HasData` type. A call reaches both borrows. An async method of the same crate calls `with_getter` and reaches the view through the new accessor.
- [ ] A generated async method calls `TypedFunc::call_concurrent` and `close_with` with its `&Accessor<T, Self>`.
- [ ] An async import that a plain registration would satisfy is linked as concurrent, so the PDD020 link check passes for generated registrations.
- [ ] `lint` passes, and `tests all` is green on both targets with the conformance summary unchanged.
