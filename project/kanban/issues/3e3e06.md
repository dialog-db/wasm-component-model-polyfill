## What to build
Revise the fallback of the suspend seam (`SuspendSeam::run_nested_turns` and `nested_turn_loop` in `src/concurrency/suspend_seam.rs`, `StoreContext::nested_turn` and `run_turn` in `src/store/store_context.rs`, and `StoreData::suspend_cause` in `src/store/store_data.rs`) so that a task that is allowed to block waits for guest work through nested turns under four rules. First, a yielded item runs inside a nested turn once no other item is ready: the nested turn runs the resumption after a yield when nothing else is ready, rather than reporting `Outcome::Yield` and stopping, while the driver's turn keeps the yield rule of PDD018 and returns control to the host executor before a yielded item runs. Second, the causes: when the loop cannot progress and the condition is unmet, the cause is cannot-block when any instance in the store has a sync-typed call in progress (read the may-not-suspend flag of every instance record, not only the current task's), stack-switch-needed when a host task is pending (the blocked call's own future included), and deadlock when the store is idle. Third, a sync-typed task's block runs only items of its own instance and polls no host task, which `must_not_block_instance` already provides, and an async-typed task's block runs any ready item. Fourth, nested turns nest: an item a nested turn runs can block and open another nested turn on the real stack, so the one-level `in_nested_turn` refusal goes, and the guest's own call nesting bounds the depth. The revision applies to every blocking built-in of PDD019 and to `thread.yield`. A provider in the seam's slot still suspends the thread and ends the turn instead. Flip the seam's unit tests that assert the old rules (`it_never_resumes_a_yielded_item_inside_the_guest_call_that_blocked`, `it_refuses_a_suspension_reached_from_inside_a_nested_turn`) to assert the new ones, and keep every other test of the seam, the waitable built-ins, and the yield built-in green. The docs on the seam and on `nested_turn` state the four rules.

## Acceptance criteria
- [ ] A yielded item runs inside a nested turn after every other ready item, and a driver's turn still returns control to the executor before a yielded item runs, each proved by a test.
- [ ] A block whose store is idle fails with the deadlock cause; one with a host task pending fails with the stack-switch cause; one that cannot progress while a sync-typed call is in progress in any instance fails with the cannot-block cause, each proved by a test.
- [ ] A sync-typed task's block runs only items of its own instance and leaves other instances' items queued for the driver, and an async-typed task's block runs any ready item, proved by tests.
- [ ] An item a nested turn runs can block and open another nested turn, and both return when their conditions hold, proved by a test.
- [ ] `lint` passes and `tests all` is green on both targets, and any async directive that starts passing has its line removed from the expected-failure list.
