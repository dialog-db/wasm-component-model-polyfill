## What to build
Map `Trampoline::ThreadYield` in `src/executor/translate.rs` to a spec and build it: `thread.yield` gives way and returns zero. It traps with the cannot-leave cause when the instance's `may_leave` is clear. It asks `SuspendSeam::suspend` to suspend the thread with a condition that already holds; with no provider the nested turn runs the ready work once and the built-in returns, under the lazy rule of the seam: a task that must not block gives way only to ready work of its own instance, and with none the yield is a no-op, as Wasmtime runs it. The built-in never fails on its own, whatever the nested turn finds. The `cancellable` immediate has no effect, because no cancellation can be pending in this design. From inside a guest frame with no stack switch the polyfill cannot hand control to the host executor, so a callback task that wants the executor to run returns the yield status word instead; the doc says so.

## Acceptance criteria
- [ ] A `thread.yield` in a callback task's core function runs a queued item of another task before it returns, proved by a test on a component written by hand.
- [ ] A `thread.yield` in a synchronous export with no ready work of its own instance returns zero at once, and one with a queued item of another instance leaves that item unrun, each proved by a test.
- [ ] The built-in fails with the cannot-leave cause when a realloc calls it, proved by a test.
- [ ] The component of `task-builtins.wast` that defines only `thread.yield` instantiates and its line leaves the list.
- [ ] `tests all` passes on both targets, and any async directive that starts passing has its line removed from the expected-failure list.
