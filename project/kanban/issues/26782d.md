## What to build

Wasmtime 50 lets a host start a background task in a store with `spawn`. The
methods are `Store::spawn`, `StoreContextMut::spawn`, `Accessor::spawn`, and
`Access::spawn` (`crates/wasmtime/src/runtime/component/concurrent.rs` at
`v50.0.0`). The task is an `AccessorTask`, so it reaches the store through an
accessor. The store's event loop runs it, as it runs a host task, and `spawn`
returns a `JoinHandle` that the host can await or abort.

The polyfill has no `spawn`. `notes/bindgen.md` lists the missing
`Accessor::spawn` as a difference from Wasmtime. Add `spawn` to `Store`,
`StoreContext`, `Accessor`, and `Access`, with Wasmtime's names and its
`JoinHandle`.

## Acceptance criteria

- [ ] `Store`, `StoreContext`, `Accessor`, and `Access` have `spawn`, which
      runs the task in the store's event loop and returns a `JoinHandle`.
- [ ] A spawned task runs in a later turn of `run_concurrent` on both targets,
      and an aborted one does not run.
- [ ] `notes/bindgen.md` no longer lists the missing `spawn` as a difference.
