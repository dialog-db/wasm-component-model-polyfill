## What to build
The two review rounds of card `f3f685` accepted the `inline_js` shim and its browser test, and left one coverage gap and two wording overstatements. First, the asynchronous-lower prepare path (`PREPARE_ASYNC_*`) shares the variadic shim but has no test under a content-security policy; the landed test drives a synchronous lower of an asynchronous lift (`RESOLVES_AT_ONCE`). Add the asynchronous-lower case under the same policy. Second, `rust/vendor/js_wasm_runtime_layer/src/func.rs:225-228` says "every call an adapter prepares … then fails on a page that sets one", which overstates twice: a prepared call that passes no flat arguments has arity exactly eight and takes the `Closure::new` arm, needing no shim at all; and the failure lands at instantiation rather than at call time, because `build_prepare_call` runs eagerly for every `TrampolineSpec::PrepareCall` (`src/executor/instantiate.rs:231`, `:589`) — the text this round replaced had that timing right. Third, `PATCHES.md:134-135` drops the same qualifier: "could then run no composition that prepares a call, which is every composition with an asynchronous lower or lift" should keep "that passes an argument". Both are narrower than the error the first round fixed, and no control in the repo contradicts them, but the patch note exists to describe the patch exactly.
