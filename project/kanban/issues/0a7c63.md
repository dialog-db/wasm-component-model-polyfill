## What to build
The browser backend now refuses a re-entrant host call with a structured `ReentrantHostCall` error, and `backend::substrate_failure` maps it to `SchedulerCause::ReentrantHostCall` at the seven export and task call sites. Four other guest-call sites lose or hide it: the `resource.drop` trampoline in `src/executor/trampoline.rs` (around line 215) stringifies a destructor failure with `anyhow!("resource destructor failed: {{err}}")`, so a destructor that drops another handle of the same resource type in the same instance is refused correctly but the cause cannot be downcast; `abi/context.rs` (around line 335, post-return), `abi/strategy.rs` (around line 119, realloc) and `store/store_context.rs` (around line 233) keep the error under an `AbiCause` but never name the cause. Route all four through `substrate_failure` (or the equivalent for their error types) so the cause is preserved, and add a web test for the destructor shape. While in the vendored backend: state in `PATCHES.md` entry 10 that an engine-level throw (a stack overflow or out-of-memory) during an in-flight host call leaves the `RefCell` borrow out for the life of the store, where the old `FnMut` shim restored its pointer in a JS `finally` — unreachable from ordinary guest traps, but a robustness property the patch gave up. And tighten `src/concurrency/suspend_seam.rs` around lines 119-124: the pre-guard failure was a catchable exception, not a page crash, and an import from an outer nesting level still on the stack is refused too; fix `SchedulerCause`'s type doc, which still says nothing produces the cause.

Two neighbouring sites are other cards': the `thread.yield` arm at `src/executor/thread_yield.rs:163`, which swallows every scheduler cause including this one, is card `6c8808`'s, and the statement of how broad the browser's refusal is (any host function already on the stack, the blocking built-in's own trampoline included) is card `2b062e`'s. This card keeps the four sites and the docs named above.
