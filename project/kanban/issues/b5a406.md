## What to build

The polyfill sets the Wasm features of its translator from the capabilities of the backend. When a component needs a capability that the backend lacks, `Component::new` fails with `Unsupported` and the capability's name, before any core module compiles.

For example, without `exceptions` the translator does not enable exception handling, so the fused adapters emit no exception barrier (Wasmtime wraps the adapter body in a barrier only when the features include exception handling, `crates/environ/src/fact/trampoline.rs` at `v49.0.0-rc.1`). In a browser without `multi_memory`, a composition whose fused adapter reads two memories fails with `multi_memory`.

## Acceptance criteria
- [ ] The translator's features come from the backend's capabilities, not from a fixed set.
- [ ] With the browser's `multi_memory` probe forced off, a composition whose adapter needs two memories fails at `Component::new` with `Unsupported(multi_memory)`, and no core module compiles.
- [ ] With `exceptions` absent, a composition of two components translates without the exception barrier.
- [ ] No outcome in the conformance record or the Zena record moves from pass to fail.
- [ ] `tests all` passes.
