## What to build

PDD028, "The Macro" and the type part of "The Code for One Interface". The front-end of `wcmp::bindgen!`: the invocation, the WIT, and the Rust types, with no traits, registrations, or calls yet.

- **Crate.** A function-like proc macro in `wcmp-macros` (or a new proc-macro crate; engineering decides), re-exported at `wcmp::bindgen!`. It is the polyfill's own generator over `wit-parser`, not a fork of `wasmtime-internal-wit-bindgen`; use that crate as the reference for structure and names (`crates/wit-bindgen` at `v49.0.0-rc.1`). Add `wit-parser` to `[workspace.dependencies]`, at the version Wasmtime 49 uses if the graph allows. The runtime crate does not depend on `wit-parser`, and no browser binary contains it.
- **Invocation forms.** `bindgen!()`, `bindgen!("world")`, `bindgen!(in "path")`, `bindgen!("world" in "path")`, and `bindgen!({ … })`. With no path, read `wit/` beside the invoking crate's `Cargo.toml`. Options here: `world`, `path`, `inline`, `interfaces`, `stringify`, `debug`, `include_generated_code_from_file`, `additional_derives`, and `wcmp_crate`. `wasmtime_crate` is refused with a message that names `wcmp_crate`. Every other option of the ledger parses, so later cards only add behaviour.
- **Feature gates.** Read every WIT feature gate as `all_features = true` does. Generate every `@unstable` item as if every feature is on. No `LinkOptions`.
- **Modules.** One module per interface at Wasmtime's path (`example::app::log`), exported interfaces under `exports`, a versioned interface's module name carrying the version as Wasmtime spells it (`dep0_1_0`).
- **Types.** Records, variants, enums, flags, tuples, options, results, lists, and type aliases become Rust types with the PDD027 derives (`ComponentType`, `Lift`, `Lower`, `flags!`) and its layout assertions. An imported resource is the empty enum `pub enum Name {}`, and its handle type is `Resource<Name>`.

## Acceptance criteria
- [x] The invocation forms read WIT: a test invokes the macro in each of the five forms, and with `inline` and with `interfaces`, and each one generates the expected modules.
- [x] A generated record, variant, enum, and flags type have the same `SIZE32`, `ALIGN32`, and type check as the hand-derived equivalent, on both targets.
- [x] A versioned interface generates a module whose name carries the version.
- [x] `stringify` gives the generated code as a string, and `include_generated_code_from_file` builds from a written file.
- [x] `additional_derives` adds its derives to each generated type.
- [x] `wasmtime_crate` fails the compile with a message that names `wcmp_crate`, and `wcmp_crate` moves every emitted path.
- [x] A WIT package with an `@unstable` item generates that item.
- [x] The macro emits the same tokens for `wasm32-unknown-unknown` and the native target.
- [x] `lint` passes, and `tests all` is green on both targets with the conformance summary unchanged.


## Delivery notes

Delivered on the host with 5290bd in `feat(bindgen): Generate types and import bindings from WIT`: one generator change implements both cards.

- The macro is its own proc-macro crate, `rust/wcmp-bindgen`, re-exported as `wcmp::bindgen!`, so `wit-parser` stays out of `wcmp-macros`, which the browser backend builds. It is published before `wcmp` (`publishedCrates`). Its tests live in an unpublished crate, `rust/wcmp-bindgen-tests`, because `bindgen!()` with no path reads `wit/` beside the invoking crate's manifest. Refusals are unit tests inside the macro crate, which call the expansion and read its error.
- `flags!` takes an optional outer `#[component(wcmp_crate = path)]` (and doc comments) before the type's name, which Wasmtime's does not. Without it, a generated flags type would name `::wcmp` under `wcmp_crate`.
- Each generated type has Wasmtime's layout assertion (`SIZE32`/`ALIGN32` against `wit-parser`'s `SizeAlign`) and derives `Debug`, where Wasmtime writes a manual `Debug`.
- A package or namespace named as a Rust keyword is escaped (`async` becomes `async_`); Wasmtime's macro writes an invalid module there.
- Same tokens on both targets: `tests/front_end.rs` compares the `stringify` output with a committed snapshot, on both lanes.
- `lint` and every `tests all` lane green (zena run in the main repo).

## Review notes
