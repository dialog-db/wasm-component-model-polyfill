## What to build
Without a suspend provider, a stackful caller that yields while a worker thread it started keeps yielding fails after exactly 65 worker yields, whatever the caller's own yield count (confirmed by the fed20f reviewer with a probe: with a provider it works for 3 to 200 caller yields; without one it fails for every count, including 3, always after 65 worker tallies). The error is the misleading substrate message ("instantiation error: the runtime substrate failed to instantiate the component") plus a wasm backtrace, not the stack-switch cause. It looks like nested yields on the real stack exhausting a fixed budget or the native stack. The smoke card fed20f's thread story uses a callback export as the caller to avoid it.

Find the cause. Either make the shape run without a provider, or make it fail at once with the structured stack-switch cause the polyfill uses for other shapes that need a stack switch. PDD023's no-provider paragraph covers cancellable blocks but not cancellable yields, where `subtask.cancel` cannot run the yield first from a frame above it; state that case too (a design note for the owner).

## Acceptance criteria
- [x] A repository test with the provider off runs a stackful caller that yields while its worker yields more than 65 times, and either it completes or it fails with the structured stack-switch cause on its first impossible switch.
- [x] The same test passes with a provider on both targets.
- [ ] `lint` passes and `tests all` is green on both targets.

## Review notes
- 2026-10-05 (host session, backlog-burndown-001-q2) Cause: the seam's `SPIN_BUDGET` (64). With no provider the caller's first yield runs the worker's start in a nested turn (a served turn), and each later worker yield runs a nested turn that finds only the caller, a frame below that no turn can reach, so the count passes 64 on the 65th worker yield whatever the caller's own count. The stack depth stays constant; it is no stack exhaustion. The misleading substrate message was already gone at the tip: since `cb097e157` the failure reaches the host as `Error::Scheduler(StackSwitchNeeded)`. Chosen fix: keep the budget (failing at the first yield would contradict `it_returns_zero_from_a_yield_inside_a_nested_turn` and the reference, where a yield may return to the same thread) and pin the shape: `it_runs_a_worker_that_yields_within_the_budget_under_a_stackful_caller_without_a_provider` (8 rounds return), `it_fails_a_stackful_callers_worker_that_yields_past_the_budget_with_the_stack_switch_cause_without_a_provider` (1000 rounds, 3 and 200 caller yields: `StackSwitchNeeded`, exactly `1 + SPIN_BUDGET` notes), and `it_runs_a_stackful_callers_yielding_worker_to_its_end_under_a_provider` (stack-switching and Wasmi/JSPI host-suspension, 1000 rounds). The budget docs name the third shape. **Owner reading needed:** criterion 1 says "fails ... on its first impossible switch"; the seam can only call the switch impossible when the budget runs out. Also found: the nextest default filter dropped every test whose name ends in `without_a_provider`, not only the corpus twins, so `it_fails_a_host_async_lower_of_a_synchronous_export_with_the_stack_switch_cause_without_a_provider` had never run in any lane; the filter now scopes that exclusion to the conformance binary.
- 2026-10-05 Design note for the owner, for the no-provider paragraph of PDD023 (not edited here): "Without a provider, a cancellable yield gives way in a nested turn, so its frame lies below the work that turn runs. A `subtask.cancel` made inside that turn cannot run the yield first: an asynchronous cancel returns `BLOCKED`, the yield takes the request when its turn ends and returns 1, and the caller then gets the subtask event. A request from a frame below the yield cannot be made until the yield returns." The code already behaves so (`executor/cancel.rs`, `tests/baseline_cancellable.rs` `it_answers_one_from_a_cancellable_yield_on_the_real_stack_when_the_provider_is_off`).
