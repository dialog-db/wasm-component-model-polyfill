## What to build
Three sites lose a failure. First, a host `async` function that fails after its first poll: the lowering item at `src/concurrency/host_task.rs:166-170` matches `Err(_) => Ok(())`, marks the subtask cancelled, and records the subtask event, so the guest sees `CANCELLED_BEFORE_RETURNED` and neither the host nor any driver sees the error value, while the same error on the first poll fails the guest's call outright (`src/store/store_context.rs:446-449`). Wasmtime propagates a failed host future out of the event loop as the call's error. Second, `thread.yield` at `src/executor/thread_yield.rs:163` matches `Err(Error::Scheduler(_)) => {}`; the arm is meant for the seam's own three causes, which a yield never asked the turn to avoid, but it also drops `ReentrantHostCall` (the browser's refusal, mapped at `src/backend.rs:58-66`), `RecursiveDriver`, and `StoreNotInPoll` raised by an item the nested turn ran, whose task was already abandoned (`src/executor/callback_task.rs:213-216`); the yield returns 0 and no driver reports the loss. Third, a lowering that fails ends the turn (`host_task.rs:200` through `run_turn`, `store_context.rs:649`) and surfaces as the `Err` of whichever driver happens to be polling, which can be an unrelated `Func::call`; Wasmtime poisons the store instead, and only the internal doc says what the polyfill does.

Settle one rule for where a failure that belongs to no driver surfaces (the driver that is polling, as today, or a store-level poison, which the error-context and trap-rules design will need in any case), state it in the public docs of `Func::call` and `Store::run_concurrent`, and make the three sites follow it: the lowering item ends the turn with the body's error the way a failed crossing already does; `thread.yield` matches the seam's three causes explicitly and hands every other error on. The cause-preservation sites of the re-entrant refusal are card `0a7c63`'s and stay out of this one.

## Owner decisions (2026-09-21)
A host task's failure is the trap of the guest task that made the call: that task ends with the error, its driver reports it, and the subtask does not resolve. This is the outcome Wasmtime gives the common one-driver case. `thread.yield` matches the seam's three causes explicitly and hands every other error on, which under this rule reaches the task the nested turn was running. A lowering that fails follows the same rule, so an unrelated `Func::call` no longer fails for another task's host function. The store-level poison Wasmtime applies stays with the error-context and trap-rules design (55c5ef), which cites this rule as its starting point.

## Acceptance criteria
- [ ] A host `async` function that fails after a pending poll fails the guest task that called it with that error, reported by that task's driver, and the subtask does not resolve, proved by a test on both targets; a second driver of the same store is unaffected.
- [ ] `thread.yield` hands on a non-seam scheduler error raised by an item its nested turn ran: a web test with `ReentrantHostCall`, a native test with `StoreNotInPoll`.
- [ ] The public docs of `Func::call` and `Store::run_concurrent` state where a failure that belongs to no call surfaces.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
