## What to build
Map `Trampoline::AsyncStartCall` in `src/executor/translate.rs` to a spec and build the trampoline on the prepare-and-start machinery: it places the `TaskStart` item in the switch slot, enters the implicit thread through the gate, runs the slot when the gate let the item pass, and returns the status word of PDD018. The word is `RETURNED` (2) with no index when the subtask resolved before the lower returns; otherwise the subtask enters the caller's handle table and the word is the state in the low four bits with the index in the high bits: `STARTED` (1) when the callee has read its parameters and parked or is still running, `STARTING` (0) while the gate holds it. The subtask event of the callee's start and resolution goes to the caller's waitable sets as the subtask record states, so a callback export that reads `STARTED`, joins the subtask to its set, and returns the wait word receives the event when the sibling calls `task.return`, with the result already crossed into the caller's memory. An asynchronous lower of a sync export whose task the gate holds returns `STARTING`; when the gate opens, the driver runs the start item, the results cross, and the event carries `RETURNED`. A callee whose core function blocks inside a built-in and can be released only by its caller fails with the stack-switch cause. A trap in the callee unwinds to the trampoline as it does for the synchronous start. The four combinations of lower and lift then cross correctly, and the table in the design says what the caller sees in each.
