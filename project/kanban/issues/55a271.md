## What to build
Remove the `cfg_attr(target_arch = "wasm32", ignore)` gates from the composition tests and the conformance harness. Where the browser target genuinely differs (substrate limits such as tags or GC references), record the difference in a per-target delta file (`expected-failures.web.txt`) the harness applies on top of the shared list, so the parity rule holds without hiding real gaps.

## Acceptance criteria
- [ ] No test under `tests/` carries a target gate.
- [ ] `tests web debug` runs the composition tests and the corpus and passes.
- [ ] The web delta file lists only substrate-specific differences, each with a category.
- [ ] `tests conformance` reports both targets.
