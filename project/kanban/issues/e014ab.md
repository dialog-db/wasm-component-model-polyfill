## What to build
The owner asked for a smoother start. The page shows a spinner in a fixed-height
space until the list draws. `<todo-app>`'s Zena source then reveals the list: it
measures the list out of sight, and at once animates the frame's height to it,
fades the spinner out as it rises 10 px, and fades the list in as it rises
10 px into place. The shelf slides up from below the page. The hint
"Double-click a todo to edit it." appears only with the list.

The host framework gains two generic primitives: a shadow root starts with a
slot, so an element shows its children until it first renders, and a view's
`resize` event reports a node's height through a ResizeObserver. The page
defines `<todo-app>` last, after the service worker controls it, so the element
upgrades in place around the spinner. The spinner turns by Web Animations, so
moving it into a slot does not restart it.

## Acceptance criteria
- [x] Spinner in a fixed-height space before the list; no skeleton.
- [x] Height, spinner, and list animate together (sampled frame by frame).
- [x] The spinner keeps one animation through the reveal; no jump.
- [x] The shelf slides in from below.
- [x] The double-click hint is absent until the list shows.
- [x] Reduced motion shortens each transition to a moment.
- [x] Demo lane 66/66; lint green; PDD026 updated.

## Review notes
The shelf arrives about 0.6 s before the list reveal: the page adds it when
`<todo-app>` is defined, not when the list draws.

Owner feedback 2026-10-03, addressed: the colophon showed under the spinner and
jumped as the frame resized, and the hint read as detached. The whole colophon,
hint first, is now one paragraph in `<todo-app>`'s list, so nothing shows below
the spinner. The spinner stalled while the page compiled, then jumped: it drew
its arc on the main thread. It is now a ring that only turns, which the
compositor runs.
