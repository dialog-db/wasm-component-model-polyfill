## What to build
Give each component instance a thread table and build the three thread built-ins that need no stack switch. Accept them on every target behind the existing gate `wasm_component_model_threading`, which stays off by default. With the gate off they fail with `Error::Unsupported`, as now. Each first traps with the cannot-leave cause when the may-leave flag of the instance is clear, as the reference states.

- `thread.index` returns the current thread's index in the instance's thread table.
- `thread.new-indirect` creates a suspended thread whose start function comes from a table, and returns its index. It reads the table that the translator's table initializer already extracts; the translator refuses that extraction today (`src/executor/translate.rs:631`). The start function takes one `i32`, or one `i64` in a 64-bit memory, and returns nothing. The reference admits both. Wasmtime 49 admits only the `i32` form. The polyfill admits both, because it runs 64-bit memories and the reference states the rule. A table entry that is empty fails with Wasmtime's message for an uninitialized start function. A start function of another type fails with Wasmtime's type message, "start function does not match expected type (currently only `(i32) -> ()` is supported)".
- `thread.resume-later` marks a suspended thread ready. It runs in a later turn, which starts it from the scheduler. A resume that names a thread which is not suspended fails with Wasmtime's message "cannot resume thread which is not suspended".

Each message is a structured cause of `wcmp::Error`, so the corpora match it by substring. `src/concurrency/thread.rs` and `thread_id.rs` hold today's thread record.

## Acceptance criteria
- [ ] A repository test proves the `i32` start function of `thread.new-indirect`, and a second proves the `i64` start function in a 64-bit memory.
- [ ] An empty table entry and a start function of another type each fail with Wasmtime's message, proved by a test.
- [ ] A thread that `thread.new-indirect` creates and `thread.resume-later` marks ready runs in a later turn and reads its own index through `thread.index`, proved by a test.
- [ ] `thread.resume-later` on a thread that is not suspended fails with "cannot resume thread which is not suspended", and each built-in fails with the cannot-leave cause when the may-leave flag is clear, each proved by a test.
- [ ] With the gate off, a component that uses a thread built-in fails with `Error::Unsupported`.
- [ ] The two directives of `task-return-traps.wast` that extract a table (21, 58) pass, or carry their true cause from a live run.
- [ ] `lint` passes and `tests all` is green on both targets, any directive that starts passing has its line removed from the expected-failure list, and every line whose reason this card changes is refreshed from a live run.
