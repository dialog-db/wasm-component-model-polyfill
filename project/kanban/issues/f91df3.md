## What to build

Robustness items the review of the scheduler named, none reachable by a guest today. In `src/concurrency/driver.rs` (around line 116) the `Waiting` arm returns pending without re-checking the driver's condition, so a turn that both resolves the task and leaves a host task pending parks `Func::call` until that host task wakes it; against a never-returning host task the call never returns, which contradicts PDD018 §The Scheduler and Its Drivers ("the future does not wait for it"). Re-check the condition before parking. In `src/store.rs` (around lines 250 and 273) `enter_turn` and `leave_turn` are not paired by a guard, so a panic inside an item leaves the in-turn flag set and every later driver fails with the recursive-driver cause; make the pair a guard that clears on unwind. In `src/concurrency/scheduler.rs` (around line 256) `claim_exclusive` has no release; add the release the reference performs when the task's implicit thread ends. In `Cargo.toml` `wasm-bindgen` is both a wasm32 dependency and a wasm32 dev-dependency; drop the redundant one. Add a test per behavioural item that fails against the current code.

Also, from the re-review of the reconciled tip: `store.rs` (around lines 386-387) swallows both `Result`s when the completed host task's item runs, so a subtask record that vanished between the poll and the item loses its event silently; surface that as a structured error or an internal error rather than `let _ =`.

From the review of 3727fa: `run_concurrent`'s `Idle` branch (`store.rs` around lines 342-350) polls the closure once more and returns pending without re-checking whether that poll left ready work or a host task in the store; guard the park with `has_ready_item() || host_task_count() > 0`. And `Accessor::with` runs embedder closures between `enter_turn` and `leave_turn`, so the guard this card adds must cover a panic in user code, not only in the polyfill's own items.

From the review of d552c8: the swallowed `Result`s moved to `src/concurrency/host_task.rs` (around lines 131 and 139-140) and a third was added at line 128, where a later-turn body failure is dropped whole — the subtask stays `started` with no event and the guest deadlocks, while the same failure on the first poll fails the guest's call. Make a later-turn failure resolve the subtask the way a first-poll failure does. The `Waiting` item above is now reachable: `run_turn` runs items then polls host tasks, so a turn that resolves the driver's task and leaves a host task pending returns `Waiting`.

## Acceptance criteria

- [ ] A driver whose task resolves in the same turn that leaves a host task pending returns at once, proved by a test with a never-returning host task.
- [ ] A panic inside an item, or inside an accessor closure, does not leave the store refusing every later driver, proved by tests.
- [ ] `run_concurrent` does not park while the store holds a ready item or a pending host task, proved by a test.
- [ ] The exclusive thread is released when its task's implicit thread ends, proved by a test.
- [ ] A host task whose body fails in a later turn resolves its subtask and delivers an event, proved by a test.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
