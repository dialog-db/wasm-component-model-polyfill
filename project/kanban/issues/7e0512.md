## What to build
With the fused adapter compiler of Wasmtime 49, an adapter between two components whose lower or lift is asynchronous calls `PrepareCall` and then `SyncStartCall` or `AsyncStartCall`; when both are synchronous it calls only the enter and exit intrinsics of PDD018. Map `Trampoline::PrepareCall` and `Trampoline::SyncStartCall` in `src/executor/translate.rs` to specs, and accept a `funcref` parameter in an intrinsic's core signature (`core_signature` and `CoreSignature` in `src/executor/ir.rs`), since prepare carries the two generated functions as funcrefs: the start function takes the caller's flat arguments, lifts them in the caller, and lowers them into the callee, and the return function takes the arguments of the callee's `task.return`, or a sync export's flat results, and lowers them into the caller; the adapter itself handles realloc, the may-leave flag, and fresh context slots around each realloc, and the polyfill only calls the two functions at the right moments. Build the prepare trampoline: it creates the callee's task with `create_export_task` for the callee function, lift options, and instance, records the caller's thread, creates the subtask in the caller's scope in `STARTING`, and stores the start function with the caller's flat arguments, the return function, and the caller kind (sync, or async with or without a result) on the subtask. Build the synchronous start trampoline: it queues a `TaskStart` item that calls the start function, marks the subtask started, calls the callee's core function, and on a synchronous lift calls the return function with the flat results, resolves the subtask, runs post-return, and ends the task, or on a callback lift hands the status word to `CallbackTask::handle_status_word` (`src/executor/callback_task.rs`); it places the item in the scheduler's switch slot (`Scheduler::switch_to`), enters the implicit thread through the entry gate (`enter_implicit_thread`, where a held task clears the slot and stays queued in arrival order), runs the slot, then blocks through `SuspendSeam::suspend` on the subtask's resolution, delivers the resolution, and returns the flat results. A synchronous export of a sync-typed function ignores the gate. When the callee's `task.return` runs (`src/executor/task_return.rs`), the return function runs at that moment through the caller's boundary context, before the callee's callback continues, which is the reference's `on_resolve`; for a sync export the results cross when the core function returns and post-return runs afterwards. A callback export that returns the yield or wait word parks and leaves its caller free; a callee that blocks inside a built-in keeps its frame below the trampoline and the nested turn serves it with work that is ready or becomes ready without the caller, and when only the caller can release it the call fails with the stack-switch cause. A sync-typed caller that has to wait fails with the cannot-block cause, and only after the callee did not resolve at once, which is the lazy rule of the reference and of Wasmtime 49. A trap in the callee unwinds through the start item to the trampoline and fails the caller's call with the message the synchronous baseline gives it. The adapters of Wasmtime 49 import no may-block global: the may-not-suspend flag of the instance record carries that state, set by the enter intrinsic for a synchronous call between components and by a host call into a sync-typed export for the length of the call, and cleared on exit.

## Acceptance criteria
- [ ] The translator accepts the `component-prepare-call` and `component-sync-start-call` trampolines and a `funcref` intrinsic parameter, and still refuses `subtask.cancel`, `task.cancel`, the stackful lift, the stream, future, and error-context built-ins, and the thread built-ins other than `thread.yield`.
- [ ] `callback-yield-then-exit.wast` passes: a synchronous lower returns at the callee's `task.return`, and the callee's late exit runs in the next driver's turn.
- [ ] `many-params-with-retptr.wast` passes: a synchronous lower of a callback export with the maximum flat parameters and a return pointer.
- [ ] The second directive of `dont-block-start.wast` passes with the cannot-block message, and `wait-forever.wast` passes with the deadlock message.
- [ ] The synchronous-lower directives of `fused.wast` pass, and a repository test proves that a sync-typed caller's wait fails with the cannot-block cause only after the callee did not resolve at once.
- [ ] A trap in the callee of a synchronous lower fails the caller's call with the baseline's message and releases the callee's exclusive thread, proved by a test.
- [ ] `lint` passes and `tests all` is green on both targets, and any async directive that starts passing has its line removed from the expected-failure list.
