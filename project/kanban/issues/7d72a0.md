## What to build
The host-import trampoline calls a concurrent registration's closure synchronously to obtain its future (`src/executor/trampoline.rs:604-606`). No `PollScope` is entered until the store polls that future, so an `accessor.with(..)` written before the `async move` block, the natural way to read host data into the future, fails with `SchedulerCause::StoreNotInPoll`. Wasmtime runs the closure inside the future it returns, under its thread-local set, so the same host code works there; the doc at `src/linker/linker_instance.rs:284-292` tells the host to move the token into the block instead, which a port from Wasmtime will not have done, and the smoke-test card for a host task inside a synchronous call will meet the same wall. Enter a `PollScope` around the closure call with the active turn's waker, or the noop waker outside a turn as `start_host_task` already does, or defer the closure call into the first poll of the host task; then drop the workaround from the doc.

## Acceptance criteria
- [ ] A `func_wrap_concurrent` and a `func_new_concurrent` closure that each call `accessor.with` before their `async move` block read the host data on both targets, proved by tests.
- [ ] The registration docs no longer tell the host to clone the token into the block, and a reach from inside the closure that nests another reach still fails with the recursive-driver cause.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
