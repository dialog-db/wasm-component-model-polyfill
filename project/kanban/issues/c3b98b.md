## Review notes

Implementor (2026-09-14): four of five criteria hold. `nix flake check` is
green, `flake.lock` pins `v0.5.1` with no crane/nix-filter/rust-overlay
inputs, `nix/rust.nix` is gone, and `test:native:debug` (175 passed) and
`test:web:debug` (70 passed) ran from `nix develop`.

`katsuobushi-check-artifact-alignment --profile dev` on the new
`workspace-deps-dev` package reports NOT aligned, on one field only:
`vendored src` (the shell's cargo resolves from the registry, the bundle was
built against crane's vendor directory). Every other field matches. Making it
report aligned needs a source-replacement `.cargo` config pointed at the
bundle's vendor directory, the way arcanabasis' `warm-cargo` script does. That
is a feature of its own and is not in this card's body; the checker is on the
shell PATH so the verdict is one command away.

Environment note: nixpkgs' `fetchCrate` downloads through the crates.io API,
which answers 403 to Nix's fetcher on this host. The workspace-deps checker
crate's source was realized once from `static.crates.io` under the same hash
(a fixed-output derivation, so the store path is identical). Other hosts do
not need this step.

Owner (2026-09-14): the alignment criterion is dropped. Menu commands are the
build and test path and they are derivations; a dev-shell `cargo` pays one
closure compile per profile into the out-of-tree target directory and is
incremental after that. Making the checker report aligned needs a warm-cargo
mechanism (unpack the bundle, point cargo at its vendor directory), which
belongs in katsuobushi's `lib.rust` next to the checker rather than in this
project. Tracked on the katsuobushi board. Revisit if a dev-shell closure
compile ever becomes a problem here.
