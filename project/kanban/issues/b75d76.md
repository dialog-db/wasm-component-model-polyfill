## What to build

PDD027, "Derived Types". The derive macros `ComponentType`, `Lift`, and `Lower`, with Wasmtime's attributes and shape rules (`crates/component-macro/src/component.rs:41-345` at `v49.0.0-rc.1`), re-exported flat at `wcmp::` beside the traits of the same names.

- **Attributes.** `#[component(record)]`, `#[component(variant)]`, `#[component(enum)]` on the type, and `#[component(name = "…")]` on a field or a case. Without `name`, the WIT name is the Rust name as written.
- **Shape rules.** A record is a struct with named fields. A variant is an enum with at least one case, each with no payload or one unnamed payload. An enum has no payloads and no explicit discriminants, and carries `#[repr(u8|u16|u32)]` matching its count of cases. No style attribute, or two, is refused. `#[component(flags)]` is refused with a message that names `flags!`. Each refusal is a compile error with the meaning of Wasmtime's.
- **Crate path.** `#[component(wcmp_crate = path)]`. `#[component(wasmtime_crate = …)]` is refused with a message that names `wcmp_crate`.
- **Output.** Layout constants computed from the fields at compile time. Direct lift and lower field by field through the hidden context, with no `Val`. The type check walks fields and cases in Wasmtime's order.
- **Migration.** Move the hand-written trait impls (the demo's `http_types`, the Zena test host, the wasi-http handler test, the error-context baseline) to the derive.

The macros can live in `wcmp-macros` or a new proc-macro crate. Engineering decides. The crate inherits its dependencies from `[workspace.dependencies]`. Compile-fail checks can be rustdoc `compile_fail` blocks, as the crate's own seam docs use.

## Acceptance criteria
- [ ] A record and a variant cross in both directions as Rust types on both targets. A typed export takes a derived record and returns a derived variant. A typed host function takes a derived variant and returns a derived record. The test states each expected Rust value, and each value that crosses equals it.
- [ ] The typed path builds no `Val` for derived types: a test counts allocations around a typed call with a list of derived records, on both targets. The count is the same for 16 and 4,096 records, apart from the result list.
- [ ] A type mismatch is refused when the host acquires a typed export. A record with a different field name, a different field type, or an extra field fails with `Error::TypeMismatch`, the path names the first wrong field, and no call reaches the guest.
- [ ] A type mismatch is refused when the linker links a typed host function over a derived record. The position names the interface, the item, and the wrong field.
- [ ] The `name` attribute renames a field and a case. A derived record and variant with renamed parts cross both ways, and the type check uses the WIT names.
- [ ] A compile-fail check covers each refusal: a record on a tuple struct, a variant with no cases, a variant with a case of two payloads, an enum without `#[repr]`, an enum whose `#[repr]` width does not match its count, an enum with an explicit discriminant, no style attribute, two style attributes, `#[component(flags)]`, and `wasmtime_crate`. Each error names the rule.
- [ ] `<T as ComponentType>::SIZE32` and `ALIGN32` of a derived record equal the Canonical ABI size and alignment, checked against the same record's layout in the `Val` path.
- [ ] No hand-written impl of the three traits remains outside the polyfill crate.
- [ ] `lint` passes, and `tests all` is green on both targets with the conformance summary unchanged.
