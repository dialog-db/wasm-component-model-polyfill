## What to build
The menu commands for the Zena tests, and a Zena lane in `tests all`.

- `tests zena` runs the three subjects and prints the compatibility table: one row per scenario, the columns `Browser`, `Native`, and `Wasmtime` in that order, the stage in each cell, a footer that counts the passes in each column, and a header line that names the pin.
- `tests zena regenerate` runs all three subjects, the browser included, and writes the record again: the header from the flake lock's revision, and every line with its stage and error text. `--dry-run` prints the difference and writes nothing. Follow the shape of the existing `tests regenerate` in `flake.nix`.
- `tests all` runs the Zena scenarios as one more timed lane.
- Update the menu descriptions.

Notes from the review of d9ec04 (landed as `8466db57d`):
- Each lane gates the `wasmtime` line and its own polyfill line only (`tests/zena.rs:199`). A browser-only run ignores an edited `native` line and the other way round; only a run of both lanes checks every line. Keep that in mind for the Zena lane in `tests all` and for what `tests zena` runs.
- A failing gate lists each difference, then this run's stages in record-line form, ready to paste. The pin difference names both revisions but does not point at a regenerate command; `tests zena regenerate` is the natural place to name.
