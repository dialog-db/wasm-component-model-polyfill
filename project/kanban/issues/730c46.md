## What to build
Prove, and fix where a proof fails, that a provider serves every block that only a frame below the blocked thread can release. Under a provider the callee runs on a stack of its own, so the frame below gets control back and releases the block.

The frame-below directives:
- Component Model corpus: `async-calls-sync.wast:250` and `:251`, `cancel-and-exclusive-lock.wast:196`, `sync-streams.wast:208`.
- Wasmtime corpus: `reenter-during-yield.wast:81`, `stream-zero-ops.wast:201`, `streams-massive-send.wast:238` and `:240`, `sync-streams.wast:186`, `task-builtins.wast:723`, and `trap-if-done.wast` 594, 596, 612, 614, 623, 625, 627.

Without a provider every one of them fails with the stack-switch cause, so each is in the no-provider overlay.

## Acceptance criteria
- [ ] With a provider, every frame-below directive above passes on both targets, and its cascade lines go with it.
- [ ] With the provider turned off, every frame-below directive fails with the stack-switch message and none with the deadlock message, and each sits in `expected-failures.no-provider.txt`.
- [ ] `deadlock.wast`, `wait-forever.wast`, and `wait-forever2.wast` still fail with the deadlock message on both targets, with and without a provider.
- [ ] The repository tests still prove all four rules of the failed-block cause.
- [ ] `lint` passes and `tests all` is green in all four states. A directive that starts passing under a provider leaves the shared list. A line that still fails without a provider sits in `expected-failures.no-provider.txt` with the stack-switch reason. Every line whose reason this card changes is refreshed from a live run.
