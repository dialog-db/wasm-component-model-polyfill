## What to build
A component may export a core module for the host to instantiate itself. The translator rejects `ModuleStatic` and `ModuleImport` exports at `src/executor/translate.rs` ("module-typed exports"). Wasmtime exposes them through `Instance::get_module`, returning a core `Module` the host instantiates with the core API. The polyfill's public API has no core module type, and its rule is that no runtime-layer type appears in a public signature. Design a polyfill-owned handle for an exported core module, decide what the host can do with it (at minimum: obtain its import and export types, and instantiate it against a store with host-supplied imports), and thread the export through `Instance::exports()`. Mirror Wasmtime's names where a name exists.

Parity: the handle wraps the runtime layer's `Module` on both targets; the browser build compiles it through the same asynchronous path `Component::new` uses, so the handle's constructor from bytes, if offered, is awaited.

Corpus: 12 `deferred-feature` lines in `wasmtime/modules.wast`, `wasmtime/nested.wast`, `wasmtime/aliasing.wast`, and `cm/binary/binary.wast`.

## Acceptance criteria
- [ ] A component exporting a core module yields a handle the host can inspect and instantiate on both targets.
- [ ] No runtime-layer type appears in the new public signatures.
- [ ] Every `module-typed exports` line is removed from `expected-failures.txt`, and the corpus is regenerated.
- [ ] `tests all` passes on both targets.
