## What to build
The browser's engine caches a precompiled core module by its bytes (`rust/vendor/js_wasm_runtime_layer/src/lib.rs` `Engine::precompile`, an `insert` into a crate-private map), and `Module::new` takes the entry with `remove` (`module.rs:43`). Card `3839ef` made one `Component::new` compile each distinct byte string once and discard its unbuilt entries on failure, but two batches on one engine that compile the same bytes at the same time — two `Component::new`, or a `Module::new` beside a component — still share one key. The first `Module::new` takes the only entry and the second falls back to a synchronous `new WebAssembly.Module`, which Chrome refuses on the main thread above 8 MB; and if one batch fails, its drop guard discards the entry the other batch still needs. The comment at `executor/compile_module.rs:88-90` ("no other batch's entry for the same bytes can be in the map") holds only on the success path.

Hand each caller its own compiled `WebAssembly.Module` instead of a shared byte-keyed map: have `precompile` return the module to the caller (or reference-count the entries), and correct the comment.

## Acceptance criteria
- [ ] Two concurrent `Component::new` on one engine over components that share a core module larger than 8 MB both succeed in the browser, and a failure in one does not break the other, proved by web tests.
- [ ] The vendor change is recorded in `PATCHES.md`.
