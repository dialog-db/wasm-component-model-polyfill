## What to build
A non-instance import under an interface name (`(import "pkg:ns/iface@0.1.0" (func ...))`) now resolves through the root namespace by exact name (`resolve_root` in `src/linker/resolve.rs`). Wasmtime's root `NameMap::get` (`crates/environ/src/component/names.rs` around lines 180 and 293) falls back through an alternate lookup key for any name carrying `@`, so a root registration under `pkg:ns/iface@0.1.0` satisfies an import of `pkg:ns/iface@0.1.3` there and fails with `UnresolvedImport` here, while the polyfill's own interface registry already implements Wasmtime's semver ranges for instance imports. The root namespace applies the same range rule to a versioned name, as Wasmtime does (owner decision, 2026-09-21); implement that, and make the `resolve.rs` module doc and the `Linker` type-level doc (`src/linker/linker.rs` around lines 30-41, which still say the root holds plain-named imports) state the rule. No design document covers interface-named non-instance imports; say so in the report so the owner can add it.

The interface registry's own range rule departs from Wasmtime in three ways as well (`src/linker/resolve.rs:700-754`). `prefer` takes the strictly greater version, so with `a:b/c@0.2.0` and `a:b/c@0.2.7` both registered an import of `@0.2.0` resolves to `0.2.7`, where Wasmtime's `NameMap::get` returns the exact definition first (`crates/environ/src/component/names.rs` around lines 180-201). `versions_compatible` ignores prerelease tags, so `@0.2.0-rc.1` satisfies `@0.2.0`, where `alternate_lookup_key` treats a prerelease as compatible with nothing (around lines 293-320). Two `0.0.x` versions compare compatible because their minors are both zero, where Wasmtime says nothing is compatible with a `0.0.x`. The module doc's claim of "the WIT specification's reading of semver" cites nothing; the specification fixes only the name grammar and the rule is the host's, so the tie-break is Wasmtime. Settle the root and the interface rule together and cite `names.rs` from the module doc.
