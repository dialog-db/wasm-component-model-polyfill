## What to build
A non-instance import under an interface name (`(import "pkg:ns/iface@0.1.0" (func ...))`) now resolves through the root namespace by exact name (`resolve_root` in `src/linker/resolve.rs`). Wasmtime's root `NameMap::get` (`crates/environ/src/component/names.rs` around lines 180 and 293) falls back through an alternate lookup key for any name carrying `@`, so a root registration under `pkg:ns/iface@0.1.0` satisfies an import of `pkg:ns/iface@0.1.3` there and fails with `UnresolvedImport` here, while the polyfill's own interface registry already implements Wasmtime's semver ranges for instance imports. Decide with the owner whether the root namespace applies the same range rule to a versioned name (Wasmtime's behaviour) or keeps exact matching, implement that, and make the `resolve.rs` module doc and the `Linker` type-level doc (`src/linker/linker.rs` around lines 30-41, which still say the root holds plain-named imports) state the rule. No design document covers interface-named non-instance imports; say so in the report so the owner can add it.

## Acceptance criteria
- [ ] A root registration under `pkg:ns/iface@0.1.0` satisfies, or is documented not to satisfy, a function import of `pkg:ns/iface@0.1.3`, proved by a test either way.
- [ ] The `Linker` type-level doc and the `resolve.rs` module doc state the root's matching rule truthfully.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
