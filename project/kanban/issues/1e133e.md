## What to build
Build the JSPI form of the switch module, and the probe that selects the JSPI provider in the browser.

**The probe.** The JSPI provider is selected when `WebAssembly.Suspending` and `WebAssembly.promising` exist as functions. The probe runs in the browser only, after the switch probe, and stays synchronous.

**The JSPI form.** A thread starts through `WebAssembly.promising` over its entry wrapper. The `suspend` of a shim is a call to an import made with `WebAssembly.Suspending`. The JavaScript function behind that import returns a promise the scheduler holds, and to resume the thread the scheduler resolves the promise with the built-in's result. A promising call returns a promise and never the entry's results, so the WebAssembly entry wrapper is how the scheduler learns at once that an entry finished. The wrapper must be WebAssembly: a JavaScript wrapper puts a frame that is not WebAssembly between the start of the stack and the suspension, and that suspension traps.

The shim calls the suspending import only when the built-in is not ready. Chromium 147 measured that a `WebAssembly.Suspending` import always suspends, even when its function returns a plain value or a resolved promise. The proposal's overview states the opposite, so the design assumes the measured behavior.

The vendored `js_wasm_runtime_layer` needs a way to wrap an import with `WebAssembly.Suspending` and an export with `WebAssembly.promising`. Record the change in its `PATCHES.md`.

This card does not yet run guest threads through the provider.

## Acceptance criteria
- [ ] In the flake's Chromium the engine's query answers the JSPI provider, and with the provider turned off it answers none, each proved by a repository test in the web lane.
- [ ] A repository test proves that a shim whose built-in is ready returns without a suspension.
- [ ] A repository test in the web lane runs the JSPI form of the switch module with two core instances: a thread suspends with a frame of the other instance between, a plain import running inside that thread starts a second promising stack that suspends, and both resume later in either order and finish.
- [ ] `lint` passes and `tests all` is green on both targets, any directive that starts passing has its line removed from the expected-failure list, and every line whose reason this card changes is refreshed from a live run.
