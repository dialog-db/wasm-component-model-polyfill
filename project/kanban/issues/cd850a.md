## What to build
The end-to-end smoke test (`rust/wcmp-smoke`, run by `tests smoke native` and `tests smoke check`) has no story about stack switching. Its "Asynchronous hosts" chapter and "Streams and futures" chapter use only the callback form, and nothing shows a guest thread that suspends. Add stories, in a new chapter (for example "Suspending guests"), that show what the PDD022 work enables. Write each one the way the existing stories are written: a `Story` with a chapter, a title, and a goal that a reader understands without the design, and a step that returns what it proved.

Cover at least these shapes:
- **A synchronous export waits for an `async` host function.** The guest lowers a host `async` function synchronously, and the host's future awaits a timer the store knows nothing about, like `RUN_CONCURRENT` does. The guest's thread suspends, the driver returns pending, and the export returns the host's result when the timer fires. This is the PDD's network-fetch user story.
- **A stackful export blocks and resumes.** A stackful export (`canon lift async` with no `callback`) waits in `waitable-set.wait` on work that another component or the host completes later, then delivers its result through `task.return`.
- **Guest threads.** A guest starts threads with `thread.new-indirect` and parks them with `thread.suspend`. Another thread wakes each one with `thread.resume-later` or a switch, and the story checks the order in which they ran. The PDD's user story is a C component that uses pthreads.
- **Which provider you got.** The "Introspection and configuration" chapter reports the engine's provider query (stack-switching natively on x86_64 Linux, JSPI in the browser). A "Known limits" story turns the provider off through `EngineConfig` and shows that the first shape fails with the stack-switch cause instead of a wrong answer or a hang.

Build the fixtures from real toolchains where the toolchain supports the shape, as the "Real toolchains, real types" chapter does. Use the menu's `fixtures` command, and put the sources under `rust/wasm-component-model-polyfill/tests/corpus/fixtures/`. wit-bindgen's core ABI marks the stackful export as not supported, and the flake supplies no C toolchain today. So a shape that no toolchain in the flake can build may be written by hand in WAT inside the smoke crate, as `MODULE_CONSUMER` and `MEMORY64_COMPOSITION` are. Name each such shape in the report and say why. If a fixture needs a C toolchain added to the flake, report its cost instead of adding it.

Every story must pass natively on the x86_64 Linux host and in the flake's Chromium. A browser without JSPI, such as WebKit before Safari 27 (see bug 629412), falls back to nested turns. There, a story that needs a suspension must state the documented outcome in its goal, not fail silently.
