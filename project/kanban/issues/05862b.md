## What to build
Give the store one poisoned flag, as Wasmtime keeps one trapped flag per store (`crates/wasmtime/src/runtime/component/store.rs:285-298` at `v49.0.0-rc.1`). Set it on each of these failures:

- A failure of guest core code, including a failure of a host function that guest code called under a synchronous lower.
- A failure of a built-in, a lift, a lower, or a fused adapter while a guest call runs.
- A failure of a core `start` function or an initializer during instantiation.
- A failure of a resource destructor.
- A host `Val` of the wrong type that `Func::call` finds while it lowers the arguments. Wasmtime poisons here because its lowering runs after the entry check; the polyfill matches it.

These failures do not poison, because the polyfill raises each one before any guest state changes: an arity mismatch of `Func::call`, the recursive-driver cause, the store-not-in-poll cause, the wrong-store cause, and a link error.

Add the cannot-enter cause next to `TaskCause::CannotLeave` (`src/error.rs:996`), with Wasmtime's message "cannot enter component instance", and map it to Wasmtime's `Trap::CannotEnterComponent` where the error module maps the other traps. A poisoned store fails these entries with it:

- `Func::call` and `TypedFunc::call`.
- `Func::call_concurrent` and `TypedFunc::call_concurrent`.
- Every instantiation into the store, through `Linker::instantiate` or a core module's instantiation. This is a stated departure from Wasmtime, which lets instantiation run: it runs guest `start` functions, and the reference permits no guest code after a trap.
- `Store::resource_drop` of a resource that a guest defines.

These still work, because no guest code runs: `Store::resource_drop` of a host-defined resource, `Store::run_concurrent` whose closure does only host work (an entry into a guest from inside the closure fails with the cannot-enter cause), reads and writes of the store's host data, and dropping the store. No public method answers whether a store is poisoned; Wasmtime keeps its flag internal. The scheduler's note that nothing raises `CannotEnterComponent` (`src/concurrency/scheduler.rs:801`) changes with this card.

Out of scope, each on its own card of this design: the failure of a host `async` future as a trigger, the discard of queued work at the moment of poison, and the rule for which driver reports a trap.

## Acceptance criteria
- [ ] `cm/async/builtin-trap-poisons-instance.wast` lines 10 and 39 pass on both targets with the cannot-enter message.
- [ ] A repository test proves each trigger on both targets: a guest trap, a built-in trap, a failed host function under a synchronous lower, a mistyped host `Val`, a trap in a core `start` function, and a trap in a destructor. After each one, `Func::call` fails with "cannot enter component instance".
- [ ] A repository test proves that an arity mismatch, a recursive driver, and a link error leave the store usable.
- [ ] A repository test poisons a store and then makes each entry on both targets. `Func::call`, `TypedFunc::call`, `call_concurrent`, `Linker::instantiate`, a core module's instantiation, and `Store::resource_drop` of a guest-defined resource each fail with the cannot-enter message. `Store::resource_drop` of a host-defined resource succeeds. A `run_concurrent` whose closure does only host work returns the closure's value.
- [ ] `lint` passes and `tests all` is green on both targets, any directive that starts passing has its line removed from the expected-failure list, and every line whose reason this card changes is refreshed from a live run.
