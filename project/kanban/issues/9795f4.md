## What to build
The review of card `6c8808` accepted the rule that a host task's failure is the trap of the guest task that called it, and left three findings that need one card. First, a failure can still vanish: `FailureChannel` is a `WakeSlot` (`src/concurrency/failure_channel.rs`), and a fill after the reader has completed is dropped with no observer. A callback export that does `task.return` in turn N and then waits on the host subtask has its `ResultChannel` taken at the end of turn N, so `Func::call` or `call_concurrent` has already answered; when the body fails in turn N+1, `fail_export_task` (`src/store/store_context.rs`) takes the channel arm, ends the task, drops its queued callback, and fills a channel nobody reads. The guest task disappears and the error is lost, where the old code delivered `CANCELLED_BEFORE_RETURNED`. The doc at `failure_channel.rs:19-22` holds only for the same-item case. Second, the rule reaches only tasks with a failure channel: `attach_failure_channel` is called from `start_concurrent` (`src/instance/func.rs:398`) and `call_async` (`:504`); a synchronous `Func::call` task, a guest-to-guest callee the prepare intrinsic created, and an adapter-pushed task have no channel, so `store_context.rs:969` returns `Err` and the error still ends the turn and lands on whichever driver polls — a guest-to-guest callee that starts an async host call and waits is an ordinary shape. Decide what a resolved-then-failed task and a channel-less task do (the design's rule is that the failure belongs to the task that made the call) and make every arm honour it. Third, the on-stack arm (`store_context.rs:963-966`) tests whether the failing task is anywhere on the scope stack and then ends the innermost nested turn; with the stack `[Task(A), Task(C)]` where A's lowering item runs inside C's nested turn, A's error traps C and A never learns. Make the arm surface at the failing task's frame or state the narrower rule in the doc. Add the tests the review found missing: the resolved-then-failed ordering across turns; a failing host call made by a task with no channel; a host-body failure while the caller sits on the scope stack; and a borrow the guest lent to the failed call released on the integration path. Consider folding `discard_subtask` (`src/concurrency/host_task.rs:205`) into `executor::release_subtask` (`src/executor/start_call.rs:459`), which it duplicates.

## Acceptance criteria
- [ ] A host body that fails after the calling task resolved surfaces its error to a driver or to the guest as the design states; a test on both targets pins which, and no failure is dropped.
- [ ] A host call made by a task with no failure channel (synchronous export, guest-to-guest callee) traps that task, not the polling driver, proved by a test.
- [ ] The on-stack arm traps the failing task's own frame, or its doc states the innermost-turn rule and a test pins it.
- [ ] The four missing tests exist, and the ones that pin a behaviour fail on the code before their change.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
