## What to build
`map<K, V>` is a value type of the current Component Model release and the outlook lists it as "Implement", with Wasmtime supporting it. The polyfill rejects it at the type projection ("`map<K, V>` values"). Add the type to `ValueType`, a `Val` shape for it, lift and lower per the canonical ABI's layout rules, structural equality and mismatch reporting in the type system, and a `ComponentValue` conversion for a Rust map type so `TypedFunc` and `func_wrap` accept it. Mirror Wasmtime's `Val` naming.

Parity: the ABI is shared code; test in both lanes with a map crossing in both directions.

Corpus: `wasmtime/map-types.wast` declares the type only and passes today; no vendored directive moves a value. Add a fixture built with `wasm-tools` from WIT so the harness covers values.

## Acceptance criteria
- [ ] A `map<string, u32>` round-trips through an export and an import on both targets, typed and untyped.
- [ ] A fixture under `tests/corpus/fixtures/` exercises the type and passes in both lanes.
- [ ] `tests all` passes on both targets.
