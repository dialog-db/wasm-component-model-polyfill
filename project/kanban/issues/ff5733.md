## What to build
Twelve corpus lines fail because the runtime layer has no exception tag type and no GC reference types: `cm/linking/tags.wast` (4), `wasmtime/tags.wast` (1), `wasmtime/exceptions.wast` (1), and six `wasmtime/alias-region-*.wast` and `wasmtime/modules.wast` lines that use `(ref i31)` or concrete function references. Wasmtime supports both. Both browsers and Wasmtime implement the underlying core features (the outlook lists exception handling and GC as shipped everywhere), so parity is possible once `wasm_runtime_layer` carries them: a `Tag` extern kind, and reference-typed values beyond `funcref` and `externref`. Propose the extension upstream (with the backend issues in 4599cd), carry it in the vendored browser backend and a patched native backend meanwhile if the owner agrees, and lift the polyfill's parser patch that turns tag imports into errors.

Parity: the extension lands in the runtime layer's shared trait; both backends implement it; the corpus lines flip in both lanes.

Blocked in practice on the upstream conversation; file the proposal first and keep this card until the runtime layer exposes the kinds.
