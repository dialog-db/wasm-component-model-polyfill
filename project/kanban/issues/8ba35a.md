## What to build
A Rust partner component that links with Zena at run time, in both directions.

- A scenario can hold a partner's Rust source and its locked cargo manifest. The partner uses `wit-bindgen` against the same WIT world as the Zena side, as the Rust fixtures of the conformance suite do (`tests/corpus/fixtures/build.sh`).
- The build compiles the partner at test time with this workspace's Rust toolchain and the locked manifest. Nothing is committed. The partner's build does not depend on the `zena` input, so a move of the pin changes only the Zena side.
- Scenario 10: Zena imports from Rust at run time. Scenario 11: Rust imports from Zena at run time. Each passes a string across the link.
- Regenerate and commit the record lines.

Notes from the review of aea6dd (landed as `83fa59cd1`):
- A run-time link forwards only async-typed functions in both runtimes: Wasmtime 49 panics on a nested `run_concurrent` (`check_recursive_run`) and refuses `func_new_concurrent` for a sync-typed import; the polyfill has the same registration rule and no public path for a sync host function to call a guest. Give the partner contract async functions (scenario 8 uses `greet: async func(name: string) -> string`), and say so in the report.
- The link machinery lives in `wcmp-scenario` (`Wiring`, `Link`, `Linking`, `Link::check`), `tests/zena/runner.rs` and `wcmp-wasmtime/src/wasmtime_run.rs`; a scenario declares its links in `wiring.txt`. Typed and untyped calls both work across a link.
- Real Zena components still stop at `parse` on web and native, so the polyfill side of a Zena-to-Rust link is only reachable through stand-ins until that changes.
