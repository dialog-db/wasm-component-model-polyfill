## What to build
Close the gaps the independent review of card 2103de found in the Zena composition step (landed as `278b47272`). None blocked the card.

- **The import named in the wiring is ignored (medium).** `tests/zena/compose.sh` reads only the importer and exporter columns of a `composition` link, and `wac plug` fills every import whose name matches. The reviewer changed scenario 9's wiring to `composition importer wcmp:bogus/nothing exporter` and it composed with status 0. So a mistyped or stale wiring composes silently, and it can plug more imports than the one named. After a plug, check that the named import is gone from the composition, or fail the build when the named interface is not among the importer's imports.
- **Reasons name only the importer.** The composition takes the importer's name, so a refusal inside the exporter half reads `component importer`: `rust-imports-zena-composition`'s web and native lines blame the Rust importer for a Zena exporter's refusal. `Verdict::not_composed` names only the importer, and the exporter's compile log is deleted. Name the composition after both halves, or name the exporter in the reason.
- **Untested branches.** An exporter plugged into two importers and an importer that did not compile have no build-check case (`compose.sh:77`, `:90`).
- **Tidy-up.** `uncomposed()` and the compose fields are duplicated between `tests/zena/bundle.rs` and `wcmp-wasmtime`; `compose_status: Option<i32>` plus a separate `compose_log` would read better as one `Option<(i32, String)>`.

## Acceptance criteria
- [ ] A composition link whose named import the importer does not have fails the build with a layout message, and a build-check case covers it.
- [ ] A refusal in the exporter half of a composition names the exporter in its reason.
- [ ] The two untested branches have build-check cases.
- [ ] `tests zena`, `tests native debug`, `tests web debug` and `lint` pass.
