## What to build
Remove the one difference between the targets that PDD020 records for a re-entrant host call: a native engine enters a host function that is already on the stack, and the browser backend refuses the second call.

The refusal comes from a guard in the vendored `js_wasm_runtime_layer` (`rust/vendor/js_wasm_runtime_layer/src/func.rs`, `ReentrantHostCall`). The backend wraps each host function's body in a shared JavaScript closure and in a guard that detects a second entry. The patch that introduced the guard states that the shared closure is entered at any depth, and the function the runtime layer hands the backend is `Fn`, so the body needs no exclusive access. Drop the guard and call the body directly. Make sure the arguments and results of one call never share a buffer with a second call of the same function; the module docs of `src/backend.rs` say they do today. Record the change in the backend's `PATCHES.md`.

Then remove `SchedulerCause::ReentrantHostCall` and the backend's refusal type, the downcast in `substrate_failure` (`src/backend.rs`), and the refusal's documentation (`src/backend.rs` module docs, `src/concurrency/suspend_seam.rs`, `src/error.rs`). This breaks the public API, which the project accepts before its first major release. Tests that expect the refusal (`tests/baseline_reentrant_drop.rs`, `tests/baseline_reentrant_wait.rs`, `src/baseline/call_concurrent.rs`, `src/abi/context.rs`) now expect the call to succeed in the web lane, as it does natively.

Card e82a3b asks for browser tests of every refusal site; this card removes the refusal it would test.

## Acceptance criteria
- [ ] A repository test calls the same host import from inside that import's own call, in the web lane, and the call succeeds.
- [ ] A repository test drops a second handle of a resource type from inside that type's destructor in the browser, and the drop succeeds.
- [ ] The re-entrant host-call cause and the backend's refusal type no longer exist in the public API, and `public-api.txt` is updated.
- [ ] No line of `expected-failures.web.txt` carries the re-entrant host-call reason. A line that still fails in the browser carries its true cause from a live run.
- [ ] `lint` passes and `tests all` is green on both targets, any directive that starts passing has its line removed from the expected-failure list, and every line whose reason this card changes is refreshed from a live run.
