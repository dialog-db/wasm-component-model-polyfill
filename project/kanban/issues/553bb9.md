## What to build
Run every destructor `resource.drop` runs as a task with one thread, as the reference lifts the destructor as a synchronous function of one `u32` parameter and lowers a call to it: in `build_resource_drop_trampoline` (`src/executor/trampoline.rs`) for a guest drop, and in the host release path of `Store::resource_drop` for a host release, the host closure of an imported resource and the local core function alike. Push a task with a fresh thread as the current scope before the destructor runs and pop it after, whether the destructor returned or failed, sharing the mechanism the realloc task uses. The thread starts with zero context slots and its slots end with it, so a destructor sees zeros and what it sets does not reach the thread that dropped the handle; a destructor that drops another resource nests a second task the same way. Register in `link_spectest` (`tests/conformance.rs`) a `wasmtime` instance whose `gc` function does nothing, as Wasmtime's wast runner registers it, because one directive of `context-in-resource-drop.wast` imports it. Every directive of that file passes after this card: alone, nested, across a composition, and after a host call.

## Acceptance criteria
- [ ] `context-in-resource-drop.wast` passes whole with the `wasmtime` `gc` host item registered, and its lines leave the list.
- [ ] A destructor sees zero context slots, a slot it sets does not reach the dropper, and a nested destructor gets its own slots, proved by a test for a guest drop and for a host release.
- [ ] The destructor's task is the current scope while it runs and is gone after, including when the destructor fails, proved through the store's records.
- [ ] `tests all` passes on both targets, and any async directive that starts passing has its line removed from the expected-failure list.
