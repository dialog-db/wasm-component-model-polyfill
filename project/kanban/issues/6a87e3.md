## What to build
Three tests in `src/error.rs` pin the trap wording of the polyfill's causes to `wasmtime_environ::Trap`: `it_pins_the_scheduler_causes_to_the_traps_wasmtime_environ_renders`, `it_pins_the_waitable_causes_to_the_traps_wasmtime_environ_renders`, and `it_pins_the_task_causes_to_the_traps_wasmtime_environ_renders`. Each asserts `trap.to_string().ends_with(cause_message)`. Two reviews (cards `d4f541` and `e4cb68`) noted the same two gaps and did not block on them. First, `ends_with` passes when a literal is truncated to a proper suffix of the trap text (for example `leave component instance`), while the conformance harness matches the corpus directive's text by `contains`, so such a truncation would break directives that the pin does not catch. Replace the suffix check in all three tests with an equality against `format!("wasm trap: {cause}")` (`Trap`'s `Display` is `wasm trap: {desc}`), or an equality on the trap text after its fixed prefix, so a literal must equal the trap's description exactly. Second, nothing keeps a pin list in step with its enum: a Wasmtime-backed cause added without a pin, or a pin deleted, is silent. Give each test a way to prove its list is complete, for example by matching over every variant of the cause enum with an explicit list of the causes that have no Wasmtime trap (`SetHasWaitables`, `ReturnFromSynchronousTask`, and whichever others the docs name as the polyfill's own), so a new variant fails to compile until it is placed on one side or the other. Change no message and no variant; this card only strengthens the tests.

## Acceptance criteria
- [ ] Each of the three pin tests fails when a pinned literal is shortened to a proper suffix of the trap text, proved by trying it once and reverting.
- [ ] Each of the three pin tests fails to compile, or fails, when a variant of its cause enum is neither pinned nor listed as the polyfill's own.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
