## What to build

PDD026, "Elements: Events" and the ordering rule in "Lifecycle".

- **Handlers.** A view names its events as DOM event name to handler name. The diff adds and removes listeners. When an event fires, the host framework calls `handle-event` with the id, the handler name, and an `event` record (`kind`, `value`, `checked`, `key`), then renders again.
- **Emit.** The authoring library's `emit` calls the host's `emit`. The host framework dispatches a `CustomEvent` on the element's host node that bubbles and crosses shadow boundaries. A parent's listener receives the `detail` in `value`.
- **Order.** The calls for one element run one at a time, in order: a call waits until the call before it on the same element completes. Calls for different elements of one tag can run at the same time and interleave where the Zena code awaits.

## Acceptance criteria
- [ ] An element handles events. A test clicks a node whose view names a `click` handler. `handle-event` receives the handler name, and the element renders again.
- [ ] A child event reaches its parent. A test makes a child element call `emit`. The parent's handler receives the event, with the detail in `value`.
- [ ] The calls of one element run in order. A test fires two events on one element in one task. The second `handle-event` starts after the first completes.
- [ ] Two elements of one tag can be in `handle-event` at the same time when the first awaits.
- [ ] `tests all` and `lint` pass.
