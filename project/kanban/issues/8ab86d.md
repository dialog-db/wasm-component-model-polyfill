## What to build

Hardening items from the review of the waitable records, none reachable by a guest today. In `src/concurrency/task_tables.rs`: `join_waitable_set` (around lines 387-395) removes the waitable from its previous set before it validates the target set, so a failed lookup leaves the waitable naming a set that no longer lists it; validate first. `begin_wait` (around lines 424-431) raises `num_waiting` before it validates the thread, so the error arm leaves the count raised and `drop_waitable_set` then traps forever; validate first. `take_pending_event` (around line 506) is public and empties the slot without delivering a subtask resolution, while only `HandleTables::take_event` pairs the two; make the paired operation the only public one. In `src/resource/tables.rs`, `discard_scope` (around line 298) and `exit_subtask` (around line 118) remove a subtask record without leaving its waitable set, and `RecordTable` reuses freed indices, so a later record could inherit a stale set membership; route those removals through the same path `drop_waitable` uses. Add a test per item that fails against the current ordering.

## Acceptance criteria

- [ ] A failed `join_waitable_set` and a failed `begin_wait` leave the records unchanged, proved by tests.
- [ ] No public operation empties a subtask's event slot without delivering its resolution.
- [ ] Removing a subtask through any path leaves no set membership behind, proved by a test that reuses the freed index.
- [ ] `lint` passes and `tests all` is green on both targets.
