## What to build

wasmparser 0.259 turned on `CM_IMPLEMENTS` and `CM_MAP` in
`WasmFeatures::default()`. `EngineConfig::default` builds on that default
(`engine_config.rs:49`), so `implements` is now on by default. The doc comment
at `:70` and Wasmtime 50 say it is off. Wasmtime 50 builds its defaults from an
explicit base (`config.rs:2568-2650`).

wasmparser 0.261 also adds the `CM_ACCESSORS` gate. Wasmtime 50 has
`wasm_component_model_accessors` and `wasm_component_model_canonical_names`,
off by default (`config.rs:1428`, `:1438`). The conformance harness turns both
on for the spec tests, as Wasmtime's harness does.

This card lands in the same series as 2397ff. The workspace does not build or pass on Wasmtime 50 without it.

## Acceptance criteria

- [ ] `EngineConfig::default` builds from an explicit feature base, and
      `implements` is off.
- [ ] `EngineConfig` has the accessor and canonical-name settings, off by
      default.
- [ ] The harness maps both for `cm/`, and `baseline_component_binary.rs`
      passes on both targets.
