## What to build
Build the host's reading side. `StreamConsumer<T>` and `FutureConsumer<T>` are polled inside a turn with the store context, a `Source<'_, Item>`, and a `finish` flag, under the same `Send` rule as the producers. `Source` is the polyfill's view over `Vec<T>` of a write the host serves: `remaining` is the count the writer offers and `read` moves up to a count the consumer names into a `Vec<T>`. A consumer that can take items takes them and returns `Completed` or `Dropped`; it can take items and still return pending, which delays the writer's completion until a later poll returns ready, the backpressure of the Wasmtime contract; a `FutureConsumer` returns `Poll<Result<()>>`. `finish` is true when the guest cancelled the write, and the consumer answers as the producer contract states. `StreamReader<T>::pipe` and `FutureReader<T>::pipe` set the consumer as the reading side of a readable end the host holds and give the end up; the end then runs as a host task and a guest's writes reach the consumer inside turns. Lifting a readable end out of a guest into the host produces the typed reader through `ComponentValue`: a stream in a result the host reads through a typed call, or in a parameter of a typed host function, arrives as `StreamReader<T>` and the guest's entry is gone, and lifting checks the payload type against the projection of `T`. A stream the host created and the host piped copies from producer to consumer inside a turn with no guest involved.
