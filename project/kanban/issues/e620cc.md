## What to build
Give the conformance harness a progress metric and a menu command. Add a category tag to each line of `expected-failures.txt` (for example `deferred-feature`, `substrate`, `trap-message`, `cascade`). Make the harness emit a machine-readable summary per corpus directory: directives passed, expected failures per category, total. Add `tests conformance` to the menu; it builds the test archive as a derivation, runs only the conformance binary, and prints the summary as a table with a single pass percentage per corpus. Print the same summary as part of `tests native debug`.

## Acceptance criteria
- [ ] Every line in `expected-failures.txt` carries a category, and the harness rejects a line without one.
- [ ] `tests conformance` prints one row per corpus directory with pass, expected-failure, and total counts, and a pass percentage.
- [ ] The summary is also written as JSON next to the archive output for tooling.
- [ ] The harness still fails on an unlisted failure or a stale expectation.


## Review notes

Implementor (2026-09-14): the JSON copy is written under the cargo target
directory (`$CARGO_TARGET_DIR/conformance/summary.json`, printed by the
command), not literally next to the archive, because the archive lives in the
read-only Nix store. `tests native debug` and `tests native release` print the
summary after their run by replaying the summary test with output shown; the
summary test itself also runs inside the archive, captured. Baseline at this
commit: 1595 directives, 1226 passing (76.9%); cm 80.4%, wasmtime 68.4%.
