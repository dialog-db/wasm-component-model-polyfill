## What to build
Give `Store` one cooperative scheduler: a loop the store owns that holds the ready queues, the host tasks, and the task records, with no thread and no executor of its own. Implement `turn` as the design's pseudo-code: a slot for the thread it must switch to next (the callee thread of a call between two components), a high-priority queue for fresh readiness, a low-priority queue for resumptions after a yield, and a resume-after-yield slot; run one item to its next yield point; then poll the host tasks the executor woke with the turn's waker; return `Progress`, `Yield`, `Waiting`, or `Idle`. An item is the start of a task, a callback invocation, the resumption of a thread, or the lowering of a completed host task's result. Record the driver's waker for the duration of the turn so a trampoline can poll a host task with it, and clear it after. Make `Func::call` in `src/instance/func.rs` (and through it `TypedFunc::call`) a driver: it creates a task for the export, polls the scheduler until the task resolves, and returns the lifted result; a synchronous export's task resolves when its core function returns; work the task leaves behind stays in the store, and the future does not wait for it. Make `Linker::instantiate` a driver that runs the plan's initializers inside turns. Enforce the driver rules: a driver entered while another driver of the same store is inside a turn fails with the recursive-driver cause; when a turn finds nothing ready, no host task pending, and the driver's condition unmet, `Func::call` and instantiation fail with the deadlock cause, or with the cannot-block cause when the waiting task must not block; dropping a driver's future cancels nothing, and the task runs in the next turn of any driver; dropping the store drops every task, host task, and suspended thread, and no destructor runs. Add the entry gate as the reference's `enter_implicit_thread`: a task of an `async` export waits at the gate as a queued item, not a suspended thread, when the instance's backpressure is set, when it needs the exclusive thread and one is set, or when tasks are already waiting; tasks held at the gate start in arrival order; a synchronous export's task ignores the gate. Resolve scheduling order as Wasmtime does: threads that became ready together resume in the order they became ready, and a yield always gives way, resuming after every other ready item, with its resumption first returning control to the host executor. The wake after a yield is the one per-target line: natively the driver wakes itself and returns pending; in the browser the yield crosses a macrotask boundary before it wakes the driver, because a self-wake from a microtask lands ahead of every network response and timer and starves the page. Everything else is one code path, polled by any executor natively and by `wasm-bindgen-futures` in the browser.

## Acceptance criteria
- [ ] Every existing test and the whole conformance corpus pass with `Func::call` and `Linker::instantiate` as drivers, on both targets, with the summary counts unchanged except async lines that start passing, which are removed.
- [ ] A test enters a driver from inside a turn and gets the recursive-driver cause.
- [ ] A test makes a driver go idle with its condition unmet and gets the deadlock cause; a variant whose waiting task must not block gets the cannot-block cause.
- [ ] A test drops a driver's future after a `Yield` and shows the pending item runs in the next turn of another driver.
- [ ] A test drops a store with a queued item and a host task and shows no destructor runs.
- [ ] Unit tests of the queues show the switch slot runs before the high-priority queue, the high-priority queue before the low-priority queue, and a low-priority item returns `Yield` to the driver before it runs.
- [ ] A unit test shows tasks held at the entry gate start in arrival order when the gate opens, and that a synchronous task ignores the gate.
- [ ] A browser test shows the driver's resumption after a yield runs after a queued macrotask; a native test shows the driver wakes itself and returns pending.
