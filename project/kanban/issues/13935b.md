## What to build
The `async` canonical option is valid only on an async function type (the spec's Explainer, wasmparser's `check_asyncness`, and the corpus's `validate-no-async-abi-for-sync-type.wast` all enforce it), and the link rule holds an async-typed import to a concurrent registration, so a synchronous registration can never be reached through an asynchronous lower. Yet `return_host_values` in `src/executor/trampoline.rs` carries a `LowerKind::Async` arm (around line 639) that is dead, and the module doc (around lines 37-41) and the function's doc (around lines 677-680) narrate that pairing as live behaviour — contradicting `it_refuses_an_asynchronous_lower_of_a_sync_typed_import` in the same crate. `write_host_result` (around line 745) also carries an arity check that is unreachable on both its callers. Remove the dead arm, make both docs say that an asynchronous lower always reaches a concurrent registration and why, reduce or remove the unreachable arity check with a comment naming the wrapper that fires, and tighten the spilled-parameter test's assertion to a positional check so its message ("in order") is true. The design side — PDD020 line 31 says a sync-typed import can be lowered asynchronously — is the owner's correction and is noted on card 6705da.

## Acceptance criteria
- [ ] `return_host_values` has no `LowerKind::Async` arm and the two docs state the rule truthfully.
- [ ] One arity check remains on the host-result path, or the remaining one is documented as unreachable.
- [ ] The spilled-parameter test asserts the five values positionally.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
