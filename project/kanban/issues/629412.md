## What to build
The owner ran the smoke page (`nix run .#smoke-web`) in Epiphany, which is built on WebKitGTK, as a stand-in for Safari. Two stories fail there and pass in Chromium:

- "Drive a wit-bindgen world with records, variants, and resources" (`RICH_WORLD`, `rust/wcmp-smoke/src/lib.rs:398`, run by `rich_world`).
- "Cross into a 64-bit memory" (`MEMORY64`, `rust/wcmp-smoke/src/lib.rs:406`, run by `memory64` at `:970` over `MEMORY64_COMPOSITION` at `:139`).

Every other story passes in Epiphany. The error text each failing story printed was not captured when this card was filed; record it first.

Find the root cause of each failure and fix it. Safari is a browser the project supports, so a WebKit failure is a bug, not a platform gap to ignore. For each story, find out whether the cause is in the polyfill (the browser substrate `rust/vendor/js_wasm_runtime_layer/`, `src/backend.rs`, or a file with a `wasm32` cfg), in the smoke host, or in a WebAssembly feature JavaScriptCore does not support. Verify browser support against WebKit's own sources or release notes rather than assuming it. For example, check whether the WebKitGTK version in the flake supports 64-bit memories (memory64) and each core feature the wit-bindgen components use.

- If the polyfill is at fault, fix it and add a test that fails without the fix. Put it in the web lanes if a Chromium run can show the defect, and name the WebKit behaviour it guards against.
- If JavaScriptCore lacks a feature the component needs, the polyfill must not fail obscurely. Detect the missing feature and fail with a structured `Error::Unsupported` that names it. The smoke story must then report that refusal clearly instead of an unexplained failure. Record which WebKit release is expected to support the feature.

To reproduce without Safari, drive the smoke page in WebKitGTK from the dev shell. `WebKitWebDriver` ships with nixpkgs' WebKitGTK, and the existing `tests smoke check` shows how the Chromium run is driven. If a headless WebKit run is practical, add it as a menu command (for example a `tests smoke` leaf) so the regression stays checkable. If it is not practical, say why and document the manual Epiphany procedure in the smoke crate.
