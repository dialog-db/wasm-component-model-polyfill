## What to build

PDD028, the second half of "Keeping Up With Wasmtime", and the snapshot test.

- **Corpus.** A pinned copy of the 35 WIT entries of Wasmtime's codegen corpus (`crates/component-macro/tests/codegen.rs:3-47` at `v49.0.0-rc.1`), with its source commit.
- **Sets.** Wasmtime's six option sets with the PDD's expected results (no options compiles; `async` and `async | store` on imports refused; `tracing | verbose_tracing` with `Borrowing` refused; `imports` with `store` compiles; `anyhow: true` with `trappable` compiles), plus the polyfill's three: `tracing | verbose_tracing` without `Borrowing`, `exports` with `async | store`, and `trappable | exact` on one named function. An entry that needs a refused option fails with that refusal in every set.
- **Both targets.** Each entry that compiles builds natively and for `wasm32-unknown-unknown`.
- **Snapshots.** `stringify` output for a chosen set of corpus entries, committed, compared on each run. Document how to regenerate them (a menu command or the existing `tests regenerate` path).

## Acceptance criteria
- [ ] The codegen corpus gives the expected results: under each of the nine sets, each entry compiles or fails with the refusal the table gives.
- [ ] Both targets build each entry that compiles.
- [ ] The output keeps its shape: snapshot tests through `stringify` match their committed snapshots, and a change to the generator fails them.
- [ ] Moving the pin is documented: a new corpus entry fails the test until a person classifies it.
- [ ] `lint` passes, and `tests all` is green on both targets with the conformance summary unchanged.
