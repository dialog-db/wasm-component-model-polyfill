## What to build
The review of card `7f515d` accepted the seam's one budget (`src/concurrency/suspend_seam.rs`, `unserved_turns` and `note_turn`) and left findings that need one card. First, the count is store-global and `run_nested_turns` does not reset it on entry, and `past_budget` (`suspend_seam.rs:393`) is checked ahead of `store.suspend_cause()` (`:397`), so yields taken earlier in the same call poison a later block's cause: a guest that yields exactly `SPIN_BUDGET` times against an idle store and then calls a blocking built-in fails with the stack-switch cause where deadlock or cannot-block is the true one. The window is one call, because each host export call runs a task-start item that resets the mark. Decide whether a block starts its own run (reset on entry) or whether the design's "one count for the store" means the block inherits the yields, and state which. Second, the docs of the public `Error` type at `src/error.rs:819-832` still describe `StackSwitchNeeded` as "the store still held work the block could not reach" and say an idle store gives deadlock and a may-not-suspend carrier gives cannot-block; past the budget all three are false, and this finding was carried over from the asynchronous-start review. `src/store/store_context.rs:325` still says "Four rules hold for the fallback" while the seam and the design say five. Third, add the tests the review found missing: a target with a suspend provider never consults the budget (the `Recorded` provider harness at `suspend_seam.rs:1092-1099` already exists); a converging no-caller loop just past the budget, pinning where the cut-off lands; the block-after-yields cause; and the store-wide per-thread rule now that `it_starts_the_run_over_when_another_thread_gives_way` is gone (two tasks that ping-pong yields share one count).

## Acceptance criteria
- [ ] A guest that yields `SPIN_BUDGET` times and then blocks on an idle store fails with the cause the design states for that block, proved by a unit test in `suspend_seam.rs` that calls `give_way` `SPIN_BUDGET` times and then `SuspendSeam::suspend(|_| false)`.
- [ ] The docs of `Error` at `src/error.rs:819-832` and the comment at `src/store/store_context.rs:325` state the rule the seam implements.
- [ ] The four missing tests exist, and the ones that pin a behaviour fail on the code before their change.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
