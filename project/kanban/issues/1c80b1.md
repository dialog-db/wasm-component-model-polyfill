## What to build
`StoreContext::abandon_export_task` (`src/store/store_context.rs` around lines 1025-1031) calls `Scheduler::discard_task_items` unconditionally before `HandleTables::abandon_task`, but `abandon_task` returns early when the task's scope is not on the stack (`src/resource/tables.rs` around line 90) and leaves the record in the store; the same holds for `exit_export_task`. Every production caller today has the scope on the stack, so nothing reaches it, but the pairing is load-bearing: the first caller that abandons a parked task would drop a live task's items, the mirror of the bug the sweep fixed. Make the sweep conditional on the record actually leaving (return whether `abandon_task`/`exit_task` removed the record and sweep only then), or state the precondition on `abandon_export_task` and enforce it with a structured internal error, and add a test that abandons a parked task and asserts its items survive. Also fix the doc at `scheduler.rs` around line 109 — "a task ends this way on every path" — to name the three record-removal paths that do not sweep (`exit_current_task` via `exit_sync_call`, `BoundaryCall::drop`, `StartTask::drop`) and why they need not; correct the comment at `tests/baseline_prepared_call.rs` around lines 592-593 (the callee's core function is never reached; `start_call` fails on the removed subtask record); and add one component whose callback returns the exit word, so the literal `an export's task is not in the store` message the original card named is proved absent.

## Acceptance criteria
- [ ] Abandoning a task whose scope is off the stack leaves its queued items in place, proved by a test, and the sweep runs on every path where a record does leave.
- [ ] The scheduler module doc names which record-removal paths sweep and why the others need not; the wrong test comment is corrected.
- [ ] A component whose dead callee's callback returns the exit word neither runs it nor fails with the internal error, proved by a test.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
