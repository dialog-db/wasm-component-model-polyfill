## What to build
Work through the expected-failures lines categorized `trap-message`: emit the trap messages Wasmtime uses (`unknown handle index N`, `discriminant N out of range [0..M)`, `string pointer/length out of bounds of memory`, `invalid utf-8`, `realloc return: beyond end of memory`, `realloc return: result not aligned`, `string pointer not aligned to 2`, `cannot leave component instance`) and add the checks the messages imply: realloc result bounds and alignment, UTF-16 pointer alignment, and a variant discriminant range check. Route each through `AbiCause` variants rather than free text where a variant exists.

## Acceptance criteria
- [ ] Every `trap-message` line whose directive the polyfill otherwise passes is removed from the list.
- [ ] `assert_trap` directives in `values/realloc.wast` and `values/strings.wast` pass.
- [ ] No message is matched by substring where the corpus expects the exact Wasmtime wording.


## Review notes

- Implemented on the host, 2026-09-15. Every `trap-message` line is gone
  from `expected-failures.txt`; the corpus is at 217 expectation lines
  (113 cascade, 67 deferred-feature, 24 validation, 12 substrate, 1
  defect). Native 214 tests, web 172, `nix flake check` green.
- Messages now use Wasmtime's wording: `unknown handle index N`,
  `discriminant N out of range [0..M)`, `string pointer/length out of
  bounds of memory`, `list pointer/length out of bounds of memory`,
  `string pointer not aligned to N`, `invalid utf-8`, `incomplete utf-8
  byte sequence`, `realloc return: beyond end of memory`, `realloc
  return: result not aligned`, and `handle index N used with the wrong
  type, expected guest-defined resource but found a different
  guest-defined resource`. Realloc results route through the new
  `AbiCause::ReallocReturn { reason }` variant.
- `cabi_realloc` now runs for empty lists and strings too, as the
  canonical ABI prescribes, so a misbehaving allocator traps even when
  nothing is written. List allocation uses the element alignment.
- The wrong-type trap needed the spec's table model: one handle table
  per component instance shared by every resource type, with each entry
  tagged by its `ResourceTypeId`. `HandleEntry` is now a struct (`rep`,
  `type_id`, `guest_defined`, `kind: HandleKind`), and every access goes
  through `HandleTables::lookup` / `remove_own`, which return a
  `HandleLookupError` carrying the Wasmtime message. The host-side
  tables are unchanged in behavior.
- The browser backend gained patch 5 (`Memory::current_pages` from the
  buffer length) so the bounds checks see the real memory size on web.
- The harness matches trap text by substring, as Wasmtime's own wast
  runner does; the polyfill's messages are the exact Wasmtime strings.
