## What to build
The smoke test (`rust/wcmp-smoke`) is the one program a person reads to see what the polyfill does, run from the same source natively and in the page, and gated by `smoke check`. Its six steps predate the parity work on core modules, plain-named and nested exports, `map<K, V>`, fixed-length `list<T, N>`, 64-bit memories, and engine configuration, so none of that surface appears in it.

Add one self-contained step for each, in the crate's style (its own store, real evidence in the report, identical evidence on both targets):

1. **Real-toolchain values.** Drive the `maps` and `fixed-lists` fixtures the harness ships: a `map<string, u32>` through `HashMap` and through `Val::Map`, and a `[u8; 16]` through the typed and untyped surfaces.
2. **Core modules at the boundary.** A component that exports a core module; the host takes the `Module`, reads its imports and exports, instantiates it, and registers it through `LinkerInstance::module` for a second component that imports and instantiates it.
3. **Export navigation by name.** Reach a function inside a plain-named instance export and inside a nested one through `ExportLookup`, and read its signature through `Func::ty`.
4. **A 32-bit and 64-bit composition.** The string round trip between a 32-bit and a 64-bit component, with a small memory so the page passes too.
5. **Engine configuration.** Instantiate the same `implements`-annotated component under the default `EngineConfig` and under one that opts in, reporting the rejection on one side and success on the other.

Failure contracts (kind mismatches, unresolved imports, wrong lengths) stay in the baseline tests; a smoke step shows the polyfill working. Every step's evidence must be the same string on both targets, because `smoke check` compares the page's report with the native run's line for line.

## Acceptance criteria
- [ ] The smoke test has one step per item above, and each names the guest it drives and the value it moves.
- [ ] `smoke native` and `smoke check` pass with the same report.
- [ ] `tests all` passes on both targets.
