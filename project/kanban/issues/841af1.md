## What to build

Non-blocking findings from the independent review of 5ccfd2 (browser faithfulness, landed with this card's parent), in `rust/wcmp-wasm-core-web` and `rust/wcmp-wasm-core-faithfulness`:

- **Worker lane.** Workers may wait, so running `tests/faithfulness.rs` with wasm-bindgen-test's `run_in_dedicated_worker` should clear `proposals/threads/atomic.wast:434-435`, if wbg-pool supports workers. Keep the main-thread wait trap covered in the contract and web tests.
- **NaN fallbacks.** NaN payloads are still lost where a float crosses as a Number: exports of non-final, subtyped or multi-type rec-group function types; signatures that mix a float with a concrete reference; calls where the function type is unknown (a funcref a guest handed out); `WebAssembly.Global` get and set. No spec script observes it, but a host could. Add web tests that pin each path, and close the ones that can be closed.
- **f64 cost.** Every f64 now crosses as a BigInt. Measure it with the web bench.
- **Safari lane readiness.** The expected-failure list is one per backend, with a V8 header and citations, and the stale check makes it unshareable: a Safari lane needs per-engine lists (the macro takes one const). The segment-trap texts are V8-only and JavaScriptCore needs its own rows.
- **Stale wording.** The parse error still says "cites no defect of the engine" (`expected_failures.rs:65`, matched by the Wasmtime `should_panic` test), and `lib.rs:139` is named `it_cites_an_engine_defect_for_each_expected_failure`, both narrower than the rule now, which also accepts spec citations for embedding limits.

## Acceptance criteria

- [ ] Each NaN fallback path is tested, and closed where possible.
- [ ] A bench number for f64 crossings is recorded.
- [ ] Expected-failure lists can be per engine, and the browser backend's are.
