## What to build
Scenario 14 of PDD024: two Rust partners linked at run time, with no Zena component. It is the baseline for the scenarios with a Rust partner (10 to 13).

The independent review of card 8ba35a (landed as `2c71c4b6a`) found that the browser and native subjects never exercise the Rust partner: the record compares only stages, and in scenarios 10 and 11 the Zena component stops at `parse` first, so a polyfill regression on the Rust side would still pass the gate. The reviewer showed, in a throwaway clone, that two partners linked at run time pass today in the browser, natively and under Wasmtime. PDD024's Integration Scenarios section now describes scenario 14 and why it exists.

- Add scenario 14: a Rust importer and a Rust exporter, built as partners the way scenarios 10 and 11 build theirs (`tests/zena/partner.sh`), linked at run time through `wiring.txt`, passing a string across the link untyped and typed. Follow the async contract that run-time links need.
- Each partner declares whatever world it needs; PDD024 now lets a partner declare its own world in the scenario's WIT or its own.
- The greeting should name the answering side, as scenarios 10 and 11 do, so a pass proves the call crossed the link.
- Regenerate and commit the record lines.

## Acceptance criteria
- [x] Scenario 14 runs under all three subjects and passes on each.
- [x] A change that breaks the polyfill's handling of a Rust partner or of the run-time link fails `tests zena` in the browser and natively.
- [x] The record holds lines for scenario 14, and `tests zena` passes the gate.
- [x] `tests native debug`, `tests web debug` and `lint` pass.
