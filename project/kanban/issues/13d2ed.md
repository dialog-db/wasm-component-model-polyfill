## What to build
From the 2026-10-13 review of e2fb8a. The downstream guard still lets a Cargo configuration through.

- Crane's `configureCargoCommonVarsHook.sh` sets `CARGO_HOME=${CARGO_HOME:-$PWD/.cargo-home}` in postPatch. `downstreamBuildCheck`'s postUnpack changes into `rust/wcmp-downstream` first, so `CARGO_HOME` is `rust/wcmp-downstream/.cargo-home`. That directory is inside the build's fileset, and the guard checks only `.cargo`.
- Checked on 2026-10-13: a committed `rust/wcmp-downstream/.cargo-home/config.toml` holding `paths = ["/nonexistent-wcmp-probe"]` passed the guard, and Cargo then failed with "failed to update path override `/nonexistent-wcmp-probe` (defined in `/build/source/rust/wcmp-downstream/.cargo-home/config.toml`)". A real `paths` entry would build a local fork.
- A `paths` override keeps the crates.io source in `Cargo.lock` and in `cargo metadata`, so neither the lock check nor `downstreamPathCheck` (which looks only at `source == null`) sees it.
- The comment above `downstreamBuildCheck` says "no Cargo configuration above the consumer applies". That is not true while `CARGO_HOME` is in the source tree.

Fix options from the review, which can be combined:
- Export `CARGO_HOME="$NIX_BUILD_TOP/cargo-home"` in postUnpack, before the `cd`.
- Allow only known entries in the consumer's directory (`Cargo.toml`, `Cargo.lock`, `src`, `tests`).
- Make the path check refuse any package whose `manifest_path` is neither under the vendor directory nor one of the allowed paths, whatever its `source`.

Nit: the `config-include` and `config-two-files` cases in `downstream-guard` refuse on file names alone, and the build maps file contents to `null`, so they do not test any parsing. Say so in their comment.

## Acceptance criteria
- [ ] A Cargo configuration under `rust/wcmp-downstream/.cargo-home` (or any other directory the build makes `CARGO_HOME`) does not reach the downstream build, and `downstream-guard` holds that case.
- [ ] A `paths` override of a crates.io dependency is refused by the guard or by the path check.
- [ ] The comment above `downstreamBuildCheck` is accurate.
- [ ] `lint` passes, and `downstream-build` passes.
