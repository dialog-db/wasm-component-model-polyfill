## What to build

The test of one host core under both macros (2f73a6, `rust/wcmp-bindgen-tests/tests/dual.rs`) found three differences between its two glue modules that PDD028's "Both Targets" list does not name. Decide for each whether the polyfill closes it or the design lists it.

1. **A host's own error.** Wasmtime's glue writes `self.core.checked(x).map_err(wasmtime::Error::new)`; the polyfill's writes `Ok(self.core.checked(x).map_err(anyhow::Error::new)?)`, because `wcmp::Error` converts from an `anyhow::Error` but not from any `std::error::Error`. A `From<E: std::error::Error>` would overlap the reflexive `From<Error>`, so closing this needs another shape (for example `Error::host(e)` or a `Context`-style extension trait).
2. **Finding the host's error in a call's error.** Wasmtime's glue calls `error.downcast_ref::<CheckFailed>()` on the error a call returns. The polyfill's reads `std::error::Error::source(&error)` first, because `Error::Host` keeps the host's error as its source and `wcmp::Error` has no `downcast_ref`. A `downcast_ref` on `Error` that walks the chain would make the two the same.
3. **Making the engine, the store, and the component.** `wcmp::Store::new` returns a `Result`, `wcmp::Component::new` is awaited, and the engine takes a backend; Wasmtime's engine takes a `Config` with `wasm_component_model_async(true)`. This is outside the glue's trait impls, and may only need listing.

## Acceptance criteria
- [ ] Each of the three is closed in the polyfill or listed in PDD028's "Both Targets", with the owner's decision recorded here.
- [ ] `tests/dual.rs`'s list of differences matches the decision.
