## What to build

PDD028, "The Option Ledger" and the first half of "Keeping Up With Wasmtime".

- **Ledger in code.** One table in the macro crate that classifies each option and each flag as matched, accepted with no effect, or refused with a reason, matching the PDD's two tables. The refusals not yet built: `ownership: Borrowing { … }`, `named_imports`, `include_component_type`. Each refusal is a compile error that names the option and the reason.
- **Ledger test.** Reads the options and the flags that the parser of Wasmtime's macro accepts at the pinned version (`crates/component-macro/src/bindgen.rs:276-296` and `crates/wit-bindgen/src/config.rs:5-15` at `v49.0.0-rc.1`) and compares them with the ledger. An option or flag without an entry fails the test and names it. Engineering decides how the test reads Wasmtime's set (the pinned crate source, or a checked-in extract with its source commit and a check that it matches the pin).
- **Compile-fail tests.** One per refusal of the ledger: `Borrowing`, `named_imports`, `include_component_type`, `wasmtime_crate`, `async` on a plain import, `async | store` on a plain import, `async` on `[drop]r`.

## Acceptance criteria
- [ ] The ledger is complete: the ledger test finds an entry for each option and each flag that Wasmtime's parser accepts at the pinned version.
- [ ] Removing one entry from the ledger makes the test fail and name the option.
- [ ] The macro refuses each unsupported option: a compile-fail test covers each refusal, and each error names the option and the reason. The error for `async` on a plain import suggests `async func`.
- [ ] `lint` passes, and `tests all` is green on both targets with the conformance summary unchanged.
