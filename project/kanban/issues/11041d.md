## What to build
`LinkerInstance` inserts every registration into a map (`src/linker/linker_instance.rs:116, 153, 171, 201, 262, 321`), so a second `func_new`, `func_wrap`, `resource`, or `module` under one name silently replaces the first. Wasmtime fails with `map entry `{name}` defined twice` unless `allow_shadowing(true)` was set (`crates/environ/src/component/names.rs` around line 146 and `crates/wasmtime/src/runtime/component/linker.rs`). Refuse the duplicate with a `LinkError` carrying Wasmtime's wording, add `Linker::allow_shadowing`, and state the rule on the `Linker` type doc. Wasmtime's `define_unknown_imports_as_traps` has no counterpart either; the owner decided (2026-09-21) it is a later card of its own, because it changes what `instantiate` does with a missing import, so this card stays with the shadowing rule.

## Acceptance criteria
- [ ] A second registration of any kind under one name fails at registration with Wasmtime's wording unless `allow_shadowing(true)` was set, proved by tests for each kind.
- [ ] The `Linker` type doc states the rule and the escape hatch.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
