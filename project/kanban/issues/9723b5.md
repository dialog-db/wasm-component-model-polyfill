## What to build
A component whose interface `b` does `use a.{r}` imports `b` as an instance whose type carries `(export "r" (type (eq …)))` for the resource `a` defined. The polyfill's linker demands a registration of `r` under `b` as well: in `check_instance_items` (`rust/wcmp/src/linker/resolve.rs:575-596`) the item's label equals its own name, so it falls through to `check_resource_item("r", <b's registration>)`, which refuses when `b` registers no `r`.

Wasmtime links it. `TypeChecker::definition` (`crates/wasmtime/src/runtime/component/matching.rs:74-80`, Wasmtime 49) accepts a resource import with no definition when the resource was already defined by an earlier import: "this is an `(eq ...)` import which is not required to be satisfied via `Linker` definitions". When a definition is supplied anyway, it must match the identity already recorded.

The polyfill already applies this rule at the root (`resolve_root`, `resolve.rs:457-463`, through the `defined` set). Extend it to items inside an instance import: an `eq` resource item whose resource index is in `defined` needs no registration under that interface. A registration that is present must still carry the same identity (`check_shared_identity`).

Why now: a generated `add_to_linker` for `b` registers nothing for `r`, as Wasmtime's bindings do, so the host-binding design (3200e7) depends on this rule. It was that card's constraint 7; it needs no design, because it follows Wasmtime.

## Acceptance criteria
- [x] A component with `b` using `a.{r}` links with `r` registered under `a` only, and a handle minted under `a` passes through a function of `b`, on both targets.
- [x] A registration of `r` under `b` with a different identity is still refused with `TypeMismatch` naming the interface and item.
- [x] A component whose `b` declares its own (non-`eq`) resource `r` still needs a registration under `b`.
- [x] `lint` passes and `tests all` is green with the conformance summary unchanged or improved (name any corpus line that starts to pass).


## Delivery notes

Pulled into the PDD028 thread with the owner's OK (2026-10-17), because 1cc7ae's `eq` criterion depends on it. Delivered on the host in `fix(linker): Link a used resource with no registration of its own`.

- `check_instance_items` takes the `defined` set: a resource item whose resource an earlier import defined, with nothing registered under its name, needs no registration under that instance. The item may arrive as `ExternType::Resource`, so the test is the `defined` set alone; a fresh `(sub resource)` has an index of its own, which no earlier import defined. A registration that is present is checked against the recorded identity as before.
- Tests: `rust/wcmp/tests/baseline_eq_resources.rs` (links and passes a handle through `b`; another identity under `b` is a `TypeMismatch` naming `users` and `counter`; a resource `b` declares itself still needs a registration).
