## What to build
The first trap ends the driver that is polling, with that trap, and poisons the store in the same step. A driver is `Func::call`, `TypedFunc::call`, an instantiation, or `Store::run_concurrent`. The rule is Wasmtime's: a failure of a work item or a host future ends its event loop, and the whole `run_concurrent` returns it (`concurrent.rs:1325-1340` at `v49.0.0-rc.1`). It holds whichever task the trap belongs to:

- A trap in the call's own task ends that call.
- A trap in work that a task left after it resolved ends the driver whose turn runs that work.
- A trap inside `run_concurrent` ends the whole `run_concurrent`, and its closure is dropped with every call future inside it.
- A trap in a thread that outlives its task's host call ends the driver whose turn runs that thread.
- A failed host `async` function ends the driver whose turn polls it.

A host `async` function whose future completes with an error is a trap of the guest task that made the call, and it poisons the store. This trigger is the polyfill's own: Wasmtime ends the event loop without setting its flag, but that task can never resolve its subtask, which the reference does not permit.

This replaces the per-task routing of card `6c8808`. Retire its machinery: `FailureChannel` (`src/concurrency/failure_channel.rs`), the `attach_failure_channel` sites in `src/instance/func.rs`, and the channel arms of `fail_export_task` (`src/store/store_context.rs:2243`). A caller that already returned never learns of a later trap in its task; the next driver reports it. State the rule in the public docs of `Func::call`, `TypedFunc::call`, and `Store::run_concurrent`.

This card absorbs bug cards `9795f4`, `2999c3`, and `6349cc`, which the plan cancelled in its favor. Their findings that still apply under the new rule:

- A callback export that resolves in turn N and whose host body fails in turn N+1, after `Func::call` or `call_concurrent` answered (`9795f4`, `6349cc`). The failure must reach the polling driver and must not be lost.
- A failing host call made by a task that had no failure channel: a synchronous `Func::call` task, a guest-to-guest callee created by the prepare intrinsic, an adapter-pushed task (`9795f4`).
- A host-body failure while the calling task sits on the scope stack below another task's nested turn (`9795f4`).
- A trap in an explicit thread after its task's host call returned, swallowed today (`2999c3`; the corpus symptom is `during-sync-call-no-sibling-resume.wast:156`).
- The no-provider `run_thread` path in `src/executor/thread_builtins.rs`, which returns a thread's failure to the switching thread's built-in even when the ended thread belongs to another task; make it report as the provider path does (`2999c3`).
- `WakeSlot` (`src/concurrency/wake_slot.rs`) drops a value on a poisoned lock instead of returning a structured `Error`, which turns the slot into a permanent park; fix it if `WakeSlot` survives the retirement (`6349cc`).
- `discard_subtask` in `src/concurrency/host_task.rs` duplicates `executor::release_subtask`; fold it if the retirement leaves both (`9795f4`).

## Acceptance criteria
- [ ] A repository test proves each shape on both targets, and the driver returns the trap in each: a callback task that resolved in one turn and traps in a later turn; a thread that outlives its task's host call and traps; a callback export that fails after it resolved; a host `async` function that fails, called by a task that no host call owns; two concurrent calls inside `run_concurrent`, where one traps. In the last shape, `run_concurrent` returns the trap and the other call future is dropped. In each shape, the next driver fails with "cannot enter component instance".
- [ ] A repository test on both targets proves that a failed host `async` future poisons the store: after it, `Func::call` fails with the cannot-enter message.
- [ ] A repository test on both targets covers a failing host call made by a synchronous `Func::call` task and by a guest-to-guest callee, and a host-body failure while the calling task is on the scope stack; each reaches the polling driver.
- [ ] `FailureChannel` and its attach sites are gone, and the public docs of `Func::call`, `TypedFunc::call`, and `Store::run_concurrent` state where a trap surfaces.
- [ ] `lint` passes and `tests all` is green on both targets, any directive that starts passing has its line removed from the expected-failure list, and every line whose reason this card changes is refreshed from a live run.
