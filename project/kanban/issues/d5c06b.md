## What to build

Non-blocking findings from the independent review of 7ae4a0 (the fidelity suite, landed `e777b6c85`) in `rust/wcmp-wasm-core-fidelity`:

- **Silent drops.** If a `wasmparser` bump or a pin move sends a script outside every suite, its test still passes with "the backend does not run it" (`suite.rs:44-47` for a module refused under every feature, `suite.rs:62-66` for a feature the lexicon does not name, both reaching `check.rs:35-48`). Commit a record of script to suite, plus the skips, and have a test hold the run to it.
- **`ref.host`.** The `extern.wast:42` skip can be avoided: the runner can make a `ref.host` by passing an `ExternRef` through a small generated module (`any.convert_extern`). Tighten the loose patterns too: `patterns.rs:57` accepts any non-null `anyref` for `ref.host`, and `patterns.rs:53` ignores which function a `ref.func` names.
- **Lifted refusals.** A spec refusal that a declared capability lifts is skipped (`assert_refused` via `Suite::lifting`). Check instead that the engine accepts the module.
- **Citations per engine.** `Citation::parse` (`citation.rs:51`) accepts an issue from any GitHub repository or a bug from any browser tracker for any backend. Tie the accepted forms to the backend.
- **Missing tests.** Runner tests for `assert_unlinkable`, `register` and import resolution, and a lifted refusal; a `check_script`-level `unexpected:` test.
- **Speed.** `Suite::of` runs two or three times per script (`check.rs`, `runner.rs`, the report).

## Acceptance criteria
- [ ] A committed sorting record fails the run when a script changes suite or a skip appears.
- [ ] `extern.wast:42` runs, and the `ref.host` and `ref.func` patterns check identity.
- [ ] A lifted refusal asserts that the engine accepts the module.
- [ ] Each backend accepts only citations that fit it.
- [ ] The missing runner tests exist.
- [ ] `tests all` and `lint` pass.
