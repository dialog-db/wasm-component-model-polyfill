## What to build
When the payload is a number type (`s8`, `u8`, `s16`, `u16`, `s32`, `u32`, `s64`, `u64`, `f32`, `f64`) or absent, a copy moves bytes: the translator (`src/executor/translate.rs`) selects the byte path from the payload type of the built-in, and the copy calls the runtime layer's read of one memory and write of the other once, with no value built per element. Every bit pattern of those types is a valid value, so a byte copy and a value copy give the same bytes. `bool` and `char` are excluded because not every bit pattern is valid for them, which is the set Wasmtime selects in its compiler. Every other payload keeps the element-wise path through the two boundary contexts. The same set gates a read and a write from one instance: the reference traps, as a temporary rule, when the two ends of one stream or future are used from the same instance and the payload is not a number type, and the polyfill keeps the rule with Wasmtime's message (`cannot read from and write to intra-component future`, and the stream form). `passing-resources.wast` passes whole: owned handles cross a stream, and its last directive expects the handle-table message the synchronous baseline gives an unknown index.
