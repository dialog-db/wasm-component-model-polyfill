## What to build
The synchronous-lower card's tests prove a pending-once future resolves inside `block_on_host_task`, but `SuspendSeam::run_nested_turns` checks the condition before the first nested turn, so every new test resolves on the first condition check with zero turns run; the test named `it_blocks_a_synchronous_lower_through_a_nested_turn_with_no_provider` (`src/store/store_context.rs`) and the comments at `tests/baseline_sync_lower.rs` around lines 266-270 and 294-297 claim a nested turn polled the body when none ran. Add a test whose host future resolves only after a nested turn runs a sibling task's item (for example a callback task of another instance whose event the future awaits through the accessor), so the integration the card describes is exercised, and correct the names and comments that overstate. While there, add the negative control the borrow test borrows from `baseline_async_lower.rs` — the drop traps on the same component while the lend stands — and assert the success path leaves no subtask record.

## Acceptance criteria
- [ ] A test proves a synchronous lower blocked on a host future returns once a nested turn ran the item that let the future resolve, with the turn count or the item's log pinning that a turn ran.
- [ ] The test names and comments that claim a nested turn ran say what the test proves.
- [ ] The borrow test on `LENDS_A_BORROW_THROUGH_A_SYNCHRONOUS_LOWER` has a negative control on the same component, and a test asserts the success path leaves no subtask record.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
