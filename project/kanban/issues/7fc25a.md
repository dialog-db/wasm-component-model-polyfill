## What to build
The review of card `86cb02` accepted the change that a borrow lifted out of the defining instance resolves through its table and lends, and found that one of the two changed sites has no test. The card's fixture is a cross-component call, so it exercises `transfer_borrow` in `src/executor/intrinsics.rs` only; the `lift_handle` hunk in `src/abi/lift.rs` is the host-boundary lift and no fixture enters it — no corpus or baseline fixture has a guest that defines a resource and lifts a borrow of its own resource out to a host import (`BORROWER` in `tests/baseline_resources.rs:972` imports the resource; the async fixtures are importer-side). Reverting that hunk alone leaves the suite green. Add the fixture: a component that defines `r`, mints one with `resource.new`, and passes `borrow<r>` to a host import; the host sees the rep, not the index, and the owning entry is lent for the length of the call (`resource.drop` of the owner inside the call fails with "cannot remove owned resource while borrowed", and succeeds after it). Also pin the residual both references share: a defining instance that receives a borrow as a bare rep and forwards that value onward as `borrow<r>` traps with the unknown-handle cause; a test states that this is the reference's behaviour (`definitions.py` `lower_borrow` returns the bare rep for the definer), so a later reader does not mistake it for a defect.
