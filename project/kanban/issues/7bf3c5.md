## What to build
Test host functions for the WASI imports Zena's output calls, and the three scenarios that need them.

The functions live in the scenario runner, use only the polyfill's public `Linker` API, and are not exported by the crate. They are not a WASI host. They cover only what the first set calls, at the interface versions the pinned toolchain emits:

- The p2 stdio functions Zena's console output calls, from `wasi:cli`, `wasi:io/streams`, and the `wasi:io/error` resource. A write goes to a buffer that the runner compares with the Wasmtime run's output.
- The p3 `wasi:clocks` wait, as an async host function. A `setTimeout` timer backs it in the browser, and a native timer backs it natively.
- The fixed test interface: one function that takes a string and returns it, the same one the Wasmtime run defines.
- A method the functions do not implement returns an error, so a Zena change that calls a new method shows as a stage, not a silent pass.

Scenarios, each with its Zena program, expectations file, and regenerated record lines:

- 5: console output.
- 6: an async export that sleeps on a timer. It prints "before" and "after", never a duration.
- 7: a custom world through `--wit` and `--world` that imports the test function.

## Acceptance criteria
- [ ] Scenario 5 prints through the p2 stdio functions, and its output lines are the same under the Wasmtime run and the polyfill subjects. Where a subject stops before the call, the record shows that stage and the card says so.
- [ ] Scenario 6 sleeps on the p3 timer in the browser and natively.
- [ ] Scenario 7's import is supplied by the test function on every subject.
- [ ] A test calls a method the functions do not implement, and the call returns an error.
- [ ] The record holds lines for scenarios 5, 6, and 7, and `tests zena` passes the gate.
- [ ] `tests native debug`, `tests web debug`, and `lint` pass.
