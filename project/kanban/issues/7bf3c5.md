## What to build
Test host functions for the WASI imports Zena's output calls, and the three scenarios that need them.

The functions live in the scenario runner, use only the polyfill's public `Linker` API, and are not exported by the crate. They are not a WASI host. They cover only what the first set calls, at the interface versions the pinned toolchain emits:

- The p2 stdio functions Zena's console output calls, from `wasi:cli`, `wasi:io/streams`, and the `wasi:io/error` resource. A write goes to a buffer that the runner compares with the Wasmtime run's output.
- The p3 `wasi:clocks` wait, as an async host function. A `setTimeout` timer backs it in the browser, and a native timer backs it natively.
- The fixed test interface: one function that takes a string and returns it, the same one the Wasmtime run defines.
- A method the functions do not implement returns an error, so a Zena change that calls a new method shows as a stage, not a silent pass.

Scenarios, each with its Zena program, expectations file, and regenerated record lines:

- 5: console output.
- 6: an async export that sleeps on a timer. It prints "before" and "after", never a duration.
- 7: a custom world through `--wit` and `--world` that imports the test function.

Notes from the review of 17e40b (landed as `4d3706559`):
- The pinned Zena prints through p3 `wasi:cli/stdout@0.3.0`, not p2 stdio as PDD024's Facts section says (confirmed with `wasm-tools component wit` on the compiled printer). The Wasmtime run links both p2 and p3 WASI and captures standard output in one in-memory pipe. The polyfill's test host must provide p3 standard output too.
- The Wasmtime run's fixed test interface is `wcmp:scenario/host` with `echo: func(text: string) -> string`.
- Typed calls fail in the Wasmtime run with 'does not make typed calls yet' until ff3743.

Notes from the review of 264c89 (landed as `b882bd371`):
- The polyfill runner's test host implements p3 `wasi:cli/stdout@0.3.0` (`write-via-stream`), an empty `wasi:cli/types@0.3.0`, and `wcmp:scenario/host#echo` (`tests/zena/host.rs`). An import the host does not define is left out of the linker, so the whole component stops at `link`. PDD024 says a missing method returns an error when called; that difference is the owner's to judge, and this card's stubs decide which imports exist.
- The pinned Zena keeps the stdout writer open across calls and never reads the returned future. Only a hand-written WAT test covers the host today.
