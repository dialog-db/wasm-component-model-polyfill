## What to build
Scenarios linked by composition, and the `compose` stage.

- For a scenario whose wiring says composition, the build composes its components with the flake's `wac` (the one the conformance fixtures use) into one component. The three subjects then run it like a scenario with one component.
- The build never fails because `wac` refused the components. It keeps `wac`'s error output, and the stage is `compose` for every subject, as a failed Zena compile is `compile`.
- Scenario 9: Zena with Zena. Scenario 12: Zena imports from Rust. Scenario 13: Rust imports from Zena. Each passes a string.
- Regenerate and commit the record lines.

Notes from the review of 8ba35a (landed as `2c71c4b6a`):
- A scenario's Rust partners live one directory each (`<partner>/cargo-manifest.toml`, `cargo-lock.toml`, `src/`), are built offline by `tests/zena/partner.sh` with wit-bindgen 0.62, and bind a world in the scenario's `wit/`. The builds join the Zena programs in the same `.status`/`.log`/`.wasm` layout, so the runners need no code change per partner.
- A composed component is one component, so the async-only restriction of run-time links does not apply to it; a sync contract works across a composition.
- On web and native the Zena component stops at `parse`, and the record compares stages only, so a composed scenario's polyfill lines will not show whether the partner half works (card 6d91fb).
