## What to build
Scenarios linked by composition, and the `compose` stage.

- For a scenario whose wiring says composition, the build composes its components with the flake's `wac` (the one the conformance fixtures use) into one component. The three subjects then run it like a scenario with one component.
- The build never fails because `wac` refused the components. It keeps `wac`'s error output, and the stage is `compose` for every subject, as a failed Zena compile is `compile`.
- Scenario 9: Zena with Zena. Scenario 12: Zena imports from Rust. Scenario 13: Rust imports from Zena. Each passes a string.
- Regenerate and commit the record lines.

Notes from the review of 8ba35a (landed as `2c71c4b6a`):
- A scenario's Rust partners live one directory each (`<partner>/cargo-manifest.toml`, `cargo-lock.toml`, `src/`), are built offline by `tests/zena/partner.sh` with wit-bindgen 0.62, and bind a world in the scenario's `wit/`. The builds join the Zena programs in the same `.status`/`.log`/`.wasm` layout, so the runners need no code change per partner.
- A composed component is one component, so the async-only restriction of run-time links does not apply to it; a sync contract works across a composition.
- On web and native the Zena component stops at `parse`, and the record compares stages only, so a composed scenario's polyfill lines will not show whether the partner half works (card 6d91fb).

> FINDINGS (none blocking)
> F1 [medium, verified empirically]: compose.sh ignores the <import> column of a composition link. It reads only words[1] and words[3] (compose.sh:~68-69), and 'wac plug' fills every import whose name matches. I copied the scenario 9 programs, changed the wiring to 'composition importer wcmp:bogus/nothing exporter', and the composer exited 0 with compose-status 0. So a mistyped or stale wiring composes silently, and the wiring no longer documents the link. It could also plug more imports than the one named. Suggested fix: after a successful plug, check that the named import is gone from the composition, or fail the build when the named interface is not among the importer's imports.
> F2 [low]: The composition takes the importer's name, so every later reason says 'component importer', even when the fault is in the exporter half. rust-imports-zena-composition's web/native lines blame 'component importer' (the Rust partner) for a ref-type/tag refusal that comes from the Zena exporter inside the composition. On a wac refusal, not_composed (verdict.rs:51) also names only the importer, although wac's log mentions socket/plug. The exporter's compile log is deleted either way (compose.sh:~122). This can mislead a person reading the record. Consider naming the composition after both halves (e.g. importer+exporter), or naming the exporter in the reason.
> F3 [low]: Chained compositions and an exporter plugged into two importers fail the build (compose.sh:77, :90). PDD024 neither allows nor forbids either case, so this is an acceptable limitation. The chain and missing-program paths are tested in zena-scenario-build-check (flake.nix:473). The two-importers branch and the importer-did-not-compile branch are untested (only exporter-uncompiled is tested). Compile-before-compose precedence matches the PDD stage table and is tested at wasmtime_run and zena.rs:1644.
> F4 [low, web emphasis]: No test proves that the polyfill runs a composed component to pass.
