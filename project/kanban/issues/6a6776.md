## What to build

The boundary counters (feature `boundary-counters`: `BoundaryCounters { calls,
bytes, boundary_ms, host_ms }`) count per thread. The `wasi:webgpu` spike
(`~/Git/github.com/cdata/wasi-webgpu-test`) read them once per frame. Two gaps
showed:

- **Per store.** A thread with two stores, or a store whose calls interleave
  with another's, mixes their counts. Count per store as well, so that a page
  with two guests can tell them apart.
- **Per host import.** The spike stood in host time for "wgpu time", one lump
  per frame. A breakdown by import (calls, bytes, and host time for each)
  would have named the expensive functions of `wasi:webgpu` directly. Keep it
  cheap enough to leave on in a debug build.

Also record, in the counters' docs, the resolution of `performance.now()` that
the clock depends on in each browser.

## Acceptance criteria
- [x] Each store's counters are its own: two stores on one thread give separate
      counts, on both targets.
- [x] A per-import breakdown gives calls, bytes, and host time for each import,
      and its totals equal the store's counters.
- [x] With the feature off, the counters compile to nothing, as today.
- [x] `lint` passes, and `tests all` is green on both targets with the
      conformance summary unchanged.

## Review notes

- 2026-10-18 (implementer): `Store::boundary_counters` and
  `Store::take_boundary_counters` answer a `StoreBoundaryCounters`:
  `total`, `imports` (keyed by the component's import name and the names
  inside it joined by `#`), and `other`, the store's work outside any
  import's call (the host's calls into exports and their values, host
  resource drops, copies with a host end). `imports` and `other` add up
  to `total`. Counting goes through a thread-local stack of scopes: a
  driver turn and each import call open one, and a host task carries
  its import, so its later polls and the lowering of its result count
  under it. A count goes to the innermost scope, and the running clocks
  settle into it when a scope opens or closes, so an import that calls
  back into a guest that calls another import counts the inner call to
  the inner import alone. A scope adds its counts to the store's sink, a
  lock the store holds, as it closes, so a store that moves threads
  keeps its counts. Without the feature every new type is empty and
  every guard does nothing. The `BoundaryCounters` docs record
  `performance.now()`'s resolution: 100 microseconds or coarser by the
  High Resolution Time spec (5 when cross-origin isolated), exactly that
  in Chrome since 91, and 1 ms in Firefox and Safari as reported in 2020
  (Firefox 20 microseconds when isolated). Sources:
  https://w3c.github.io/hr-time/,
  https://developer.chrome.com/blog/cross-origin-isolated-hr-timers, and
  https://groups.google.com/a/chromium.org/g/blink-dev/c/k6M3HJiqmkE/m/_vNJXzILBAAJ.
  Tests: four in `tests/baseline_boundary_counters.rs` (two stores on
  one thread, the breakdown, an async import's later polls and result)
  and a unit test of nested imports. `lint` and `tests all` green.
- 2026-10-18 (peer review 1): ACCEPT, with three non-blocking findings,
