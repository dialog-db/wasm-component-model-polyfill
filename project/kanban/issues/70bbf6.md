## What to build

Findings from the independent review of 3164da (the Wasmtime backend, landed `26d44497f`) in `rust/wcmp-wasm-core-contract` and `rust/wcmp-wasm-core-wasmtime`:

- The capability-gated contract cases return early and pass when the backend lacks the capability (`boundary.rs:40,71`, `tags.rs:135,174`, `references.rs:87,130,196`), so on a backend without GC or exceptions (Wasmi) 7 of 16 cases check nothing. Where the capability is undeclared, assert the structured failure instead (for example `Module::compile` returns `Err(Compile)` and nothing panics).
- The suspension case tests the core engine's gate (`wcmp-wasm-core` `externs/func.rs:70,129`); the backend's own refusal of a suspending host function (`wasmtime/src/store.rs:124`) is never reached. Add a case that reaches it.
- No case checks that a host-held GC or extern reference survives a collection. Add one that allocates in the guest between making the reference and using it.
- A result type mismatch from a host function surfaces as `Trap(Host(wcmp Error))` (`store.rs:505-508`). Document it, or give it its own error.

## Acceptance criteria
- [ ] On a backend that does not declare a capability, each gated case asserts the structured refusal.
- [ ] A case reaches the backend's refusal of a suspending host function.
- [ ] A case holds a GC or extern reference across a guest collection and uses it after.
- [ ] The host-function result mismatch is documented or has its own error.
- [ ] `tests all` and `lint` pass.

## Review notes

- 2026-09-29: more from the review of 67ea35 (landed `2447fc945`): (a) the memory and trap cases also skip silently where a capability is missing (`memory.rs:142-147,404,438`, `traps.rs:268,302`); `Memory::new` with a shared or 64-bit type is specified as `Unsupported(threads | memory64)`, so assert that. (b) The overlapping shared copy test (`memory.rs:419`) covers only the backward branch; add `to < from` and a copy between two shared memories.
