## What to build

Wasmtime 50 caps the live handles of a store at 100,000 by default. It counts
resources (own and borrow, the host table included), stream and future ends,
error contexts, waitable sets, subtasks, and guest threads. A full store fails
with "cannot allocate another handle: store handle limit exceeded". A drop
gives the budget back. `Store` and `StoreContextMut` get
`max_component_handles` and `set_max_component_handles`.

The polyfill has no cap. A resource insert never fails
(`resource/table.rs:99`).

## Acceptance criteria

- [x] `Store` and `StoreContext` have `max_component_handles` and
      `set_max_component_handles`, with a default of 100,000.
- [x] Every handle insert counts against the cap and can fail with Wasmtime's
      message, and every remove gives the budget back.
- [x] Ports of Wasmtime's `handle_table_limit.rs` tests pass on both targets.

## Review notes

- 2026-10-20: Wasmtime 50 creates host tasks lazily (`58c12bcbd`). The
  citation in `store_context.rs` (`:1962` at `v49.0.0-rc.1`) moves with this
  card, once the cap's timing is checked against Wasmtime 50.
- 2026-10-20: The cap is in `HandleTables`. It counts every live entry of
  every handle table, the host's tables included, and every index of every
  thread table, as Wasmtime 50 counts them. `tests/baseline_handle_limit.rs`
  ports the three Wasmtime tests and checks the default.
- 2026-10-20: The implicit thread of a call counts but is never refused,
  because `TaskTables::start_task` cannot fail. Wasmtime 50 refuses it
  (`add_guest_thread_to_instance_table` in `concurrent.rs`).
  `notes/differences-from-wasmtime.md` records this.
- 2026-10-20: The citation that the earlier note names now cites Wasmtime
  50. The owner chose to follow Wasmtime 50's lazy host task. The subtask of
  a host call does not count until the call's first poll leaves it pending.
  A full store then traps the call after that poll. The host task entry no
  longer counts on its own, so one pending call is one record, as one
  `HostTask` is in Wasmtime. Wasmtime 50 also makes the record when a borrow
  is lent to the host call or the host calls back into a guest. The
  polyfill does not count the record at those points.
