## What to build
From the 2026-10-13 review of 1bbe43. A host-written type that holds an error context is not checked before the call.

`ComponentValue::check_store` has a default that returns `Ok(())`. A host's own `ComponentValue` type, such as a record with an `ErrorContext` field, gets that default, because `StoreId` is not public. Its error context from another store fails only when it lowers inside the call, which poisons the store. PDD023 says a value from another store fails with the wrong-store cause and does not poison. The docs state the gap (`rust/wcmp/src/concurrency/error_context.rs`, `rust/wcmp/src/linker/component_value.rs`). The repository has no derive macro, so every typed record or variant that holds an error context is written by the host.

Related, out of this card's scope unless the owner widens it: streams, futures and resource handles from another store are still not detected (`stream_any.rs`), although PDD023 states the rule for every value from another store.

Owner decision, one of:
- make `StoreId` public (or give `ErrorContext` a public store accessor) so a host type can override `check_store`;
- add a public "visit the error contexts this value holds" hook that the pre-check calls;
- accept the gap as documented, and cancel this card.

## Acceptance criteria
- [ ] The owner has chosen one option.
- [ ] If a hook or public id is added: a host-written record holding another store's error context is refused before the call, and the store stays usable; a test on both targets shows it.
- [ ] `lint` passes and `tests all` is green on both targets.


## Owner decisions

- 2026-10-13: make `StoreId` public as an opaque type with no public constructor, so a host type overrides `check_store` by delegating to its fields, as the built-in overrides do.
