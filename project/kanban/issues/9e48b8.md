## What to build

The shelf editor's Format button must replace the editor's text, whatever had
the focus before the click.

Reported by the owner on 2026-10-13:
- On a file with no edits, Format put the file's formatted text into the
  TODO input instead.
- On an edited file, Format inserted the formatted text at the caret, and the
  text before the caret stayed in place, which usually broke the source.

Cause: `editor::replace` (`rust/wcmp-demo/src/editor.rs`) set the text area's
selection and then ran the browser's `insertText` command, which edits wherever
the document's selection is. A real click on the button leaves that selection
in the field focused before the click. That was the application's input, which
has `autofocus`, or the caret of the editor itself: a selection set while the
text area is not focused does not move the document's selection. The demo test
clicked from script (`element.click()`), which moves no focus, so it passed.

## Acceptance criteria

- [x] Format replaces the editor's whole text with the formatted text, with
      the focus in another field or with the caret in the editor.
- [x] A demo test clicks Format through Chrome's input events, as a mouse
      does, in both cases, and fails without the fix.
- [x] `tests demo` and `lint` pass.

## Implementation notes

- 2026-10-13 (`fix(demo): Format into the editor wherever the focus was`):
  `replace` focuses the text area before it sets the selection. `insert` runs
  `insertText` only while the text area has the focus, and otherwise sets the
  text directly, without undo. The new test
  `it_formats_the_source_on_a_click_wherever_the_focus_was` failed before the
  fix (the format never reached the editor) and passes with it, as do the
  existing format and completion tests, which go through `replace` too.
- Gate: `tests demo` 69/69 and `lint` green on the fix.
