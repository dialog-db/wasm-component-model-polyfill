## What to build

PDD027, "Flags". The `flags!` macro with Wasmtime's syntax and generated API (`crates/component-macro/src/component.rs:1120-1517` at `v49.0.0-rc.1`), re-exported as `wcmp::flags!`.

```rust
flags! {
    Permissions {
        #[component(name = "read")]
        const READ;
        #[component(name = "write")]
        const WRITE;
    }
}
```

It emits one constant for each flag, `empty`, `all`, `contains`, `intersects`, `as_array`, the operators `|`, `&`, `^`, `!` with their assigning forms, `Debug`, `Default`, `Clone`, `Copy`, `PartialEq`, `Eq` (padding bits masked), and `ComponentType`, `Lift`, and `Lower` with a type check of count then names in order. It takes no crate path, as in Wasmtime.

## Acceptance criteria
- [x] A flags type crosses through `flags!`. Flags types with 1, 8, 9, and 32 flags cross in both directions on both targets. A 33-flag type has Wasmtime's layout, checked without a guest, because the spec caps a flags type at 32 flags.
- [x] The test exercises each constant, `empty`, `all`, `contains`, `intersects`, and each operator.
- [x] A flags type whose names or count differ from the component's fails the type check with a path to the flags type.
- [x] `lint` passes, and `tests all` is green on both targets with the conformance summary unchanged.

## Notes

- 2026-10-16: `flags!` is `rust/wcmp-macros/src/flags.rs`, with Wasmtime's API and storage in `u8`, `u16`, or a run of `u32` words. Flags of 1, 8, 9, and 32 cross through the fixture. The Component Model limits a flags type to 32 flags, and the validator refuses a 33-flag type, so no component can declare one. The 33-flag type is therefore checked for layout only (two `u32` words, as Wasmtime lays it out), following card a70072. The first box stays open for the owner: should it say "up to 32 flags"?
