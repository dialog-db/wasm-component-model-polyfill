## What to build
PDD026 needs a Zena change that lets a host pass its own WIT reader to the WIT module synthesis. Without it, Zena's compiler cannot build as a component that serves its sources from memory. The change is commit `1bbe472f4c34d3faf12c74f9876afcfe541c4ac3` on branch `component-target-compiler` of the fork https://github.com/cdata/zena, and the owner offers it upstream as a pull request to https://github.com/elematic/zena.

Until Zena accepts it, the `zena` flake input names the fork. A fork drifts from Zena and weakens the ground truth of the Zena compatibility suite, so the input must move back to Zena's own repository as soon as a Zena revision holds the change.

- Watch the upstream pull request. When it merges, point the `zena` input at `github:elematic/zena` and run `nix flake update zena`.
- Regenerate the Zena compatibility record for the new pin (`tests zena regenerate`) and commit the lock and the record together.
- If Zena accepts a different form of the change, adapt the compiler component's entry module to it.

## Acceptance criteria
- [ ] The `zena` flake input names `elematic/zena`, and the lock records a Zena revision that holds the WIT reader change.
- [ ] No flake input or lock entry names the fork.
- [ ] The compiler component builds from the new pin and imports no `wasi:filesystem` interface.
- [ ] The Zena compatibility record names the new pin, and `tests zena` passes against it.
- [ ] `tests all` and `lint` pass.
