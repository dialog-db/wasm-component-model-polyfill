## What to build

Step 1 of the migration (build beside). Finish the Wasmtime backend with memory access and trap kinds, and add both to the backend contract tests.

- **Memory.** Every memory method of the trait. An offset is 64 bits, so memory64 uses the same methods. Each method checks its range against the memory size; a range outside is a structured error, never a panic or abort. `with_bytes` lends the memory's own bytes on an unshared memory (no copy). `Memory::copy` moves bytes between two guest memories of one store with no host buffer.
- **Shared memory.** Never lend a shared memory as a slice. `with_bytes` on a shared memory copies with atomic reads and lends the copy. `read` and `write` use atomic access. This follows Wasmtime's own rule for `SharedMemory::data`.
- **Trap kinds.** Map each Wasmtime trap to `TrapKind`, with Wasmtime's message. A host error is `Host(error)`. An exception that reaches the host uncaught (`ThrownException`) is `UncaughtException`, carrying the `exnref` as an opaque reference, with the message `thrown Wasm exception`.
- **Trap fixture.** A test fixture that raises each core `TrapKind` that a backend's capabilities permit. Later backends run the same fixture and must report the same kind and message.

## Acceptance criteria
- [ ] `with_bytes` on an unshared memory returns the bytes of the range and copies nothing. On a shared memory it returns a copy.
- [ ] A range outside the memory is a structured error for every memory method.
- [ ] `Memory::copy` copies between two memories of one store.
- [ ] The trap fixture raises each core `TrapKind` the backend's capabilities permit, and the backend reports each with Wasmtime's message.
- [ ] A guest throws an exception that nothing catches. The call fails with `UncaughtException` and the message `thrown Wasm exception`.
- [ ] The memory and trap tests are part of the shared contract tests.
- [ ] `lint` and `tests native debug` pass.
