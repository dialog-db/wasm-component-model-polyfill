## What to build
`wasmtime/resources.wast` asserts, from inside the guest, which index a `resource.new` returns after earlier handles were dropped (lines 81, 592, 600 execute `unreachable` when the index differs). The polyfill's table reuses freed indices from a free list; Wasmtime's allocation order differs in these cases. Read Wasmtime's `ResourceTables` allocation rules (a per-table free list with the same LIFO order, but with the first entries reserved and per-instance tables) and make the polyfill's `HandleTable` allocate identically, then re-baseline.

## Acceptance criteria
- [ ] `wasmtime/resources.wast:81`, `:592`, and `:600` pass and leave the expectation list.
- [ ] `it_reuses_freed_handle_indices_after_drop` still passes, updated if the order changed.


## Review notes

Implementor (2026-09-15): the table now reserves index 0 as the canonical
ABI's reference table and Wasmtime do; the free list was already LIFO. That
cleared 20 directives, including all of `cm/linking/unit.wast` and the
`borrows.wast` and `handle-table.wast` lines. Of the three lines the card
names, 81 and 600 pass; 592 is not a defect: it belongs to the next component
in the file, which imports `host` and never instantiates (the harness
registers no host), and the harness used to run the directive against the
previous, still-current instance. A component directive that fails now clears
the current instance, so such lines report as cascades. That change moved 14
accidental passes to honest cascades (defects fell from 26 to 3).
