## What to build
`wasmtime/resources.wast` asserts, from inside the guest, which index a `resource.new` returns after earlier handles were dropped (lines 81, 592, 600 execute `unreachable` when the index differs). The polyfill's table reuses freed indices from a free list; Wasmtime's allocation order differs in these cases. Read Wasmtime's `ResourceTables` allocation rules (a per-table free list with the same LIFO order, but with the first entries reserved and per-instance tables) and make the polyfill's `HandleTable` allocate identically, then re-baseline.

## Acceptance criteria
- [ ] `wasmtime/resources.wast:81`, `:592`, and `:600` pass and leave the expectation list.
- [ ] `it_reuses_freed_handle_indices_after_drop` still passes, updated if the order changed.
