## What to build
A guest trap from `Func::call` (and other guest-call failures) displays as "instantiation error: the runtime substrate failed to instantiate the component". `backend.rs:28` (`substrate_failure`, at `a0983522f`) wraps every guest-call failure from the substrate as `Error::Instantiation(InstantiationError::SubstrateFailure)`, whose Display names instantiation. The root cause is kept in the source chain, but the top-level text misleads a host that prints the error. The smoke card fed20f's trap story shows the root cause instead to avoid it.

Give a failure of a guest call its own structured cause and message (for example a trap cause that names the trap), and keep `SubstrateFailure` for instantiation. Keep the source chain.

## Acceptance criteria
- [x] A guest trap from `Func::call` displays a message that names the trap, not instantiation, on both targets.
- [x] An instantiation failure still displays as an instantiation error.
