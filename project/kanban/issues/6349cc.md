## What to build
The review of card `4a29c4` accepted `WakeSlot<T>` (`src/concurrency/wake_slot.rs`) and left three non-blocking findings. First, a post-resolve failure of an asynchronous callback export is not routed to the caller's failure slot: `CallbackTask::exit` returns `Err` from the item, which fails the whole `run_concurrent` entry (`src/store/store_context.rs:622-626`) instead of waking the one concurrent call that owes the failure, as the synchronous `run_task` item now does (`src/instance/func.rs:484`). Second, `WakeSlot` drops the value on a poisoned lock instead of returning a structured `Error` as the rest of the crate does (compare `src/executor/start_call.rs:528-534`), which turns a poisoned slot into a permanent park; the code it replaced did the same. Third, failure-wins between the result channel and the failure slot holds only because both writes land inside one item polled from `poll_lent` on the driver thread (`store_context.rs:1286-1292`); Wasmtime carries result and error through one oneshot (`crates/wasmtime/src/runtime/component/concurrent.rs:6248, 6290-6301`). Decide whether the two slots become one channel. Add the tests the review found missing: a call whose start fails before any resolve under the waker-gated combinator (both the `start_async_task` and the `run_task` lowering-failure writers), a resolving call beside a never-resolving one in the same combinator, `TypedFunc::call_concurrent` directly, and `WakeSlot`'s keeps-the-later-value rule.

## Acceptance criteria
- [ ] An asynchronous callback export that fails after its task resolved wakes the concurrent call that owes the failure with that failure; the other calls in the same `run_concurrent` keep running; a test proves it on both targets.
- [ ] A poisoned `WakeSlot` lock surfaces as a structured `Error` to the caller instead of a permanent park, proved by a unit test.
- [ ] Either the result and failure slots are one channel, or the two-slot ordering rule is stated in the docs of `WakeSlot` and its two callers with the reason it holds.
- [ ] The four missing tests exist and each fails on the code before its change.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
