## What to build

PDD026, "The Elements of the Demo", "Data Down, Events Up", and "The Two Contexts: Boot". The TodoMVC application.

- **Elements**, as Zena source defined with `define_element`:
  - `<todo-app>` owns the list. It is the only element that calls the API. It passes data to its children as attributes and handles their `CustomEvent`s. Its `filter` attribute holds the filter.
  - `<todo-input>`: the field for a new todo and the toggle-all control.
  - `<todo-item>`: one todo, with the checkbox, the title, the delete button, and in-place editing.
  - `<todo-footer>`: the count of active todos, the filter links, and "Clear completed".
- **TodoMVC edit rules.** An edit to an empty title sends a `DELETE`. Enter and blur commit an edit, and Escape cancels it.
- **Filter.** The page sets `filter` on `<todo-app>` from the URL hash at start and on each `hashchange`.
- **Boot.** In PDD026's order: register the service worker; fetch the compiler and the source bundle and instantiate the compiler; compile and define each element, with a skeleton (a gray placeholder in the element's shape) until its tag is defined; wait until the service worker controls the page; then add `<todo-app>` to the document. Edits from IndexedDB and the boot fallback come with the drawer cards.

## Acceptance criteria
- [ ] Every TodoMVC behavior works. The demo lane covers each behavior of the TodoMVC specification through the shadow roots:
  - [ ] Add, toggle, toggle all, and delete.
  - [ ] Edit by double-click, with Enter, with blur, and with Escape.
  - [ ] Delete by an edit to an empty title.
  - [ ] The count of active items.
  - [ ] The three filters by URL hash.
  - [ ] "Clear completed", and when it shows.
  - [ ] Persistence after a reload.
- [ ] The root element calls through `wasi:http/client`. A test adds a todo through the user interface and watches the network. Each API request has a response with the `x-demo-route` header, and no API request reaches the network.
- [ ] The todo list persists. A test adds todos, stops the service worker, and reloads the page. The list is the same.
- [ ] Authors never write WIT. The source of every element and route of the demo contains no WIT and no `wasi:` import.
- [ ] Each element shows a skeleton until its tag is defined.
- [ ] `tests all` and `lint` pass.
