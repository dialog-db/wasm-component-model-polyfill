## What to build

Findings from the independent review of edf2c7 (landed `16b227b7a`). The soundness fix holds, but its refusal reaches the host as a panic on most paths.

- **The panic reaches further than `data`/`data_mut`.** In the refused state (a host function of a forgotten flight reaching its own store past its caller), `wcmp-wasm-core` `checks::same_store` calls `store.data().id()` (`checks.rs:16`) before almost every public operation (`Func::call`/`call_resumable`, memory, global, table and tag operations, `Instance` import checks), and `Func::new`, `Memory::new`, `Global::new` and `Table::new` call `store.engine()`, as does `Debug for Store`. So most host-facing calls panic there, which on wasm32 with panic=abort traps the Rust module and leaves the hosting count stuck. Only `ExternRef::new` and a few handle-free operations return `Error::Backend`. PDD025 says "never a panic". Move the store identity check off `data()` (for example a `BackendStore::id`, or an engine the `Owner` caches outside the cell), so these paths return `Error::Backend`.
- **Documentation.** `Owner` is private, so its `# Panics` docs never render, and `wcmp_wasm_core::Store::data`/`data_mut`/`engine` have no Panics section. Document the remaining panic where a host sees it.
- **Missing tests.** A host function past its caller using a handle-taking API such as `Func::call` or `Memory::read`; a captured `Rc<RefCell<Store>>` variant; a reach from a lease nested inside a flight's host call.
- **Minor.** The HOSTING message (`calls.rs:205`) reads as advice and is unclear; `Flight::is_suspended` is dead code.

## Acceptance criteria
- [ ] In the refused state, every fallible public operation returns `Error::Backend`; only `data`/`data_mut` panic, and their docs say so.
- [ ] The missing tests exist and run in the web lanes.
- [ ] `tests all` and `lint` pass.
