## What to build
`lift_from_flat_slots` (`src/abi/flatten.rs:222-226`) takes a list's pointer and length from the flat slots and calls `Vec::with_capacity(len)` before any bounds check; the memory path (`src/abi/lift.rs:35-44`) does the `checked_mul` and `in_bounds` check first. The flat path is reached from every host import whose parameters fit in sixteen flat slots (`src/executor/trampoline.rs:554`) and from `task.return` with flat results. A guest that passes `len = 0xFFFF_FFFF` for a `list<u8>` parameter asks the allocator for about 160 GiB natively, which aborts the process, and overflows the capacity computation on wasm32, which panics the page; `ptr + i * element_size` at line 227 can also overflow `usize` on wasm32. The reference's `load_list_from_range` (`definitions.py:1408-1411`) traps on the byte length, then on alignment, then on bounds, before loading anything; Wasmtime bounds-checks, then charges fuel for `len * size_of::<Val>()`, then allocates.

Three sites also skip the alignment trap the reference and Wasmtime raise: the list pointer at `lift.rs:28-49` and `flatten.rs:222` (Wasmtime: `list pointer is not aligned`), the return pointer of a spilled result at `src/instance/func.rs:773-790` (`return pointer not aligned`, `pointer out of bounds of memory`), and the spilled argument tuple at `trampoline.rs:1001-1019` (`pointer not aligned`, `pointer out of bounds`), which also checks no bounds for the tuple as a whole. Strings already check alignment at `lift.rs:285-292`. Run the same `checked_mul` and `in_bounds` gate on the flat path before the allocation, and add one alignment check with Wasmtime's wording at the three sites. Take the wording from `crates/wasmtime/src/runtime/component/values.rs` and `func/typed.rs` in the clone at the corpus commit `cb091c33cece`, which is the tie-break the corpus directives were written against, and name that commit in the test that pins each message; the crate pinned in the manifest is a different revision and is not the source for a message that lives outside `wasmtime_environ::Trap`.

## Acceptance criteria
- [ ] A host import called with a `list<u8>` parameter of length `0xFFFF_FFFF` fails with the out-of-bounds ABI cause on both targets, and a test proves no allocation happens before the check (a counting allocator, or a length that would overflow the capacity on wasm32).
- [ ] A misaligned list pointer, a misaligned return pointer, and a misaligned spilled argument tuple each trap with Wasmtime's wording, proved by unit tests on both targets; the spilled tuple is bounds-checked as a whole.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
