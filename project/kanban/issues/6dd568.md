## What to build

Non-blocking findings from the independent reviews of a25aa9 (strict CSP, landed `b963cf028`) and 2976a0 (vendored layer retired, landed `3317a8da6`):

- **js-sys enables `unsafe-eval`.** `js-sys`'s default features enable `unsafe-eval` on wasm32 (`cargo tree -e features -i js-sys`). The source-level `web-backend-no-eval` check does not cover it. Turn it off where the polyfill and the browser backend depend on `js-sys`, or show that nothing reachable uses it, and add a check.
- **CSP coverage.** The CSP tests do not exercise JSPI or async host functions, streams, or the JS bulk-copy fallback used when `multi_memory` is missing (Safari's path). Add an async host function under the policy, and cover the fallback path if the test page can force it.
- **No-eval denylist.** Extend it with `\btype +Function\b` and `::constructor\b`; the flake comment claims the plain ways are caught, and the extern-type form is plain.
- **Old crates.** The seam and public-API checks now look only for `wcmp_wasm_core`. Add a flake check that bans `[patch]` and the upstream runtime-layer crate names in `Cargo.toml` and `Cargo.lock`, so they cannot come back.
- **Docs.** The CSP test file's module doc (lines 19-23) says the test binary loads from the page's own origin; under wbg-pool it loads from `assets.localhost` before the policy. Fix the reason. Unwrapped comment lines at `boot.js:17` and `prepared_call.rs:13`.
- **Owner call.** Whether the README Acknowledgements should link the upstream repository, whose URL names the crate (2976a0's criterion 3 forbids the name).
