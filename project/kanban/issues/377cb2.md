## What to build
Replace the `CallScope` stack in `HandleTables` (`src/resource/call_scope.rs` and `tables.rs`) with the store's tables of task, subtask, and thread records and a stack of current scopes, where a scope is a task record or a subtask record. A task record holds the function type of the export and the canon options of its lift, the instance the export belongs to, the state (`initial`, `started`, `pending-cancel`, `cancel-delivered`, `resolved`), the borrow count the reference names `num_borrows`, the implicit thread and the list of the task's threads, and the result or the caller's channel that receives it. A subtask record holds the state (`starting`, `started`, `returned`, `cancelled-before-started`, `cancelled-before-returned`, the last three resolved), the `lenders` list whose counts are decremented when the resolution is delivered, the pending event, the waitable set it joined, the synchronous-waiter flag, and whether cancellation was requested. A thread record holds its task, the readiness condition it waits on, and the two context slots; move the slots from `ContextSlots` in `src/executor/intrinsics.rs`, one pair per instantiation today, to one pair per thread. Push and pop the stack at every crossing: `Func::call` in `src/instance/func.rs` pushes the export's task; `invoke_trampoline` in `src/executor/trampoline.rs` pushes the subtask of the guest's host call and keeps it on the stack while the host side runs; the enter intrinsic pushes the callee's task and the exit intrinsic pops it. Route every borrow operation through the current scope: a borrow lowered into a guest increments the current task's borrow count and the entry records that task; a drop decrements the count of the task the entry names; a borrow lifted from an owned handle adds the owned handle to the current subtask's lender list; the return of a synchronous export traps when the task's borrow count is not zero, with the message the exit intrinsic uses today. Add an instance record per component instance with the `backpressure` counter, the count of tasks waiting to enter, the exclusive thread, the `may_leave` flag, and a may-not-suspend flag; keep the flags global the adapters import as they see it; have the enter intrinsic set may-not-suspend on the callee instance for the synchronous call and the exit intrinsic restore it, as Wasmtime does. A synchronous call is a task with one thread, so the synchronous baseline is the case of one task per instance at a time.

## Acceptance criteria
- [ ] A host call into a synchronous export pushes a task on the current-scope stack and pops it on return; a guest call into a synchronous host function pushes a subtask; a synchronous call between two composed components pushes the callee's task. Each is proved by a test.
- [ ] Every borrow test of the synchronous baseline passes unchanged: `borrows.wast`, `handle-table.wast`, and `multiple-resources.wast` of the Component Model corpus and `resources.wast` of the Wasmtime corpus, on both targets.
- [ ] `context.get` and `context.set` read and write the current thread's slots, and the adapters' save and restore around a callee behaves as before.
- [ ] The enter intrinsic sets the callee instance's may-not-suspend flag and the exit intrinsic restores it, proved by a test.
- [ ] `CallScope` is gone, and no other test changes.
- [ ] `tests all` passes on both targets, and any async directive that starts passing has its line removed from the expected-failure list.
