## What to build
`wasmtime/async/exceptions.wast` throws an exception in the callee of each of the three asynchronous combinations (a synchronous lower of a callback export, the same with a `thread.yield` before the throw, and an asynchronous lower), in the callee's first phase and in its callback or after its yield. Each must reach the host as the trap the synchronous baseline gives the same throw: an exception the callee does not catch unwinds through the start item in the switch slot, or through the callback item a later turn runs, to the trampoline or to the driver, and fails the caller's call or the driver's turn with the baseline's message. Check how the runtime layer surfaces an uncaught exception on each target, make the start item and the callback item carry it out unchanged, and make sure the callee's task and subtask are abandoned on that path as they are on a trap (`abandon_export_task`, `abandon_subtask`), releasing the exclusive thread and the lent handles. `exceptions.wast` then passes whole.

## Acceptance criteria
- [ ] `exceptions.wast` passes whole on both targets and its lines leave the list.
- [ ] A repository test proves that an exception thrown after the callee yielded fails the driver whose turn ran the callback with the baseline's message and leaves the exclusive thread released and the subtask abandoned.
- [ ] `lint` passes and `tests all` is green on both targets.
