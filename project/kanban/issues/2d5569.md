## What to build
The public API has no way to dispose of anything on purpose. Today: no type implements `Drop` beyond Rust's default; a `ResourceHandle` the host minted with `Store::resource_new` and never handed to the guest cannot be released, so its destructor never runs; dropping a `Store` frees the substrate's memories but runs no host destructor and no in-binary destructor for handles still live in the handle tables; an `Instance` cannot be released independently of its store (the substrate keeps its memories until the store drops). Mirror Wasmtime's shape: an explicit `resource_drop`-style entry point on a host-held handle that runs the destructor and frees the table slot; a documented answer for what a dropped `Store` does with live handles (Wasmtime leaks them; decide whether the polyfill runs host destructors on store drop or documents the leak); and a documented answer for whether an `Instance` can be released before its store, given that the runtime layer's backends keep instance memory for the store's lifetime. Write the design into a PDD before the code. The smoke test (`rust/wcmp-smoke`) gains a step that mints a handle, disposes of it from the host, and observes the destructor; then drops an instance and a store and observes what the design promises.

## Acceptance criteria
- [ ] A PDD records the disposal model: host-side handle release, store drop semantics for live handles, and instance lifetime relative to the store.
- [ ] A host-held `ResourceHandle` can be released through the public API; its destructor runs exactly once and its table slot is reusable.
- [ ] Dropping a `Store` behaves as the PDD states, and a test observes it on both targets.
- [ ] `smoke native` and `smoke web` include a disposal step that passes.
