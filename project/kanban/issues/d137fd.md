## What to build
From the 2026-10-13 review of 1bbe43. Smaller issues with how the error-context wrong-store failure is reported and what it costs.

- **Position lost.** Inside a running lower, `lower_error_context` (`rust/wcmp/src/abi/lower.rs`) returns a bare `InstantiationError::WrongStore`. Every other lower failure carries its `position` and `ty`. When a host function returns another store's error context nested in a record, or a host stream writes one, the trap does not say which value was wrong. Wrap it as an `AbiError` with a wrong-store cause, or add the position to the message.
- **Error type name.** The refusal is `InstantiationError::WrongStore`, for a value check made during a call. Decide whether a call-time value check should use another variant or a wrapper.
- **Extra walk.** When any parameter holds an error context, `CallValues::check_store` (`rust/wcmp/src/instance/call_values.rs`) walks every argument. For `f(big: list<u8>, e: error-context)` that is one extra pass over the whole byte list. Walk only the parameters whose type holds an error context.

## Acceptance criteria
- [x] A wrong-store failure inside a running lower names the position and type of the value, and a test asserts it.
- [x] The owner has decided on the error variant, and the code follows it.
- [x] An untyped call walks only the parameters whose type can hold an error context, and a test or benchmark shows a large `list<u8>` beside an error context is not walked.
- [x] `lint` passes and `tests all` is green on both targets.


## Owner decisions

- 2026-10-13: split by site. The pre-check keeps `InstantiationError::WrongStore`, as `Func::call` on another store does. A failure inside a running lower becomes an `AbiError` with a new `AbiCause::WrongStore`, which carries the position and type.

## Implementation notes

- 2026-10-13 (`fix(abi): Name the value a wrong-store lower fails on, and
  walk less`): new `AbiCause::WrongStore`. `lower_error_context` returns it
  as an `AbiError` with its position and type, for example `at result (type
  ErrorContext): the value holds an error context lifted in a different
  store`. The relay and host-stream tests assert that text. The pre-check
  keeps `InstantiationError::WrongStore`. `Signature` keeps the indices of
  the parameters whose type holds an error context
  (`error_context_params`), and the untyped pre-check walks only those.
  `it_walks_only_the_arguments_whose_type_holds_an_error_context` passes a
  `list<u8>`-typed argument that holds a foreign error context, which is
  not walked. Mutation: walking every argument fails it.
