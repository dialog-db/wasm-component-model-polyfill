## What to build
Open two issues against `DouglasDwyer/wasm_runtime_layer` for the `js_wasm_runtime_layer` backend: (1) a host function's `Err(_)` returns `undefined` to the guest instead of trapping, with the reproduction from `do_not_track/js-wasm-runtime-layer-host-err-swallow.md`; (2) the module parser hits `todo!()` for a core module that imports a memory, a global, or a tag. Link the issues from the patched backend's in-tree note. This card is the owner's, because it needs their GitHub account.

A third item joined the filing on 2026-09-21, corrected 2026-09-22 after card `f3f685` measured it: the backend implements a host function of more than eight parameters through a shim a page must be allowed to build, which a content-security policy without `unsafe-eval` refuses. The arity is reached when a call's lower or its lift is asynchronous; a synchronous lower into a synchronous lift uses the enter and exit intrinsics and never builds such a function (`src/executor/prepare_call.rs`, and Wasmtime's `crates/environ/src/fact/trampoline.rs` on `call_prepare`: "This is not used for a sync->sync function call"). Card `f3f685` carries the polyfill's own fix, which replaces `new Function` with a `wasm_bindgen(inline_js)` snippet, so do not describe the current mechanism as `new Function`; the upstream ask is closures of arbitrary arity.
