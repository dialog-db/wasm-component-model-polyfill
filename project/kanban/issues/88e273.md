## What to build
Prove, and fix where a proof fails, that a copy or a cancel without the `async` option blocks the thread under the four rules PDD020 states for the nested turn, and that nothing in those rules changes. An idle store fails the built-in with the deadlock cause: a synchronous read on a stream whose writer never writes ends this way, and `future-read.wast` expects the deadlock message from a callback export that reads a future no one writes. A pending host end counts as a pending host task, so a synchronous read against a host producer that stays pending fails with the stack-switch cause. A sync-typed call in progress turns both failures into the cannot-block cause, which `future-read.wast` expects from a synchronous export that reads a future synchronously. Ready work in other tasks runs inside the nested turn and can complete the copy: a callback task of another instance that writes the stream and then parks, returning to its event loop with no frame on the stack, releases the reader. A synchronous copy or cancel on an end inside a waitable set fails with the waitable cause, which `sync-and-async-waitable.wast` and the first four components of `cancel-sync-and-waitable.wast` expect. The one shape the nested turn cannot serve, a copy that only the caller below it on the stack can release, stays deferred with the stack-switch reason: `sync-streams.wast` in both corpora keeps its lines, and this card confirms the reason from a live run.

## Acceptance criteria
- [ ] `future-read.wast` passes whole: the synchronous read from the synchronous lift fails with the cannot-block message, and from the callback lift with the deadlock message.
- [ ] `sync-and-async-waitable.wast` and the directives of the first four components of `cancel-sync-and-waitable.wast` pass, proving the waitable cause.
- [ ] A synchronous read against a pending host producer fails with the stack-switch cause, proved by a repository test.
- [ ] A synchronous read completes when a callback task of another instance writes inside the nested turn, proved by a repository test.
- [ ] `sync-streams.wast` in both corpora stays deferred and each of its lines carries the stack-switch reason from a live run.
- [ ] `lint` passes and `tests all` is green on both targets, any async directive that starts passing has its line removed from the expected-failure list, and every line whose reason this card changes is refreshed from a live run.
