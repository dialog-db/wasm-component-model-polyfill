## What to build
From the 2026-10-13 review of a70072. The rich fixture's float and `s64` values do not reach the edges.

- The float values are 1.5, 10, -0.25, -1e300, 0 and 0.5 (`rust/wcmp/tests/corpus/fixtures/rich/assertions.wast`). There is no `-0.0` and no infinity, although the comment says "Each type at its edge". The runner compares floats bit for bit (`rust/wcmp/tests/conformance.rs`), so `-0.0` and `inf` would catch a lost sign.
- Every `s64` value (`i64::MIN`, 5, -1, and the results) is exact in an `f64`, so nothing checks an `s64` past 2^53. Add one such as `-9007199254740993`.

Owner decision: NaN. The spec makes every lifted NaN canonical (`design/mvp/canonical-abi/definitions.py` 1319-1322, at component-model `e5ee0af`). Wasmtime does not. A NaN directive forces a choice between the spec and Wasmtime. The browser's NaN fallback paths are a separate matter (card 841af1).

Also for the owner, on a70072 itself: criterion 3 names "flags wider than thirty-two bits", which the spec does not allow (`design/mvp/Binary.md:203`, `(if 0 < |l*| <= 32)`). Strike or reword it.

## Acceptance criteria
- [ ] The rich fixture carries `-0.0` and an infinity in both `f32` and `f64`, and an `s64` that is not exact in an `f64`, each checked by value.
- [ ] The owner has decided on NaN; if a NaN case is added, its expectation follows that decision.
- [ ] The fixtures rebuild byte for byte, the corpus totals move only by directives this card adds, and `lint` and `tests all` are green on both targets.


## Owner decisions

- 2026-10-13: NaN follows the spec. Lift makes every NaN canonical (`definitions.py:1319-1335`, `:1900` at component-model `e5ee0af`) on both targets, and the rich fixture gains a NaN case that expects the canonical bits.
- 2026-10-13: a70072 criterion 3 is reworded to "flags up to thirty-two bits" (`design/mvp/Binary.md:203`).
