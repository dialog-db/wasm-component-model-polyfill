## What to build

PDD026, "Routes: The Routes of the Demo". The two routes, as Zena source, defined with `define_route`.

- `/api/todos`: `GET` with `?filter=` (`all`, `active`, `completed`) returns 200 with `{"todos": [todo], "counts": {"active": n, "completed": n}}`. `POST` with `{"title": string}` returns 201 and the new todo, or 422 for an empty title. `PATCH` with `{"completed": bool}` sets every todo and returns 204. `DELETE` removes every completed todo and returns 204.
- `/api/todos/:id`: `PATCH` with `{"title"?: string, "completed"?: bool}` returns 200 and the todo, or 404, or 422. `DELETE` returns 204, or 404.
- A todo is `{"id": string, "title": string, "completed": bool}`. Any other method gets 405.
- Each route stays thin: it turns HTTP into calls on the todo model and back.

## Acceptance criteria
- [ ] A route answers through `wasi:http`. A test sends each request in the two route tables from the page through `fetch`. Each response has the status and the body that the table gives.
- [ ] A method that a route does not accept returns 405.
- [ ] The todo model enforces its rules through the routes. A `POST` with an empty title fails with 422. A `POST` with a title with spaces at both ends stores the trimmed title.
- [ ] The route sources contain no WIT and no `wasi:` import.
- [ ] `tests all` and `lint` pass.
