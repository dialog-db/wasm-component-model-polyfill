## What to build
The review of card `77d9f0` accepted the port-message wake and left findings that need one card. First, the ordering rule the module doc states at `src/concurrency/yield_wake.rs:26-29` — that timers already queued run before the guest's next item — is now weaker than the code guarantees. A port message sits in the posted-message task source while a timeout sits in the timer task source, and the HTML specification leaves the choice between task queues to the implementation; Chrome floors a non-nested `setTimeout(0)` near one millisecond, so the existing test at `src/concurrency/driver.rs:411-456` passes only because more than a millisecond of work happens between the queued timeout and the wake. Either state the rule as what the code guarantees, or restore the guarantee, and add a test that queues the timeout immediately before the yield with no work between them. Second, a hang path: `post_message` answers true as soon as `postMessage` returns (`yield_wake.rs:144`), with no watchdog, so a global whose channel constructs and whose post succeeds but never delivers leaves `landed` false for ever and the driver parks, where the old timeout would have fired; a delivery failure never reaches the fallback, and on the path where `postMessage` throws, the already-installed handler and its channel leak. Third, the channel is built per yield rather than per store (`:113-119`), so a spinning guest allocates two `MessagePort`s per yield on the hottest browser path; a per-store port needs a pending-wake queue and store-lifetime teardown, so measure it with the benchmark suite before deciding. Fourth, nothing proves the wake is a macrotask rather than a microtask — an implementation that used `queueMicrotask` would pass both new tests — and the neither-mechanism branch (`:88-92`), the channel-without-ports branch and the never-delivered case have no test.

## Acceptance criteria
- [ ] The module doc states the ordering the code guarantees, and a test queues a timeout immediately before a yield with no intervening work and pins the result.
- [ ] A wake that is posted but never delivered still wakes the driver, or the design states the limit; the `postMessage`-throws path leaks no handler or channel.
- [ ] A test proves the wake crosses a macrotask boundary and not a microtask.
- [ ] The neither-mechanism and channel-without-ports branches have tests.
- [ ] A yield benchmark records the per-yield cost of the channel, and the per-store port is taken or refused on that number.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
