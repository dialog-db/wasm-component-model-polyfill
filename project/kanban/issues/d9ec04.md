## What to build
The committed record of Zena stages, and the gate that fails a run when a stage moves.

- **The record** is one committed text file. A header names the pin (`# zena <full revision>`). Comments explain the columns and the stages. Each other line holds one scenario, one subject (`wasmtime`, `web`, or `native`), its stage, and the error text in quotes. Every subject has its own line. No overlay files.
- The record is separate from `tests/corpus/expected-failures.txt`. Its stages are not that list's categories.
- **The gate** compares stages only. The error text is for a person to read. A run fails when:
  - a subject's stage differs from the record, in either direction (a scenario that passes where the record has a failing stage fails too);
  - the record has no line for a scenario, or a line for a scenario that does not exist;
  - the pin in the header differs from the revision the build passes in from the flake lock. The message names both revisions.
- A `compile` stage is the same for every subject, and nothing else runs.
- Commit the record lines for scenario 1.

## Acceptance criteria
- [ ] A record in which one subject's stage is one step later than the real run fails the run. A record in which it is one step earlier fails the run.
- [ ] A record with a missing line and a line for a scenario that does not exist fails the run once for each line.
- [ ] A record whose header names a different revision from the flake lock fails with a message that names both revisions, even when every stage matches.
- [ ] A test scenario whose program does not compile records `compile` for all three subjects. Its build succeeds, and the record keeps Zena's error output.
- [ ] `tests native debug` and `tests web debug` pass.
- [ ] `lint` passes.
