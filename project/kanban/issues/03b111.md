## What to build
With every built-in of the feature in place, make the single-instance directives of `task-builtins.wast` pass and settle the async baseline. The directives are the six components that each define only one owned built-in (`backpressure.inc`, `backpressure.dec`, `task.return`, `thread.yield`, `waitable-set.poll`, `waitable-set.wait`), the directive whose realloc calls backpressure and the context slots before the export runs, and the directive whose realloc runs around a call to a synchronous host item; the components that define `subtask.cancel` and `subtask.drop`, the `async` permutations across two components, and the stream and future case stay deferred with reasons that name the missing feature. Then audit `tests/corpus/expected-failures.txt` and `expected-failures.web.txt` against the design: every line the feature's files and directives account for is gone and no other; each remaining line of an owned file states the design's reason (a call into an asynchronous export from a sibling component, a future or stream built-in, the stackful lift, a thread built-in, cancellation, or an asynchronous host item). Refresh `tests/corpus/README.md`: the baseline table's `cm/async` and `wasmtime/async` rows and the prose that says the polyfill does not implement asynchronous functions yet, so they describe what the polyfill runs now. Both targets report the same results for every named file and every repository test of the feature.

- [ ] The progress summary shows the two `async` rows with the new counts, the same on both targets, and the README's baseline table and prose match a live run.
