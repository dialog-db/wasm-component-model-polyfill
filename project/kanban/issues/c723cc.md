## What to build
The review of card `7328e7` accepted the change that names a handle's real resource type in an invalid-handle error, and left findings that need one card. First, the store now keeps one name per `ResourceTypeId` (`StoreData::register_resource` in `src/store/store_data.rs` uses `or_insert`), but PDD013 "Multi-Interface Registration" lets one identity be registered under several labels, so the rendered name is whichever instantiation came first; either make the doc say it is one of possibly several labels chosen by first registration, or carry the set. Second, for a host-registered resource the linker already knows a label (`LinkerInstance::resource_with` keys `registration.resources` by it), so the `None` a never-instantiated host resource renders is self-imposed; thread the linker's label into the registration so a host resource is named even when no component instantiates it, and reserve the IR path (`ResourceTableSpec::resource_type`) for guest-defined resources. Third, layering: the branch removed the `StoreContext::register_destructor` forwarder that `instantiate.rs` used and now reaches `store.store_data_mut().register_resource(...)` directly, the only site outside `src/store/` touching `StoreData`, while the unused `Store::register_resource` (pub on the re-exported `Store`, so the rename from `register_destructor` is semver-breaking) was kept; restore a forwarder on `StoreContext` with the name argument and decide whether `Store` needs the method at all. Fourth, the comment at `instantiate.rs:114-117` says "the first table that names a resource settles its name" but `TypeProjector::resource` never returns unnamed (it falls back to `UNNAMED_RESOURCE = "resource"`), so the code takes the first table, period; make the comment true or make the code prefer a labelled table. Fifth, `AbiCause::UnregisteredResourceType` carries `None` at `src/linker/host_call.rs` and `Some(ty)` at `src/abi/lower.rs:330-337`; pick one rendering. Add the tests the review found missing: `valtype.is_none()` at the `host_call` site (the existing test at `tests/baseline_resources.rs:556` reaches the error), the destructor-substrate failure at `store_context.rs`, and a guest-defined resource (`ResourceDestructor::Local`, e.g. through `it_releases_a_locally_defined_resource_through_the_store`) whose invalid-handle error names the type — the case that justifies the IR plumbing — plus a fixture where the host's registration label and the importer's label differ, so the test can say which one the error carries.

## Acceptance criteria
- [ ] The store's naming rule is stated truthfully against PDD013 or extended to carry every label; a test with two labels for one identity proves the stated behaviour.
- [ ] A host resource registered against a linker and never instantiated renders its linker label; a guest-defined resource renders its own label; both proved by tests.
- [ ] `instantiate.rs` registers through a `StoreContext` forwarder, and the public `Store` surface is either restored or the break is recorded for the owner.
- [ ] The three missing tests exist, and `UnregisteredResourceType` renders one way at both sites.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
