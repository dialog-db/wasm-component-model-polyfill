## What to build
Every scalar crossing the boundary is one substrate read or write with a fresh allocation: `AbiStrategy::load` (`src/abi/strategy.rs:62`) allocates `vec![0u8; length]` per load, and `lift` (`src/abi/lift.rs:45-49`) lifts a list one element at a time, each element one or more loads. In the browser each load is `buffer()`, `byte_length()`, a new `Uint8Array` view, and `copy_to` (`rust/vendor/js_wasm_runtime_layer/src/memory.rs:31-50, 121-127`), four JavaScript boundary crossings and one JS object per byte of a `list<u8>`; a 1 MiB list is about a million round trips, where a string of the same size costs one. `lift.rs:70-79` also recomputes `alignment_of` and `size_of` per field per element, allocating in `src/abi/layout.rs:282-303`, and `flat_types` and `join_flat_slots` clone payload types per variant per call (`layout.rs:346-354`, `src/abi/flatten.rs:445-452`). `in_bounds` already computed the byte length: read the whole range once and decode from the buffer, write a lowered list's bytes once, give numeric element types a straight copy, and cache the canonical ABI info and flat shape per type on the `FunctionType` so no crossing recomputes them. Measure before and after with the benchmark suite and record both numbers per target on this card.

## Owner decisions (2026-09-21)
The untyped path is bounded by element count, not by guest bytes: a `Val` slot is about forty bytes natively and about twenty on wasm32, so a guest byte bound does nothing against the inflation, while an element count is what the allocation depends on and reads the same on both targets, as Wasmtime's per-element fuel does. The bound is configurable through `EngineConfig` with a default this card picks and records; the check runs before any allocation and fails with a structured `AbiCause`. It is not PDD021's copy budget, which bounds bytes copied between memories for streams; the two are separate numbers.

## Acceptance criteria
- [ ] Lifting or lowering a numeric list costs O(1) substrate reads or writes, and a list of records O(fields) rather than O(elements times fields), proved by a test that counts substrate accesses or by the benchmark's report.
- [ ] The list and string benchmarks show the before and after numbers on both targets, recorded on this card.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
- [ ] A guest list whose element count exceeds the configured bound fails with the structured cause before any allocation, on both targets, and the default bound and the `EngineConfig` knob are documented.
