## What to build
The review of card `821d73` accepted the root namespace's version rules and left findings that need one card. First, two doc comments went stale in the same diff: `src/linker/resolve.rs:272-276` still says `PositionRoot::Root`'s `name` is "the import's own name as written", and `src/executor/instantiate.rs:661-664` (`item_of`) still says the root entry sits "under the import's own name"; after `root_key` both can be the compatible registered name. Second, the root fallback is tested only for a function import; a resource import and a module import answered by a compatible root registration have no test, and the resource path is the one where the registered name changes runtime data (it is the resource label at `instantiate.rs:696`). Third, at root level nothing pins a prerelease name, a `0.0.x` name, or a versioned import against an unversioned registration; those rules are covered only through `versions_compatible`, which `root_key` does not call. Fourth, a small divergence to state or remove: when two registered names differ only in build metadata, Wasmtime's `NameMap::insert` keeps the last inserted (an equal version does not trigger the restore at `crates/environ/src/component/names.rs:155-169`) while `root_key` keeps the first in `BTreeMap` order.
