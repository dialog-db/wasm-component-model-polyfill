## What to build
Make `tests zena` show why each subject stopped, not only where.

Today `tests zena` prints the compatibility table: one row per scenario and the stage in each cell (`wcmp_scenario::Table`, `rust/wcmp-scenario/src/table.rs`). The run it is built from already holds each subject's reason, the error text of the step that stopped it, and the committed record keeps that text too. `Table` drops it, so a person who sees `parse` in a cell has to open `tests/zena/record.txt` to learn that the browser refused a GC-reference global or that the native backend refused a tag.

- After the table, print a details section: for each scenario, each subject whose stage is before `pass`, with its stage and its full reason text. Keep the table's subject order (Browser, Native, Wasmtime). Print the text as the run observed it, without truncation.
- Say nothing extra for a subject that passed. When every subject passed, print no details section.
- Keep the table itself unchanged, and keep printing the table and the details after a gate failure, where `tests zena` already prints the differences.
- The details come from this run's observations, the browser included, not from the record.

## Acceptance criteria
- [ ] `tests zena` prints, after the table, one line per subject that stopped before `pass`, with the scenario, the subject, the stage, and the full reason text.
- [ ] A unit test of the table or details type fails when the reason text is dropped or a stopped subject is left out, and it runs on both targets.
- [ ] When a gate failure is printed, the details still print.
- [ ] `tests zena`, `tests native debug`, `tests web debug` and `lint` pass.
