## What to build

Wasmtime 50 merges the `SyncStartCall` and `AsyncStartCall` trampolines into
one `StartCall { callback, post_return }` (`info.rs:1057` at `v50.0.0`). The
core import `[start-call]` takes `(funcref, param_count, result_count, flags)`.
The flag `START_FLAG_ASYNC_CALLER` (`component.rs:58`) tells the two callers
apart. An async caller gets the status word. A sync caller gets the flat
results of the callee.

`enter-sync-call` loses its first argument, the caller instance. It now takes
`(callee_async, callee_instance)` (`fact.rs:695`). The polyfill reads
`args[1]` and `args[2]` today (`executor/intrinsics.rs:219-226`). That is a
silent break at run time, not a compile error.

The translator, the IR, and instantiation carry one start call. One intrinsic
module serves both callers and reads the flags when it runs, as Wasmtime does.
A sync caller with a sync lift is a new case. It takes the post-return path and
the blocking wait.

This card lands in the same series as 2397ff. The workspace does not build or pass on Wasmtime 50 without it.

- [x] `translate.rs`, `ir.rs`, and `instantiate.rs` carry one start call, and

- [x] The existing start-call tests pass on both targets.
- [x] The doc comments in `prepare_call.rs`, `start_call.rs`, and
      `scheduler.rs` state the Wasmtime 50 protocol.
