## What to build
The polyfill accepts 24 binaries the corpus expects rejected: non-zero reserved bytes (8 lines, `cm/binary/binary.wast`), values over the maximum size (7, `cm/validation/max-value-size.wast`), kebab-name conflicts between imports (5, `cm/validation/kebab.wast`), extern-name syntax (2, `cm/validation/extern-names.wast`), the `cm-implements` gate (1, `wasmtime/implements-disabled.wast`), and one more in `cm/validation/attributes.wast`. The translator validates with every `wasmparser` feature enabled and no limits. Wasmtime rejects them through its validator configuration and its component limits. Work through the list: enable only the features the outlook commits to and gate the rest (`cm-implements` off unless the host opts in), apply Wasmtime's value-size limit, and find why the reserved-byte and kebab cases parse, noting that both files are on the reference implementation's own not-yet-passing list, so some lines may stay `validation` with a reason.

Parity: validation runs in the shared translator; the same binaries are rejected on both targets.

## Acceptance criteria
- [ ] Every `validation` line that Wasmtime rejects is removed from `expected-failures.txt`; a line that stays carries the reason it cannot be matched, and the corpus is regenerated.
- [ ] A host can enable `cm-implements` on the engine; it is off by default.
- [ ] `tests all` passes on both targets.
