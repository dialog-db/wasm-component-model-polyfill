## What to build
Update the project `README.md` once every other PDD022 card has landed, so that it states what the polyfill now supports. The last such update was the streams and futures commit `e6f18d0`, which is the pattern to follow. Every statement must come from the landed code and a live run, not from the design.

- **Feature support.** Mark each feature with its true status and a short note:
  - `canon lift async` without a `callback` (stackful), which is refused today.
  - `thread.index`, `thread.new-indirect`, `thread.resume-later`, and the five built-ins that suspend or switch, which are refused today.
  - "Suspending a guest thread (stack switching, JSPI)", which is marked not implemented today.
  - Rows whose note mentions nested turns or a clear message for a wait that needs a stack switch: the synchronous lower of a host `async` function, and a synchronous copy.
  - State that the stackful lift and the thread built-ins stay behind `wasm_component_model_async_stackful` and `wasm_component_model_threading`, off by default.
- **Providers.** Say which provider each target selects: the stack-switching provider on an engine that implements the proposal (under Wasmtime 49, x86_64 Linux only), and JSPI in every browser that ships it. Say what happens without one (nested turns, and the stack-switch cause for a block they cannot serve). Mention the `EngineConfig` opt-out and the `Engine` query.
- **Target differences.** Remove the browser's refusal of a re-entrant host call wherever the README mentions it. Add the provider as the difference PDD022 introduces.
- **Conformance.** Refresh the summary and its numbers from the closing corpus run. Name the provider-off states and the `expected-failures.no-provider.txt` overlay, and drop the stackful lift, the thread built-ins, and waits that need a stack switch from the list of what still fails. Keep any line that still fails for another reason.
- **Targets and requirements, and Design documents.** Update any statement that stack switching is only designed, not built.
