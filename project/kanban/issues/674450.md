## What to build
Run guest threads through the JSPI provider, on the same scheduler paths the stack-switching provider uses.

A resumption under JSPI runs on a microtask, which runs before the browser returns to its event loop, never inside the call that asks for it. The scheduler treats it as it treats a synchronous resumption: a turn that resumes a thread waits until the thread suspends again or finishes, and runs nothing else in between.

This matters in one place. The reference sometimes resumes a suspended thread from inside a trampoline and continues in that trampoline once the thread stops. Two cases exist:

- A synchronous call of a sync-typed function runs the ready threads of its own instance until its task resolves (`canon_lift` in `definitions.py`).
- A thread that a nested start began switches to a suspended thread before it first suspends.

The JSPI provider cannot resume a suspended stack from inside a synchronous frame. In both cases it suspends the thread the trampoline runs in as well. The scheduler then runs only the threads the reference runs from that point, in the reference's order. It runs no other item and polls no host task. It then resumes the trampoline's thread with the outcome. A guest cannot observe the difference, because no other guest code runs in the interval.

## Acceptance criteria
- [ ] The stackful export that calls a second component through a fused adapter, suspends, resumes, and returns passes in the web lane.
- [ ] The thread started by nested start from inside a host trampoline, suspended, and resumed after its starter passes in the web lane.
- [ ] A synchronous export that lowers a host `async` function whose future is pending for two polls returns the host function's result in the web lane, and fails with the stack-switch cause with the provider turned off.
- [ ] A repository test drops a store while a thread of a stackful export is suspended under JSPI. The drop completes, no destructor runs, and a later store on the same engine runs the same export to its end.
- [ ] A repository test proves that a trampoline which resumes a suspended thread of its own instance, under JSPI, runs no other item and polls no host task until that thread stops.
- [ ] `lint` passes and `tests all` is green in all four states. A directive that starts passing under a provider leaves the shared list. A line that still fails without a provider sits in `expected-failures.no-provider.txt` with the stack-switch reason. Every line whose reason this card changes is refreshed from a live run.
