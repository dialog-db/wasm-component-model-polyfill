## What to build

A browser lane that runs the web tests in WebKitGTK, beside headless Chrome.

The web lanes run only in headless Chrome. The owner's webview is WebKitGTK, and
36bcc3 stands in for Safari with a person in Epiphany. The `wasi:webgpu` spike
(`~/Git/github.com/cdata/wasi-webgpu-test`, `harness/`) ran the polyfill in
WebKitGTK 2.54.1 MiniBrowser under Nix, through WebKitWebDriver, on a headless
Weston. What it needed:

- a headless Weston (`--backend=headless`), with its runtime directory under
  `/run/user/<uid>`, because a Wayland socket's path must fit in 108 bytes;
- MiniBrowser from `webkitgtk_6_0`'s `libexec`, and WebKitWebDriver;
- for a dedicated worker with WebGL, the features `AllowWebGLInWorkers` and
  `UseGPUProcessForWebGL`; JSPI and `requestAnimationFrame` work in a worker as
  shipped.

Run the web lanes there, or a chosen subset if the whole is too slow, with the
same pass/fail rules.

## Acceptance criteria
- [ ] A menu command runs the web tests in WebKitGTK on a headless Weston, with
      nothing installed by hand.
- [ ] CI runs it, or the card records why not.
- [ ] Each test that fails only in WebKitGTK is a new card.
