## What to build
Build the call path of a host `async` function through the lowered-import trampoline (`invoke_trampoline` in `src/executor/trampoline.rs`): a lowering whose registration is concurrent lifts the arguments through the boundary context as today, builds a `HostTask` (`src/concurrency/host_task.rs`) from the registration's future with a lowering that writes the result through the subtask's boundary context, and hands it to `StoreContext::start_host_task` with the lowering's `LowerKind`. Through an asynchronous lower the trampoline returns the `CallStatus` as the status word: the trampoline polls the future once, and a ready future lowers its result so the guest sees `RETURNED` with no entry; a pending future joins the store's host tasks, the subtask enters the caller's handle table in `STARTED`, and the guest sees that state with the index. A later turn lowers the result through the boundary context of the subtask, resolves the subtask, and fills its event, which `waitable-set.wait` and `waitable-set.poll` deliver as the triple of the subtask code, the index, and `RETURNED`. Handles the guest lends for the call go on the subtask's lender list and come back when the resolution is delivered, so a borrow lent to a host task stays lent until the guest takes delivery of the event, and a guest that drops the owning handle before then traps as PDD014 states. Through an asynchronous lower, a synchronous registration of a sync-typed import resolves at once and returns `RETURNED`. When the future of the untyped concurrent entry completes, the result vector must hold one value when the type declares a result and none otherwise, and a mismatch fails the call as the untyped synchronous path fails it. Register the five asynchronous items of Wasmtime's component spectest in `link_spectest` in `tests/conformance.rs` through `func_wrap_concurrent`, each behaving as Wasmtime's wast runner makes it behave: `host-echo-u32` resolves at once with its argument; `never-return` and `[method]resource1.never-return` stay pending; `echo-slowly` and `return-two-slowly` are pending once and resolve at the next poll, which is what a single yield on Wasmtime's executor does. `wasmtime/async/lower.wast` then instantiates. The browser proof registers a function whose future awaits a JavaScript promise.

## Acceptance criteria
- [ ] A future ready on its first poll gives `RETURNED` and no handle entry, proved on a hand-written component in both registration forms.
- [ ] A pending future gives `STARTED` with an index, and a later turn lowers the result and delivers the subtask event with that index and `RETURNED`, proved in both registration forms.
- [ ] A borrow lent for the call is released only when the event is delivered, proved by a test that drops the owning handle before delivery and traps as PDD014 states.
- [ ] A result vector of the wrong length from `func_new_concurrent` fails the call as the untyped synchronous path does, proved by a test.
- [ ] The harness registers the five spectest items through `func_wrap_concurrent`, `lower.wast` instantiates and its line leaves the list, and the reason of every remaining line that named a missing host task is refreshed from a live run.
- [ ] In the browser a host `async` function awaits a JavaScript promise and the guest receives its value through an asynchronous lower.
- [ ] `lint` passes and `tests all` is green on both targets, and any async directive that starts passing has its line removed from the expected-failure list.
