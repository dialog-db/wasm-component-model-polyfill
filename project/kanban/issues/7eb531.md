## What to build
`poll_host_tasks` (`src/store/store_context.rs:785-804`) drains and polls every host task on every turn whether or not one was woken, and `open_entry_gate` runs up to three times per turn while `release_held_callbacks` (`src/concurrency/scheduler.rs:765-815`) pops and re-examines every held item, each `set_has_pending_event` walking its set's waitables. With N in-flight host calls or N parked callback tasks that is O(N) per turn and O(N squared) over the workload, and a nested turn per blocking built-in multiplies it. The poll-all rule is also what makes the noop-waker first poll in `start_host_task` safe (`src/store/store_data.rs:329-335`), so a readiness index has to keep that path correct. Keep host tasks in a waker-gated ready set, the shape of `FuturesUnordered`, so a turn polls only the tasks woken since the last one, and deliver an event straight to the set a held callback waits on instead of rescanning. Measure with the benchmark suite and record the numbers on this card.

## Acceptance criteria
- [ ] With many pending host tasks, a turn polls only the ones woken since the previous turn, proved by a test with several never-returning tasks and one that wakes.
- [ ] No wake is lost: the existing host-task and gate tests pass unchanged, including the first poll outside a turn.
- [ ] The benchmark of N in-flight host calls shows the before and after numbers on both targets, recorded on this card.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
