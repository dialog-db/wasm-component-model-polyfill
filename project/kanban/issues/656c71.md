## What to build

Filed from card 8e4e8c (the switch review findings). In the browser, a thread that a guest call starts in place inside a host function (a nested start under the host-suspension provider that is not at rest) and that fails in its first stretch fails with a generic trap: `a thread started from inside a guest call trapped before it first suspended` (`rust/wcmp/src/concurrency/host_suspension_provider.rs`, the `None` arm of `SuspendProvider::start`). The browser settles the resumable call's promise on a microtask, and a host function cannot wait for it, so neither the guest's own trap reason nor a structured polyfill `Error` that a host import raised in that stretch reaches the caller. Natively (Wasmtime, Wasmi) the call ends on its first poll and the failure is whole. `expected-failures.web.txt` records the one corpus line it costs, `wasmtime/thread-transparency/reentrancy.wast:114`.

Let the runtime layer hand the polyfill the failure of such a call without awaiting it. The web backend already records the error of the host function that trapped a flight (`Flight::fail` in `rust/wcmp-wasm-core-web/src/flight.rs`); a synchronous way to read a settled-or-failing flight's host error, or the trap reason once the browser reports it, would let the provider return it.

## Acceptance criteria
- [x] A nested in-place start whose first stretch calls a host import that fails with a structured polyfill `Error` fails the caller with that `Error` in the browser, proved by a web test.
- [x] The guest-trap half either carries the engine's reason, with `reentrancy.wast:114` removed from `expected-failures.web.txt`, or the limit stays documented with the reason the browser cannot report it.
- [x] `lint` passes and `tests all` is green on both targets.

## Implementation notes

- 2026-10-13 (`test(concurrency): Prove a nested start's host error reaches
  its caller`): the host-error half already works. The web store's
  `start_resumable` runs the first stretch under a lease, and a host function
  that fails there records its error on that lease (`Calls::fail`,
  `Reach::Lease`). `start_resumable` returns it as
  `Error::Trap(TrapKind::Host(..))` (`rust/wcmp-wasm-core-web/src/store.rs`,
  the `match failure` at its end). So `call_resumable` fails on its first
  poll, the provider's `Some(outcome)` arm takes it, and `call_failure`
  downcasts the polyfill `Error`. New test
  `it_fails_the_caller_with_the_host_error_of_a_nested_start_in_its_first_stretch`
  (`baseline/provider_threads.rs`, the reentrancy shape with a failing host
  import) passes over the host-suspension provider (Wasmi natively, the
  browser) and the stack-switching one. Mutation: a panic in that arm
  fires in the browser run, which proves the test reaches the in-place start.
- Guest-trap half: the limit stays, and the provider, the web store and
  `Func::call_resumable` now say why. The browser reports a trap's reason only
  by rejecting the call's promise on a microtask. A JavaScript frame that
  caught it at once would sit between the stack and its suspender, where JSPI
  refuses to suspend, and WebAssembly cannot catch a trap.
  `reentrancy.wast:114` stays in `expected-failures.web.txt`.
- 2026-10-13 gate on the series tip: `tests all` green (native debug and release 1741/1741, no-provider 169, Wasmi 1458, web debug and release 1728/1728, fidelity 264/267/264, Zena Browser 18/18, Native 18/18, Wasmi 2/18, Wasmtime 18/18, demo 68/68), no `unexpected:` or `stale expectation:` line, `tests regenerate --dry-run` current, and the full `lint` green.
