## What to build

Filed from card e84e63. A string transcode whose source and destination lie in the same memory and overlap is not handled consistently (`rust/wcmp/src/abi/transcode.rs`). The copy ops go through `Memory::copy` and behave like `memmove`. The converting ops write chunk by chunk as they read, so an overlapping in-place `Latin1ToUtf16` overwrites source bytes before it reads them and produces a corrupt string. Wasmtime asserts that the two ranges do not overlap (`assert_no_overlap` in `crates/wasmtime/src/runtime/vm/component/libcalls.rs`), which is a panic. The reference decodes the whole source before it writes, which behaves like `memmove`.

The owner chooses the behaviour: refuse an overlapping transcode with a structured error, as Wasmtime refuses it but without the panic, or convert it as the reference does. To know the two sides share a memory, `build_transcoder` (`rust/wcmp/src/executor/intrinsics.rs`) can pass whether the from and to memory indices are the same into `transcode`. `Memory` has no `PartialEq`, so two slots that alias one memory are a limit to state.

## Acceptance criteria
- [x] The owner's choice is recorded on this card.
- [x] A same-memory overlapping transcode either fails with a structured error or yields the reference's result, for each converting op, proved by a test on both targets.
- [x] `lint` passes and `tests all` is green on both targets.


## Owner decisions

- 2026-10-13: refuse. A same-memory overlapping transcode fails with a structured `AbiError` trap, as Wasmtime refuses it (`assert_no_overlap`, `crates/wasmtime/src/runtime/vm/component/libcalls.rs:168`) but without the panic. The spec text is silent, so Wasmtime is the tie-break.

## Implementation notes

- 2026-10-13 (`fix(abi): Refuse a string transcode that overlaps in one
  memory`): `transcode` takes `same_memory` (`build_transcoder` passes
  `from_memory == to_memory`), and every op, the three copies included as
  Wasmtime refuses them too, calls `refuse_overlap` before it writes, with
  Wasmtime's byte ranges for each op. An overlap fails with
  `AbiError { position: Argument(2), valtype: string, cause:
  AbiCause::OverlappingTranscode { .. } }`, which the trap's text carries. Two
  indices that alias one memory are a stated limit. Ranges meet only where
  both hold a byte, so an empty string overlaps nothing; Wasmtime's assertion
  also refuses an empty source at the destination's start.
- Tests (unit, both targets):
  `it_refuses_every_transcode_whose_ranges_overlap_in_one_memory` (all 12 ops,
  and the memory is unchanged) and
  `it_runs_a_transcode_within_one_memory_whose_ranges_do_not_meet`.
- 2026-10-13 gate on the series tip: `tests all` green (native debug and release 1741/1741, no-provider 169, Wasmi 1458, web debug and release 1728/1728, fidelity 264/267/264, Zena Browser 18/18, Native 18/18, Wasmi 2/18, Wasmtime 18/18, demo 68/68), no `unexpected:` or `stale expectation:` line, `tests regenerate --dry-run` current, and the full `lint` green.

## Review notes

- 2026-10-13, review round 1 (context-free reviewer): should-fix.
  `build_transcoder` turned the transcode's error into text
  (`anyhow!("string transcoder failed: {err}")`), so `call_failure` could not
  downcast it, and a host got `Error::Trap(text)` instead of
  `Error::Abi { cause: OverlappingTranscode, .. }`. Fixed in `fix(abi): Hand
  back a refused transcode as its own error`: the error itself traps the
  guest, as every other built-in's does. A new test,
  `it_hands_back_an_overlapping_transcode_as_its_structured_error`, builds the
  transcoder's host function and calls it through the runtime layer. With the
  old mapping it fails, showing the `Trap(string transcoder failed: …)` text.
- The browser corpus lines for `wasmtime/memory64.wast` changed wording with
  the fix. To read the browser's own text, I dropped them for one run of
  `it_passes_wasmtime_memory64`. Line 122 now reads `polyfill internal
  invariant violated: the host cannot address …`, the error `arg_usize`
  raises; before the fix it had the `string transcoder failed:` prefix. Lines
  126 and 131 read `cannot enter component instance`, both before and after
  the fix: line 122's trap poisons the store. So the old reasons on 126 and
  131 were wrong. They are now `cascade` lines, as the corpus README's rule
  says, and both READMEs count them that way.
- Round 1 gate: `tests all` green (native debug and release, no-provider,
