## What to build
Build `subtask.cancel` for a guest callee and `task.cancel`, replacing the stubs in `src/executor/cancel.rs` and `TrampolineSpec::TaskCancel` / `SubtaskCancel` (`src/executor/ir.rs:907-921`) that fail when a guest calls them. Cancellation is cooperative: the caller asks, and the callee decides when to stop. Follow the reference (`definitions.py`, `canon_subtask_cancel`, `Task.cancel`, `canon_lift`, `wait_from_callback`) and Wasmtime's messages.

`subtask.cancel` takes a subtask index and an `async` option:

```text
fn subtask_cancel(async_, index) -> status:
    trap if the instance's may-leave flag is clear
    subtask = the subtask at index            // trap if it is not a subtask
    trap if its resolution was delivered      // "called after terminal status delivered"
    trap if cancellation was requested        // the second cancel of one subtask
    trap if it is in a waitable set           // "cannot be used synchronously ..."
    if not subtask.resolved():
        subtask.cancellation_requested = true
        subtask.callee.request_cancellation()
        if not subtask.resolved():
            if async_: give way once          // the cooperative yield
            else:      block until resolved   // under the existing blocking rules
        if not subtask.resolved():
            return BLOCKED                    // 0xffff_ffff
    deliver the resolution
    return subtask.state
```

- A callee in the `STARTING` state never runs. The subtask resolves to `CANCELLED_BEFORE_STARTED`, and its record leaves the store when the caller drops it.
- A started guest callee's task becomes `pending-cancel`. It learns of the request once, which moves it to `cancel-delivered`, at the first of: the entry gate (a task waiting there is cancelled before its thread runs, `enter_implicit_thread`); or the callback loop, where the callback receives the task-cancelled event (6) instead of the next event, after a wait, after a yield, or at once when it is waiting, with the instance's exclusive lock free. A stackful task that never calls a cancellable built-in is never told, and the cancel waits until it resolves on its own.
- `subtask.cancel` wakes a callback task waiting in its loop and gives way to it, as Wasmtime wakes the first thread that can take the request (`concurrent.rs:4161-4345`). Waking a thread in a cancellable `waitable-set.wait` or yield is the cancellable-immediate card's.
- An asynchronous cancel gives way once, as `thread.yield` does under PDD019, then returns `BLOCKED` if the callee has not resolved. A synchronous cancel blocks until the callee resolves, through the provider or in a nested turn, and a block that cannot progress fails with the existing cause.
- The resolution is `RETURNED` when the callee returned first and `CANCELLED_BEFORE_RETURNED` when it confirmed. Delivery of either releases the handles the caller lent, as PDD020 states.

`task.cancel` resolves the current task as cancelled: the may-leave flag must be set (cannot-leave trap); the task must be in `cancel-delivered`, or it fails with "`task.cancel` called by task which has not been cancelled" (a task not lifted `async` always fails so); the task must not have resolved, or it fails with the existing "`task.return` or `task.cancel` called more than once for current task"; and its borrow count must be zero (PDD014's scope-exit rule). A task in `cancel-delivered` may call `task.return` instead, and its caller sees `RETURNED`. Its threads keep running after `task.cancel`, and the task lives until its last thread ends.

New causes, each structured with its message: "`subtask.cancel` called after terminal status delivered"; "`subtask.cancel` called twice for the same subtask", the polyfill's own message for a second cancel before delivery (the reference traps, Wasmtime has no message); and "`task.cancel` called by task which has not been cancelled". A cancel of a subtask in a waitable set uses the existing "waitable cannot be used synchronously while added to a waitable set". With this card the two cancel states of the task record and the two cancelled states of the subtask record are reached, and only through cancellation. `tests/baseline_cancel.rs` pins the old stub behavior and changes with it.

A host callee and the `cancellable` immediate are other cards of this design.
