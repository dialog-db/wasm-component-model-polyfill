## What to build
The end-to-end smoke test (`rust/wcmp-smoke`, run by `tests smoke native` and `tests smoke check`) has no story that uses a stream or a future, although the streams and futures work now lets a host and components exchange both. Add one or more stories, in a new chapter (for example "Streams and futures"), that show what that work enables, each written the way the existing stories are (a `Story` with a chapter, a title, and a goal a reader understands without the design, and a step that returns what it proved).

Cover at least these three shapes, built from real toolchains where the toolchain supports them, as the "Real toolchains, real types" chapter does:
- A guest component built with `cargo` and wit-bindgen's async support exports a function that returns a `stream<u8>` (or `stream<string>`). The host reads it through a `StreamConsumer` piped from the returned `StreamReader`, and the story checks every item arrived in order and the stream ended.
- The host hands a guest a `stream<T>` it writes through a `StreamProducer` and receives a `future<T>` the guest resolves with a result computed from the items (for example a sum or a checksum). This proves both directions and a future in one story.
- Two components composed with `wac`, where one streams values to the other through a fused adapter and the host only sees the final result, showing a guest-to-guest crossing and, for a number payload, the byte copy.

Build the fixtures with the menu's `fixtures` command and put their sources beside the existing fixtures under `rust/wasm-component-model-polyfill/tests/corpus/fixtures/`, as the existing fixtures are. If wit-bindgen's async support at the pinned version cannot express a shape, write that fixture by hand in WAT inside the smoke crate (as `MODULE_CONSUMER` and `MEMORY64_COMPOSITION` are), and say which shape and why in your report. Each story must pass natively and in the browser; if a shape needs a stack switch on the target (the suspend capability has no provider yet), choose a shape that uses the callback form instead, and state the limit in the story's goal.
