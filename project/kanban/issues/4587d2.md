## What to build
When a synchronous start's wait fails, `release_wait` in `src/executor/sync_start_call.rs` (around lines 419-423) removes the callee's task record but leaves every scheduler item that still names that task: a callback item on the low-priority queue after a YIELD status word, a held callback awaiting its set, a high-priority item from a wait on an already-filled set, or the start item still queued at the entry gate. The reviewer reproduced it with a plain component — a sync-typed caller, a callback callee whose first status word is YIELD, no third task: the caller's nested turn may not run the callee's instance, the wait fails with the cannot-block cause, and the next driver turn fails with `polyfill internal invariant violated: an export's task is not in the store` (`callback_task.rs:193-197` claims and pushes a scope for a task with no record, then `exit()` at `:124` hits the internal error) where before the release it failed with the domain error `async-lifted export failed to produce a result`. Decide, from PDD019's task lifecycle and the reference, what happens to a dead task's pending work — drop the items when the record goes, or let an item that finds no record end quietly — implement it so no internal error is reachable from a component, and state the rule in the module doc.

## Acceptance criteria
- [ ] A sync-typed caller whose callback callee yields first fails its call with the cannot-block cause, and the next driver turn neither runs the orphaned item nor fails with an internal error, proved by a test that pins the turn's outcome.
- [ ] The same holds for a held callback item and for a start item queued at the gate when the wait fails.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
