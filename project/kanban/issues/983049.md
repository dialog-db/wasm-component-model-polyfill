## What to build
The review of card `8a0e7a` accepted leaving the asynchronous lower's memory rule to wasmparser and left findings that need one card. First, the tests that justify the change are missing: the case where wasmparser's rule and the card's literal rule diverge — an asynchronous lower whose single parameter carries a pointer inside four flat slots (for example `(param "s" string)`) and no `memory` — has no test; a memory-less lower that parks a subtask (`STARTED`) and delivers in a later turn has none (the new call-through test resolves on its first poll); and the four-flat-parameter boundary is untested (only one and five parameters are). Second, with `wasm_component_model_gc(true)` (`src/engine_config.rs:77`) wasmparser routes to `lower_gc`, which never requires memory, so a gc-mode asynchronous lower that the old check refused now translates and fails at the first crossing with `AbiCause::UnsupportedDataModel` (`src/abi/strategy.rs:45, 68`); state that in the translator's doc or refuse it at translation with a cause that names the data model. Third, if a memory-less crossing were ever reached, `strategy.rs:58-61` reports `OutOfBoundsMemory` rather than a missing-memory cause; decide whether the polyfill keeps a defence behind the validator and name the cause. Fourth, the test helper's doc at `tests/baseline_async_import.rs:366-373` pins "wasmparser 0.258.0" and a source path, and `tests/corpus/expected-failures.txt` already carries a stale "wasmparser 0.254"; cite the validator by symbol, not version.
