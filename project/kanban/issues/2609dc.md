## What to build
The first concurrency feature: an `async` export lifted in the callback form (`canon lift async callback`), and the task built-ins it needs. Design against the runtime model: the task lifecycle for an export call, `task.return` (including the result type check), the callback protocol's status words and the event delivered on resume, `ExtractCallback` in the executor, `context.get` and `context.set`, `backpressure.inc` and `backpressure.dec`, `thread.yield`, and waitable sets (`new`, `wait`, `poll`, `drop`, `waitable.join`) as far as a single task uses them. On the host side, `Func::call` and `TypedFunc::call` drive the task to its return and surface the result; the futures already exist, so the public API does not change shape.

The deliverable the Test Cases must cover: an `async` export that returns at once; one that yields through `thread.yield` and is resumed; one that waits on an empty waitable set and traps or returns per the spec; the callback status words for each; and the same behavior on both targets. Name the corpus files this phase owns (for example `dont-block-start.wast`, `empty-wait.wast`, `wait-during-callback.wast`, `validate-no-async-abi-for-sync-type.wast`) and any that stay deferred with the reason.
