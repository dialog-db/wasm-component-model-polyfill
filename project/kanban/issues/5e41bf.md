## What to build

Two pre-existing hazards the re-review of the task records noted, neither a regression. First, `src/concurrency/task_id.rs` (lines 5-14) argues that index reuse is safe because a task that ends with borrows outstanding fails its call, but that call's borrow entries survive in the handle table naming a freed `TaskId`, which `RecordTable` (`record_table.rs:41-51`) can hand to a later task; `drop_handle` (`executor/trampoline.rs:260`) would then decrement the later task's count. Either give the record table a generation so a stale identity cannot alias a live task, or have the unwind drop the borrow entries a failed task leaves behind, and make the comment state what is actually guaranteed. Second, `executor/intrinsics.rs:367` and `abi/lift.rs:420` discard the boolean `HandleTables::lend` returns, and `lend` (`resource/tables.rs:208-219`) raises `lend_count` before `add_lender`, so a `false` would leak a lend; make the failure structured (an `Error` variant or a trap) and order the two steps so a refused lend leaves the count untouched.

## Acceptance criteria

- [ ] A test shows that a borrow entry left by a task that failed its call cannot decrement a later task's borrow count.
- [ ] `lend` cannot leave `lend_count` raised without a lender recorded, and a refused lend is a structured error, proved by a test.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
