## What to build
Two gaps the independent review of card 89451b found in the Zena test host's console streams (landed as `e6aa07ab5`). Neither blocked the card.

- **Zena's real write pattern.** The pinned console (`packages/stdlib/zena/console/component.zena:33-56` at `b2237f7`) keeps one stream per output open for the life of the program and never drops it, so stdout and stderr are open at once, writes interleave, and the returned futures never resolve. The stand-in `COMPLAINER` (`tests/zena.rs:692-758`) opens one stream per write and drops each one. The reviewer ran a scratch probe with Zena's pattern (separate instance types, both streams kept open, stdout `hello`, stderr `oops`, stdout `world`, no drops); it passed natively and in the browser. Add it as a test, since no real Zena component reaches the host on the polyfill today.
- **Wasmtime stderr cap.** The Wasmtime run now sends stderr to a `MemoryOutputPipe` capped at 1 MiB (`wcmp-scenario-wasmtime/src/wasmtime_run.rs:453-456`); the default sink was unbounded, so stderr past 1 MiB now fails in the guest, and nothing reads the pipe. Either make the sink unbounded or discard, or state the cap beside the stdout cap.

## Acceptance criteria
- [ ] A stand-in with Zena's write pattern (both streams open at once, interleaved writes, no drops) passes in the browser and natively, and the output lines hold only the stdout writes.
- [ ] The Wasmtime run's stderr sink cannot fail a scenario that writes much to stderr, or its cap is documented.
- [ ] `tests native debug`, `tests web debug` and `lint` pass.
