## What to build
The dispatch instructions forbid bare `cargo`, and Nix builds from the committed `Cargo.lock`, so a card that bumps a dependency has to refresh the lock file with no menu verb for it. An implementor working card `45740e` fell back to `nix develop -c cargo metadata --format-version 1` to re-resolve the lock after pinning Wasmtime 49 and reported the gap. Add a verb to the menu in `flake.nix` that re-resolves `Cargo.lock` for the workspace with the flake's pinned cargo, offline where the registry index already has what it needs and online otherwise (the sandbox allowlist reaches crates.io), and that prints the lock's diff summary so the agent can see what moved. Do not make it upgrade every crate: it resolves only what the manifests changed, the way `cargo metadata` and `cargo update --workspace` do, not the way `cargo generate-lockfile` re-resolves the whole graph to the newest versions. Name the verb in `project/kanban/.dispatch-instructions.md` beside the other menu commands.

## Acceptance criteria
- [ ] `nix develop -c menu` lists a verb that re-resolves `Cargo.lock` without upgrading crates the manifests do not ask for.
- [ ] `project/kanban/.dispatch-instructions.md` names the verb.
- [ ] `lint` passes.
