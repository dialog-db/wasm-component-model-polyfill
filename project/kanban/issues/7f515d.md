## What to build
Enabling the asynchronous start made two corpus files livelock without stack switching: `cm/async/async-calls-sync.wast` (a nested turn serving a synchronous lower's block re-ran a yielded item for ever) and `wasmtime/async/reenter-during-yield.wast` (a thread gave way for ever with another task's guest frame below it). The asynchronous-start card bounded both — a nested turn gives each held yielded item one chance, and `thread.yield` fails with the stack-switch cause when the same thread gives way twice with nothing of the store's run between and a caller's frame below — and its reviewer found both bounds contradict the design corpus: PDD019 says the built-in never fails on its own and the spec's `canon_thread_yield` has only the may-leave trap; PDD020's first nested-turn rule is unbounded. Wasmtime avoids both livelocks through its fiber scheduler, which the polyfill does not have. This is an owner decision: state in the design what the polyfill does where the reference would switch stacks — the exact bound, why it exists, and what a guest observes — or choose another rule (for example trapping the blocked caller with the stack-switch cause instead of bounding the yielder), and reconcile the code's rule with the written one. The Rust docs on the yield built-in and the seam state the bounds as the polyfill's own rule pending this decision.

## Owner decisions (2026-09-21)
The failure moves off the yielder and onto the blocked call. `thread.yield` never fails on its own, as PDD019 and the reference state. The suspend seam keeps one budget: when the nested turns it runs make no progress toward the blocked call's condition past the budget, the blocked call fails with the stack-switch cause, because the caller that alone could release the callee sits below it on the real stack and only a stack switch could resume it. That is the one departure, stated once in the design with this reason. The nested turn's rule that a yielded item runs once no other item is ready stays as its fairness rule; whether each yielded item gets one chance per nested turn is the implementor's to keep or simplify, and the design says which. A target with a suspend provider never consults the budget.

## Acceptance criteria
- [ ] The design corpus states the rule for a yield loop under a block and for a thread that gives way repeatedly with a caller's frame below, and names the departure from the reference and its reason.
- [ ] The code's rule matches the written one: `thread.yield` returns 0 in every case the unit tests pin, and the blocked call is what fails with the stack-switch cause past the seam's budget, with the tests that pin each boundary adjusted to that shape.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary matching the README.
