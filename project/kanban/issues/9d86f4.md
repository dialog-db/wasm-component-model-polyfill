## What to build
Build `stream.cancel-read`, `stream.cancel-write`, `future.cancel-read`, and `future.cancel-write` as the reference's `cancel_copy`: each is lifted with a type and an optional `async` flag, takes an end index, and returns the packed result. Its checks: the cannot-leave cause; the entry's kind matches the built-in; the payload matches; the end is `copying` and has no synchronous waiter, else the no-copy-pending cause; a synchronous cancel on an end in a waitable set fails with the waitable cause. The end moves to `cancelling`. When the end's event slot is empty, the shared record's cancel runs and notifies the pending side with the cancelled result; if the slot is still empty an asynchronous cancel returns the blocked sentinel and a synchronous cancel blocks through the suspend seam. A cancel on an end whose copy already completed returns that completion with its progress, because its event was waiting in the slot. A cancel on an end that is still the pending side takes the buffer back and returns the cancelled result with the progress made so far. The end returns to `idle` unless the result is dropped. A cancel against a host end asks the host to finish through the `finish` flag of the host surface, and can leave the guest blocked or waiting on an event until the host answers; the host-surface cards prove that half. `streams.wast`, `futures.wast`, and `async-builtins.wast` pass whole once every built-in their components define exists, and the last directives of `streams.wast` expect the concurrent-operation trap. `CopyCause` grows by the no-copy-pending variant.

- [ ] `streams.wast` and `futures.wast` pass whole, including the concurrent-operation trap directives.
