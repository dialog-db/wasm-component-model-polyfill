## What to build

Step 1 of the migration (build beside). Host suspension in the browser backend, filled with JSPI.

A suspending host function is an import made with `WebAssembly.Suspending`. A resumable call goes through `WebAssembly.promising`. The backend declares `host_suspension` when both exist. The contract:

- A suspension succeeds only when WebAssembly frames alone lie between the start of the resumable call and the suspending host function. Otherwise the call traps.
- Any number of handles can wait at once in one store, and the host resumes them in any order.
- A handle does not hold the store. It borrows the store only while it resumes.
- When a store drops, its waiting handles drop without a resumption. A resumption that started before the drop runs to its next suspension or its end first, and the backend keeps the store's state alive until then. Under JSPI that resumption runs on a microtask after the host code that started it returned.

Add the host-suspension tests to the shared contract tests, so the Wasmi backend runs the same tests later.

## Acceptance criteria
- [ ] A test starts three resumable calls in one store; each suspends in a suspending host function. The test resumes them third, first, second, and each finishes with its own results.
- [ ] A fourth call suspends with a host frame between its start and the suspension, and it traps.
- [ ] A test drops a store with waiting handles and with a resumption in flight. Nothing panics, and the in-flight resumption reaches its next suspension or end.
- [ ] The backend declares `host_suspension` only when both JSPI functions exist.
- [ ] `lint` and `tests web debug` pass.
