## What to build
Build `future.read` and `future.write` as the same copy with a count of one and no partial step, over the future kinds and the reference's `SharedFutureImpl`: the built-ins take an end index and a pointer and return the packed result, whose count is always zero. The differences the reference states: a completed copy and a dropped result both move the end to `done`, so a future is written at most once and read at most once; a writer whose readable end was dropped completes with the dropped result; a reader never sees the dropped result, because a writable future end cannot be dropped before it has written. A write on an end in `done` traps with Wasmtime's message naming both causes, `cannot write to future after previous write succeeded or readable end dropped`; a read in that state traps with `cannot read from future after previous read succeeded`. Dropping the readable end of a pending write completes it with the dropped result, and a writable future end whose reader dropped is `done` and drops cleanly. This card also lands the after-done traps for both kinds and both directions, and the lift-after-done trap the crossing card left untested, so `trap-if-done.wast` in both corpora passes whole. `drop-cross-task-borrow.wast` passes: a borrow lent to a callback task that waits on a future is dropped from another task of the same instance, and the lender's return then traps or succeeds as PDD014 states. `CopyCause` grows by the future variants.
