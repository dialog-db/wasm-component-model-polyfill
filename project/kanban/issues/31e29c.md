## What to build
The toolchain-neutral core of the Zena tests: the scenario's expectations file, the Wasmtime run's observations, the stages, and the rules that judge a subject. Both the Wasmtime run (native, with Wasmtime) and the polyfill runner (native and `wasm32-unknown-unknown`) use it, so it depends on neither Wasmtime nor the polyfill and builds for both targets.

- **Expectations file.** A text format a contributor writes by hand. It lists the calls in order. Each entry names the component and the export, gives the arguments, and gives one of three outcomes: the results, a failure, or no outcome (the Wasmtime run decides it). An entry can ask for a typed call. The file also lists the output lines the scenario prints, in order. Values cover at least scalars and strings.
- **Observations.** What the Wasmtime run saw: the results or the failure of each call, and the output lines. A build product that the polyfill subjects read. Not committed.
- **Stages**, in order: `compile`, `compose`, `parse`, `link`, `instantiate`, `call`, `mismatch`, `pass`, with the meanings in PDD024's Outcomes table. `call` is a failed call whose expectation is a result. `mismatch` is every call ran but a result or output line differs, or a call succeeded where it had to fail.
- **Judging.** The Wasmtime run is judged against the expectations file. A polyfill subject is judged against the Wasmtime observations when the Wasmtime run passed, and against the expectations file otherwise. PDD024 does not say how an entry with no outcome is judged when the Wasmtime run did not pass; accept any outcome for it, and say so in a doc comment.

Keep this part free of anything Zena-specific. PDD024 keeps the toolchain-neutral parts apart, without building an extension point.

## Acceptance criteria
- [x] A Wasmtime run whose observations fail the expectations file gets a stage before `pass`, and the polyfill subjects are then judged against the expectations file.
- [x] For a scenario whose Wasmtime run passes, a polyfill subject is judged against the Wasmtime results and output lines.
- [x] One changed result in the observations of a passing scenario gives `mismatch`.
- [x] An entry with no outcome follows whatever the Wasmtime run observed.
- [x] The unit tests pass in `tests native debug` and `tests web debug`.
- [x] `lint` passes.
