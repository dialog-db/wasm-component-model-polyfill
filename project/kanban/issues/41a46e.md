## What to build
From the 2026-10-13 review of a70072 (and its absorbed card 2e6717). The typed direct path for a numeric `Vec<T>` is not reached when parameters spill.

- The typed spill test uses `(String, [u32; 8], [u32; 8])` (`rust/wcmp/tests/baseline_typed_direct.rs`). `String::store` takes the direct path, but `[T; N]` uses the default `store`, which goes through `to_val`.
- The direct numeric branch of `Vec<T>::store` (`rust/wcmp/src/linker/component_value.rs`, the `write_pointer_pair` call) is reached by no test. Checked on 2026-10-13: passing `0` instead of `len` to `write_pointer_pair` there, `tests native debug` passed all 1733 tests.
- Fix from the review: use `(String, Vec<u32>, [u32; 8], [u32; 8])` (20 flat values), and have the guest fold the vector too.

Also from the same review, smaller:
- The UTF-16 typed echo test round-trips through a guest that echoes the pointer and length, so a typed mistake that used UTF-8 both ways would still pass. A guest export that returns the length word it was given would make the test independent.
- The two typed `call_concurrent` calls run one after the other. Make them overlap.
- `rust/wcmp-bench/README.md`: the `list-record-roundtrip` row says "the same", which now refers to the new typed row above it. That benchmark is untyped.

## Acceptance criteria
- [ ] A typed call whose parameters spill carries a `Vec<u32>` (or another numeric `Vec` wider than a byte) through the direct `store` branch, and the test fails when that branch writes a wrong length.
- [ ] The UTF-16 typed test fails if the typed path used the wrong encoding.
- [ ] The typed concurrent test has two calls in flight at once.
- [ ] The bench README row is correct.
- [ ] `lint` passes and `tests all` is green on both targets.
