## What to build

Follow-up from the second review of the PDD027 series. PDD027 says the type check of a typed value runs when the host acquires a typed function or links a typed host function, and never on a call. A host-created `StreamReader<T>` or `FutureReader<T>` breaks that.

- **Today:** lowering such a reader into a guest checks the end's payload against the declared one through `EndPayload::matches`. For a host payload that runs `T::typecheck` on every lowering: `rust/wcmp/src/abi/lower.rs` `lower_host_end`, then `src/concurrency/end_payload.rs`, then `HostPayload::check`.
- **Why the test misses it:** the check-count test (`typed::type_checker::type_check_runs`) uses only a `u32` function, so it cannot see this.

The typed reader's own type check already ran when the function was acquired or linked, so skip the payload check on the typed path. Keep it for `StreamAny`, `FutureAny`, and the `Val` path, which have no static type. Then extend the check-count test to a function that lowers a host-created reader.

## Acceptance criteria
- [ ] A typed call that lowers a host-created `StreamReader<T>` and a `FutureReader<T>` runs no type check, which the check-count test shows on both targets.
- [ ] A `StreamAny` or `Val::Stream` of a mismatched payload is still refused with the payload-mismatch cause.
- [ ] `lint` passes, and `tests all` is green on both targets with the conformance summary unchanged.
