## What to build
`lower_handle` (`src/abi/lower.rs:344-357`) lowers a `borrow<T>` parameter from `handle.rep` directly: it neither looks the handle up in the host's table for the resource type nor lends the host's owning entry for the length of the call. `ResourceHandle` is `Copy` with public fields, so a stale copy after `Store::resource_drop`, or a forged one, passes, and the guest receives a borrow of a freed or arbitrary rep. Because the host entry's lend count stays zero, `Store::resource_drop` from a re-entrant host function succeeds while the guest still holds the borrow (`remove_own` at `src/resource/tables.rs:612-631` refuses only a lent entry). Wasmtime's `host_resource_lower_borrow` lifts the host entry first, trapping `unknown handle index`, and lends it, so a drop during the call fails with `cannot remove owned resource while borrowed`. PDD014 lists `lower_borrow` as only incrementing the task's borrow count (around lines 51-53), so the design needs the lend line too; add it to the lend rule the guest-to-guest lend card settles. Look the handle up, refuse a missing or already-borrowed entry with the invalid-handle cause, and `lend_to` the crossing's scope, released when the scope ends as a guest lend is.

## Acceptance criteria
- [ ] Lowering a `Val::Borrow` whose handle was released, or one the host never minted, fails with the invalid-handle cause on both targets.
- [ ] A host function called by the export that received the borrow cannot `resource_drop` the owning handle until the call ends, proved by a test that drops during and after the call.
- [ ] PDD014 or the lend rule's document states that a host lend is counted; `markdown format` has run.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
