## What to build
Add a store entry named after Wasmtime's `run_concurrent`. It takes a closure, hands the closure an accessor to the store, and polls the scheduler until the closure's future completes, then returns the closure's value. Define the accessor as the host task contract states, mirroring Wasmtime's `Accessor`: it reaches the store's host data only inside a closure it runs during a poll; a value taken from the host data must be cloned out of the closure; an accessor used inside another accessor's closure fails with the recursive-driver cause. The entry follows the driver rules of the scheduler card with one difference: when a turn finds nothing ready and no host task pending, the entry returns pending instead of the deadlock cause, because its closure can wait on something outside the store. A host uses the entry to let a task finish after its call returned and to run host tasks that no call owns; it also exists so that several host calls into one instance can run at the same time, though the call entry that starts such a call is out of scope. Re-export the accessor from `lib.rs`.

## Acceptance criteria
- [ ] `run_concurrent` runs its closure with an accessor that reaches the store's host data and returns the closure's value, proved by a test on both targets.
- [ ] A test enters a driver from inside the closure, a `Func::call` through the accessor or a nested `run_concurrent`, and gets the recursive-driver cause.
- [ ] A test uses an accessor inside another accessor's closure and gets the recursive-driver cause.
- [ ] A test shows the entry returns pending, not the deadlock cause, when the store is idle and the closure waits on a future outside the store, and completes when that future resolves.
- [ ] A test shows the entry runs an item an earlier driver left in the store.
