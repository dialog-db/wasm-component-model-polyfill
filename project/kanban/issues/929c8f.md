## What to build
Let the translator accept an export lifted with `canon lift async (callback $cb)` and let the public type say the function is `async`. `FunctionType` in `src/component/function_type.rs` gains `pub async_: bool`, true when the type carries the `async` effect, spelled as Wasmtime's `ComponentFunc::async_`. `Projector::function` in `src/component/project.rs` stops refusing an `async` type and records the flag; the projection still refuses an `async` function type on an import with `Error::Unsupported`, because no host function of this design can satisfy it, at the lower trampoline in `src/executor/translate.rs` and wherever the component's import listing projects a function type. `signatures_compatible` in `src/instance/typed_func.rs` compares parameters and result as today and ignores the flag, so a typed handle to a callback export is acquired with no change to the host's code. In the translator, `GlobalInitializer::ExtractCallback` becomes an `Initializer::ExtractCallback { slot, source }` in `src/executor/ir.rs` beside `ExtractRealloc` and `ExtractPostReturn`, with a `num_runtime_callbacks` count; `CanonOptions` gains `async_: bool` and `callback: Option<usize>`, filled by `lift_canon_options`; `src/executor/instantiate.rs` extracts the callback from the core instance into the runtime state next to the reallocs and post-returns, and `BoundaryOptions` in `src/abi/options.rs` hands it out. The validator has already checked that the callback's core type is `(func (param i32 i32 i32) (result i32))` and that the function type is `async`; the translator trusts it. An export lifted `async` without a callback, the stackful form, is refused with `Error::Unsupported` at translation. Until the host call is built, `Func::call` and the typed call on an export whose options are `async_` return `Error::Unsupported`, so a status word is never lifted as a result. While there, make the catch-all refusal in `lift_core_def` name the refused trampoline (the translator has the `Trampoline` at hand) instead of the blanket string, so the reasons on the expected-failure list read right. `lift.wast` instantiates after this card, and `validate-no-async-abi-for-sync-type.wast` keeps passing.

## Acceptance criteria
- [ ] `FunctionType::async_` is true on a callback export's type and false on a synchronous export's, proved by a test on a component written by hand, and a typed handle to the callback export is acquired with no change to the host's code.
- [ ] `lift.wast` instantiates and its line leaves the expected-failure list; the three directives of `validate-no-async-abi-for-sync-type.wast` still pass.
- [ ] An export lifted `async` without a callback and an `async` function type on an import are each refused with `Error::Unsupported`, proved by a test.
- [ ] `Func::call` and `TypedFunc::call` on a callback export return `Error::Unsupported` until the call is built, proved by a test.
- [ ] `tests all` passes on both targets, and any async directive whose failure text changes has its line regenerated with the new reason.
