## What to build
Build `stream.read` and `stream.write` as the reference's `stream_copy` over the end records: a trampoline (`src/executor/trampoline.rs`) lifted with a stream type and canon options that carry the `async` flag and the memory, taking an end index, a pointer, and a count, and returning one `i32`. Its checks, in order: the cannot-leave cause when the may-leave flag is clear; the entry's kind matches the built-in; the end's payload equals the built-in's; the end is `idle`, else Wasmtime's `cannot have concurrent operations active on a future/stream`; a synchronous copy on an end in a waitable set fails with the waitable cause PDD018 carries for a synchronous use of a waitable in a set; a count of 2^28 or more traps with Wasmtime's `StreamOpTooBig` message; a read after the writable end dropped, or a write after the readable end dropped, traps with Wasmtime's message for that direction. The guest buffer is built eagerly through a boundary context with no borrow scope: when the payload is present and the count is above zero, an unaligned pointer or a range outside the memory traps with Wasmtime's messages naming the pointer of the direction. Then `pair`, the reference's `SharedStreamImpl.read` and `write` over the shared record: the first copy with no pending side becomes the pending side and returns; a copy that finds the other end pending copies at once, the smaller of the two remaining counts, and the later copy completes with that count while the pending copy stays pending and keeps accepting further copies until its event is delivered, its event then reporting the total (the reclaim rule); a zero-length copy completes as soon as the other end is pending with nothing moved; a copy that finds the pending side full completes it and takes its place; a copy whose other end was dropped completes at once with the dropped result and moves this end to `done`. Elements copy one at a time through the two boundary contexts, the writer's lifting from its memory and the reader's lowering into its memory, and an owned handle in the payload moves between the two tables as a call moves one. Completion fills the end's pending event, `Event::copy` in `src/concurrency/event.rs`, with the reference's `pack_copy_result`: the low four bits hold completed (0), dropped (1), or cancelled (2), and the bits above hold the count. With the `async` option the built-in returns the blocked sentinel `0xffffffff` and leaves the event for the waitable set the end joined or a later cancel; without it the copy blocks through the suspend seam (`src/concurrency/suspend_seam.rs`) until the event is set, under the rules PDD020 states, and takes the event before it returns. Dropping an end during a copy traps with the busy message; dropping the first end notifies the other end if it is pending, so its copy completes with the dropped result. Every copy runs under the copy budget. `CopyCause` grows by the variants this card reaches, each with Wasmtime's message.

## Acceptance criteria
- [ ] A pending read keeps accepting writes until its event is delivered, and the event reports the total, proved by a repository test.
- [ ] `closed-stream.wast`, `zero-length.wast`, `partial-stream-copies.wast` in both corpora, `stream-zero-ops.wast`, and `drop-stream.wast` pass whole and their lines leave the list.
- [ ] `stream-big-read-and-writes.wast` passes whole: a count of 2^28 traps with the count message and a buffer past the end of memory traps with the bounds message.
- [ ] The second component of `builtin-trap-poisons-instance.wast` instantiates and its busy-drop directive passes; its two poisoning directives stay deferred for the trap rules.
- [ ] An asynchronous copy returns the blocked sentinel and its event arrives through `waitable-set.wait` as the triple of the stream code, the end's index, and the packed result, proved by a test.
- [ ] The stream write of `streams-massive-send.wast` fails with the copy budget cause and does not exhaust the harness.
- [ ] `lint` passes and `tests all` is green on both targets, any async directive that starts passing has its line removed from the expected-failure list, and every line whose reason this card changes is refreshed from a live run.
