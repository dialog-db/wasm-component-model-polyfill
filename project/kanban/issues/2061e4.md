## What to build
Every call the polyfill itself makes into a guest `realloc` runs as a task with one thread, as the reference lifts `realloc` as a function and invokes it: the host's argument lowering in `Func::call` (`lower_args` in `src/instance/func.rs`, through `BoundaryContext::allocate_aligned` in `src/abi/context.rs`), the lowering of a host function's result into the guest (`src/concurrency/host_result_lowering.rs` and the lower trampoline in `src/executor/trampoline.rs`), and any other realloc call a boundary context makes. Push a task with no function or options (`TaskTables::push_task` with the instance of the memory) and a fresh thread as the current scope before the call, and pop it after, whether the call returned or failed. The thread starts with zero context slots and its slots end with it, so a slot the realloc sets does not reach the export that runs next or the task that made the host call, which is what `task-builtins.wast` asserts at its two realloc directives. Around each realloc call, and around the post-return call in `BoundaryContext::post_return`, clear the instance record's `may_leave` (`src/concurrency/instance_record.rs`, held at `true` today) and restore it after, so a built-in that reads the flag traps with the cannot-leave cause when a realloc or a post-return calls it; `context.get` and `context.set` in `src/executor/intrinsics.rs` do not read the flag. The adapters keep the flags global they compile against; this card moves nothing there. The corpus directives that call built-ins from a realloc close when those built-ins land, so this card proves its rules with repository tests on components written by hand.

## Acceptance criteria
- [ ] A slot set by a realloc during the host's argument lowering is not visible to the export, and a slot set by a realloc during the lowering of a host function's result is not visible to the task that made the call, each proved by a test.
- [ ] A realloc runs on a task with one fresh thread that is the current scope for the call and is gone after it, including when the realloc traps, proved through the store's records.
- [ ] The instance's may-leave flag is clear while a realloc or a post-return runs and set again after, proved by a host function the realloc calls that reads the record through the store; `context.get` and `context.set` succeed from a realloc.
- [ ] `tests all` passes on both targets with the conformance summary unchanged.
