## What to build

Follow-up from the second review of the PDD027 series. A host function's return area is checked for alignment and bounds before the host function runs, as the parameters already are.

- **Today:** when a host function's result spills, or when the lower is asynchronous, the guest passes a return-area pointer. The trampoline reads it with `pointer_argument` (`rust/wcmp/src/executor/trampoline.rs`, `return_area_ptr`), and the result is written there: through `lower_results` (`src/typed/crossing.rs`) on the typed path, and through `write_host_result` on the untyped one. Neither checks the pointer's alignment or bounds.
- **Wasmtime:** traps through `validate_inbounds_dynamic` (`crates/wasmtime/src/runtime/component/func/host.rs:415, 460` at `v49.0.0-rc.1`).
- **The spec:** its `lower_flat_values` traps on a misaligned pointer.
- **Age:** the gap predates the PDD027 series. Review 1 of that series gated the spilled parameters and `task.return` with `abi::check_spilled_address`, but not this third use.

Call `check_spilled_address` on the return area, with the result's size and alignment, before the host function runs, so a refused call never runs the host's code.

## Acceptance criteria
- [ ] A guest calls a typed host function and an untyped one whose results spill, with a misaligned return area and with one past memory. Each fails with "pointer not aligned" or "pointer out of bounds", and the host closure never runs, on both targets.
- [ ] `lint` passes, and `tests all` is green on both targets with the conformance summary unchanged.
