## What to build
`StoreContext::resource_drop` (`src/store/store_context.rs:217-249`) calls a locally-defined resource's core destructor directly, with no turn guard. A destructor that lowers a host `async` import asynchronously gets a noop-waker first poll and leaves a host task no driver runs, for a host that only drops handles; one that lowers it synchronously blocks through the seam and runs a nested turn from inside the host's call with `turn_in_flight()` false throughout, so the recursive-driver rule cannot see it. Wasmtime requires `resource_drop_async` under `run_concurrent` for this shape. The destructor runs under a turn guard with the noop waker, like a guest-initiated drop; a destructor that must wait for a host task fails with the stack-switch cause, the rule every other block without a provider gets. A `resource_drop_async` for Wasmtime parity is a later card when a host needs it.

## Acceptance criteria
- [ ] A locally-defined resource whose destructor lowers a host `async` import that resolves on its first poll completes through the turn, and one whose import stays pending fails with the stack-switch cause, on both targets, proved by tests; `turn_in_flight()` is true while the destructor runs.
- [ ] The docs of `Store::resource_drop` state the rule.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
