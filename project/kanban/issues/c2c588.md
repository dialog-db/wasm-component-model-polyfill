## What to build
`StoreContext::resource_drop` (`src/store/store_context.rs:217-249`) calls a locally-defined resource's core destructor directly, with no turn guard. A destructor that lowers a host `async` import asynchronously gets a noop-waker first poll and leaves a host task no driver runs, for a host that only drops handles; one that lowers it synchronously blocks through the seam and runs a nested turn from inside the host's call with `turn_in_flight()` false throughout, so the recursive-driver rule cannot see it. Wasmtime requires `resource_drop_async` under `run_concurrent` for this shape. Decide whether the destructor runs as a turn (a guard, the drivers' idle rules, and a documented cause when it needs a stack switch) or whether the docs of `Store::resource_drop` state that a destructor dropped from the host must not lower an `async` import, and implement the choice.

## Acceptance criteria
- [ ] A locally-defined resource whose destructor lowers a host `async` import, dropped from the host, either completes through a turn or fails with the documented cause, on both targets, proved by a test; `turn_in_flight()` is true while the destructor runs if the turn route is taken.
- [ ] The docs of `Store::resource_drop` state the rule.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
