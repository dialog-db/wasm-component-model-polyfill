## What to build
Write the PDD for the Wasmtime linker and instantiation features the polyfill lacks. A plugin host resolves a component's imports once and instantiates it many times, inspects a component's import types after substitution, and loads a component whose imports it cannot all supply.

**Reference** (`crates/wasmtime/src/runtime/component/linker.rs`, `instance.rs`):
- `InstancePre<T>` and `Linker::instantiate_pre`.
- `Linker::substituted_component_type`.
- `Linker::define_unknown_imports_as_traps`.
- Subtyping at the host boundary. Wasmtime's linker accepts a host definition whose type is a subtype of the import. The polyfill requires the exact type (README feature table: "Subtyping at the host boundary", ❌).

The PDD must settle these questions:

1. **Pre-instantiation.** Decide what an `InstancePre` fixes once (resolved imports, type checks, compiled adapters) and what each instantiation still does, on both targets. Say what it saves, measured with the benchmark suite. State its interaction with asynchronous compilation in the browser.
2. **Subtyping.** Decide which subtyping rules of the spec apply when a host definition fills an import: width and depth for records, variants, and instance types, and function parameter and result variance. Decide whether they follow Wasmtime's type check exactly, with citations.
3. **Unknown imports.** Decide what a trapping stub is for each import kind (function, resource, instance, core module), and what error a guest sees when it calls one.
4. **Substituted types.** Decide whether a host can read a component's type after the linker's definitions are applied, and in what form.
5. **Serialization.** Decide whether `Component::serialize` or an equivalent (for example, passing a compiled component to a Web Worker) is in scope, or a non-goal with its reason.

The PDD follows `project/design/README.md`: plain English, the six sections, Goals and Non-goals that express scope, and Test Cases that a later card can lift as acceptance criteria. Do not name later PDDs.

## Acceptance criteria
- [ ] The PDD is formatted with `markdown format` and passes the `markdown` flake check.
- [ ] It answers questions 1 to 5, each with its reason and a citation where it follows Wasmtime or the spec.
- [ ] Its Test Cases cover:
  - one `InstancePre` instantiated many times on both targets
  - a host function whose type is a strict subtype of the import accepted, and a non-subtype refused
  - a component with an unsupplied import instantiating under trapping stubs, and the stub's error when called
- [ ] The owner accepts the PDD before any implementation card is filed.
