## What to build

Three narrow robustness gaps the re-review of the driver hardening left. In `src/store.rs`, `run_concurrent`'s `Waiting` arm (around line 355) polls the closure once more and then parks without the `has_ready_item()` re-check the `Idle` arm does, so a final poll that queues an item through the accessor while a host task never wakes parks on ready work; add the re-check (`has_pending_work()` is always true under `Waiting`, so it must be `has_ready_item()` specifically). `turn_in_flight()` (around line 263) maps a poisoned tables lock to an internal error and both driver entries consult it before any `TurnGuard` exists, so a panic that poisoned the tables outside a turn still refuses every later driver; route that check through the same poison recovery `TurnGuard::take` uses. And `exit_task` in `src/resource/tables.rs` (around lines 86-99) runs unwind, undo-lends, and remove in sequence, so a panic between them leaves a half-unwound scope that a later reader sees silently once the poison is cleared; either make that sequence unwind-safe or have the poison recovery mark the tables as needing an unwind. Add a test per item that fails against the current code.

## Acceptance criteria

- [ ] `run_concurrent` does not park under `Waiting` while a ready item exists, proved by a test.
- [ ] A driver entered after a panic that poisoned the tables outside a turn succeeds, proved by a native test.
- [ ] A panic inside `exit_task` cannot leave a scope half-unwound for a later reader, proved by a native test.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
