## What to build
From card cd850a (landed as `b12d9f7a5`), confirmed by its reviewer. A stack-switch cause raised inside a lowered import, a built-in, or a start intrinsic reaches the host as text: `invocation_failed` (`src/executor/trampoline.rs:485-487`) wraps it as `anyhow!("trampoline invocation failed: {err}")`, reached through the finish closure (`trampoline.rs:1087-1090`; `suspend_seam.rs:354` hands the error to finish). The built-ins flatten it the same way (`waitable_builtins.rs:488-499`, `thread_builtins.rs:788-790`), and `start_call.rs:483` -> `backend.rs:28-30` wraps it as `Error::Instantiation(InstantiationError::SubstrateFailure(..))`. PDD022 says a host uses `Engine::suspend_provider()` to explain a stack-switch failure, but a host cannot match the failure structurally: the smoke test's downcast arm (`rust/wcmp-smoke/src/lib.rs:2037`) is dead for all three suspending shapes, and only its text match (`:2032`) fires. Related, pre-existing: a call's trap surfaces as "instantiation error: ...failed to instantiate".

Carry the scheduler cause through the trampoline and backend so a host receives `Error::Scheduler(SchedulerCause::StackSwitchNeeded)` (and the other scheduler causes) as a typed error, on both targets.

## Review notes

- 2026-10-05 implemented in `fix(error): Carry a guest-raised failure to the host as its own cause`, with 9e2c72 (merged here, as the triage suggested).
  - Owner decision (asked in session): the host gets `Error::Scheduler(cause)` itself, rendered as Wasmtime renders a trap, `wasm trap: <cause>`, for the causes a guest traps with (Deadlock, CannotBlock, StackSwitchNeeded); RecursiveDriver and StoreNotInPoll keep `scheduler error: `. TableFull keeps `scheduler error: ` too, a deviation from what was offered: Wasmtime raises it as `ResourceTableError::Full`, not a trap, so Wasmtime's text keeps it without the prefix.
  - Mechanism: the trampoline and every built-in family's `trap` helper (waitable, copy, thread, yield, end, error-context) trap the guest with the `Error` itself rather than its text; the runtime layer hands a host function's error back unchanged on every backend (`TrapKind::Host`), so the new `call_failure` downcasts it and returns it as raised. `call_failure` serves every call into a guest (thread entries, start intrinsic, post-return, task.return crossing, thread starts, the providers' resumes) and turns any other failure into the new `Error::Trap` (transparent: Display and source are the trap's, `wasm trap: ...`). `substrate_failure` stays for compile and instantiate and still gives `Instantiation(SubstrateFailure)`, so a core start function's failure is still an instantiation error (its carried cause reachable by downcast in the chain). A resource destructor's failure passes through as raised (a host destructor's own error, or a polyfill cause from a guest destructor); a guest destructor's own trap reads `resource destructor failed` with the trap as its source.
  - Tests: the three stack-switch shapes now match the value (`sync_lower.rs` lowered import, `thread_yield.rs` built-in in a callee, `nested_start.rs` start intrinsic); `it_reports_a_guest_trap_of_a_call_as_the_trap_and_not_as_an_instantiation_error`, `it_still_reports_a_trap_of_a_core_start_function_as_an_instantiation_error`; error render tests pin `Trap::AsyncDeadlock`/`CannotBlockSyncTask` text exactly. Three tests that pinned the old wrapping now match the structured error.
  - Smoke: `needs_stack_switch` matches `Error::Scheduler(SchedulerCause::StackSwitchNeeded)` by value; the text fallback is gone.
  - 6e247b: an event pointer whose pair leaves the memory fails with `AbiError { Argument(1), U32, OutOfBoundsMemory { offset, length: 8 } }`, checked whole before either word is written (Wasmtime's rule; the doc names the reference's partial write). The poll is one `poll_waitable_set` call. The straddle "writes nothing" is pinned: the test pokes a word at 65532 first and, since the trap poisons the store, reads it back from the host through the instance's memory; it is unchanged after both the wait and the poll.
  - Corpus: summary unchanged (native 2409/2440). Reasons refreshed from a live `tests regenerate`; 17 overlay lines and 1 shared line that still carried the old `instantiation error: ...` chains were cut to a tail first so the run's reasons replace them, and the hand-written `task-deletion.wast:311` line now says the call reports the deadlock cause itself (main names the same seam cause there; only the wrapping changed). `expected-failures.web.txt` line 10 now quotes the trap itself; line 6 is a compile refusal and still an instantiation error, as before.
