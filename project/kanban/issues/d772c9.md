## What to build
From card cd850a (landed as `b12d9f7a5`), confirmed by its reviewer. A stack-switch cause raised inside a lowered import, a built-in, or a start intrinsic reaches the host as text: `invocation_failed` (`src/executor/trampoline.rs:485-487`) wraps it as `anyhow!("trampoline invocation failed: {err}")`, reached through the finish closure (`trampoline.rs:1087-1090`; `suspend_seam.rs:354` hands the error to finish). The built-ins flatten it the same way (`waitable_builtins.rs:488-499`, `thread_builtins.rs:788-790`), and `start_call.rs:483` -> `backend.rs:28-30` wraps it as `Error::Instantiation(InstantiationError::SubstrateFailure(..))`. PDD022 says a host uses `Engine::suspend_provider()` to explain a stack-switch failure, but a host cannot match the failure structurally: the smoke test's downcast arm (`rust/wcmp-smoke/src/lib.rs:2037`) is dead for all three suspending shapes, and only its text match (`:2032`) fires. Related, pre-existing: a call's trap surfaces as "instantiation error: ...failed to instantiate".

Carry the scheduler cause through the trampoline and backend so a host receives `Error::Scheduler(SchedulerCause::StackSwitchNeeded)` (and the other scheduler causes) as a typed error, on both targets.

## Acceptance criteria
- [ ] A stack-switch failure raised inside a lowered import, a built-in, and a start intrinsic reaches the host as `Error::Scheduler(SchedulerCause::StackSwitchNeeded)` on both targets; tests prove each.
- [ ] A call's trap no longer surfaces as an instantiation error.
- [ ] The smoke test's typed-cause arm matches, and its text fallback is removed or documented.
- [ ] `tests all`, `tests smoke native`, `tests smoke check` and `lint` are green.
