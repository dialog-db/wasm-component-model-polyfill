## What to build
Twice on 2026-09-25 (cards 6977d0 and b588ed, in sandbox guests) a `tests web debug` lane ran every test green and then exited non-zero from the browser pool's EXIT trap:

`rm: cannot remove .../wbg-pool/work-<n>/browser-profile: Directory not empty`

It is a teardown race: Chrome is still writing to its profile directory after `wbg-pool daemon --stop` returns, so the trap's `rm -r` sees a new file appear. A rerun of the lane alone was green both times. A green run that reports FAILED sends an agent after a phantom failure.

Make the teardown wait for Chrome to exit before removing the work directory, or retry the removal, so a lane's exit status reflects its tests.

## Acceptance criteria
- [ ] The browser pool's teardown waits for the browser process to exit (or retries the removal) before it removes the work directory.
- [ ] A lane whose tests all pass exits 0 even when Chrome exits slowly; say how this was exercised.
- [ ] `tests all` and `lint` are green.
