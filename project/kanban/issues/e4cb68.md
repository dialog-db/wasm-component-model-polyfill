## What to build
Add a `Task` variant to `wcmp::Error` in `src/error.rs`, next to `Scheduler` and `Waitable`, carrying a `TaskCause` with seven causes: `NoResult` (the implicit thread exited and the task had not returned; Wasmtime's `NoAsyncResult`, "async-lifted export failed to produce a result"), `ReturnedTwice` (`task.return` ran on a resolved task; `TaskCancelOrReturnTwice`, "`task.return` or `task.cancel` called more than once for current task"), `ReturnMismatch` (the result type or the options of `task.return` differ from the lift; `TaskReturnInvalid`, "invalid `task.return` signature and/or options for current task"), `ReturnFromSynchronousTask` (`task.return` ran in a task whose lift is not `async`; Wasmtime has no trap for it, so the message is the polyfill's own and the doc says so), `UnsupportedCallbackCode` (a status word whose code is above two; "unsupported callback code"), `BackpressureOverflow` (the counter left its range in either direction; "backpressure counter overflow"), and `CannotLeave` (a built-in that reads the may-leave flag ran while it was clear, from a realloc or a post-return; `CannotLeaveComponent`, "cannot leave component instance"). Each message is the trap `wasmtime-environ` prints, so the conformance corpora match it by substring; pin the six Wasmtime-backed messages to `wasmtime_environ::Trap` the way `it_pins_the_waitable_causes_to_the_traps_wasmtime_environ_renders` pins the waitable causes. Mark the enum `#[non_exhaustive]`, re-export `TaskCause` from `lib.rs` with the other causes, and list the variant in the error docs. Nothing raises the causes yet; the built-ins that do are later cards.

## Acceptance criteria
- [ ] `Error::Task(TaskCause)` exists with the seven causes, and each cause renders as the message above.
- [ ] A pinning test proves that the rendered message of each Wasmtime-backed cause ends with the message `wasmtime_environ::Trap` renders for it, so a wording change upstream fails the test.
- [ ] `TaskCause` is re-exported from `lib.rs`, and the docs of the return-from-synchronous-task cause say the message is the polyfill's own.
- [ ] `lint` passes, and `tests all` is green on both targets with the conformance summary unchanged.
