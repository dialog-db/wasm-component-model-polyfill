## What to build
Card `7165b0` gave `TypedFunc` a direct crossing for `String` and numeric `Vec<T>` that never builds a `Val` per element. Its reviewer found the code correct and named the cases no test reaches through `TypedFunc`, although the code they exercise is shared with the untyped path:

- A typed `String` under the `utf16` and `latin1+utf16` string encodings. These fall back to `strings::encode`/`decode`; the echo guest in `tests/baseline_typed_direct.rs` is UTF-8 only.
- The typed spilled-parameter `store()` path, reached by more than sixteen flat parameters.
- Typed-path traps: invalid UTF-8, a `char` above 0x10FFFF or a surrogate in a `Vec<char>`, and a misaligned list pointer. Each must carry the same message the untyped path gives.
- A typed `call_concurrent` carrying a `Vec<u8>` and a `String` (the only typed concurrent test today is `(u32,) -> u32` in `baseline/call_concurrent.rs`).

The reviewer also noted that a numeric `Vec` wider than a byte (`u32`, `f64`, and so on) costs two host copies per direction, an encode or decode buffer plus the substrate copy, where `Vec<u8>` costs one. Measure `list-u32` typed before deciding whether a single-copy path for wider numbers is worth building; record the numbers here.

## Acceptance criteria
- [ ] Each case above has a test through `TypedFunc` that passes on both targets and would fail if the direct path diverged from the untyped one.
- [ ] The cost of a wide numeric typed `Vec` is measured on both targets and recorded on this card, with a decision on a single-copy path.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
