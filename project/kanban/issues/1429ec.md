## What to build

Three browser tests that assume Chromium's behavior hold in WebKitGTK too,
or say which browser they describe.

`tests webkit debug` (a23124) finds them failing only in WebKitGTK 2.54.1
(each also fails on a page of its own):

- `wcmp-wasm-core-web::web`: `it_compiles_and_instantiates_a_module_above_the_synchronous_limit`.
  The test expects the synchronous `Module::new` of a module above 8 MiB to
  fail, which is V8's limit on the main thread. JavaScriptCore has no such
  limit and compiles it: `Ok(Module { .. })`.
- `wcmp-wasm-core-web::web`: `it_lends_a_copy_of_a_shared_memory`.
  `assertion failed: buffer.is_instance_of::<SharedArrayBuffer>()`: the
  buffer of a shared memory is not a `SharedArrayBuffer` in a page that is
  not cross-origin isolated in WebKitGTK.
- `wcmp-wasm-core-web`: `accessor::tests::it_loads_a_scalar_with_no_javascript_frame_on_the_stack`.
  The test reads the frames of `Error.stack` as lines that start with
  `at `, which is V8's format. JavaScriptCore writes `name@url`, as in
  `3@wasm-function[3]`, so the test finds no frame.

For each, decide whether the backend's behavior differs (and the polyfill
or its docs must answer it) or only the test's reading of the browser does.

## Acceptance criteria
- [x] Each of the three passes in `tests webkit debug`, and still checks
      what it checked in Chrome.
- [x] Where WebKit's behavior differs in a way a host sees, the backend's
      docs say so.
- [x] `lint` passes, and `tests all` is green.

## Review notes

- 2026-10-19 (implementer): each difference is the browser's, not the
  backend's. (1) JavaScriptCore has no synchronous compile limit; the test
  expects Chromium's refusal in V8 and a module in JavaScriptCore, and the
  crate docs say so. (2) The lane's pages are cross-origin isolated
  (`crossOriginIsolated` is true, the stock runner sends COOP/COEP) and the
  buffer's brand is `[object SharedArrayBuffer]`, but WebKitGTK 2.54 leaves
  the global `SharedArrayBuffer` undefined, so `instanceof` fails. The test
  reads the brand, and the crate docs tell a host. (3) JavaScriptCore
  writes frames as `name@where` and names no module made from bytes (as
  `3@wasm-function[3]`); the test reads both formats, and in
  JavaScriptCore checks that a frame outside the polyfill lies between the
  load and the caller.

- 2026-10-19 (implementer): gates on the tip (kanban `de056af7`): `lint`
  passes, and `tests all -j 6` passes every lane, the WebKitGTK lanes
  among them (`webkit debug` 1854 tests in 103 s, `webkit no-provider`
  169 in 20 s, `fidelity webkit` 265 in 27 s).

- 2026-10-19 (peer review, round 1): ACCEPT, three non-blocking findings:
  the JavaScriptCore stack check is weaker than V8's (stated in the notes
  above); the missing `SharedArrayBuffer` global became upstream card
  4937a1, with proposed issue text; a long doc line rewrapped.

- 2026-10-19 (peer review, round 2): ACCEPT; the round-1 answers hold.
