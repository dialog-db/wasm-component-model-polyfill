## What to build
Write the PDD for typed component values in Rust. A host passes a WIT record as a Rust struct, a variant or enum as a Rust enum, and a resource as a typed handle, through `func_wrap`, `func_wrap_concurrent`, and `TypedFunc`, as a Wasmtime host does with `#[derive(ComponentType, Lift, Lower)]` (`crates/component-macro/src/lib.rs`) and `flags!`.

This splits question 3 (the derive) and the typed half of question 4 (resources) out of 3200e7, as that card allows. Bindgen generates code against the contract this PDD sets, so 3200e7 is blocked on this card. The WASI host (da3054) needs the same contract.

**Today.** The typed path covers primitives, `String`, `Vec<T>`, `Option<T>`, `HashMap<K, V>`, stream and future readers, and tuples, through `ComponentValue`, `ComponentParameters`, and `ComponentResult`. Anything else is a `Val` tree. Resources are `HostResource<T>`, `ResourceHandle`, and `ResourceTypeId`, with `Store::resource_new` and `Store::resource_drop`. The polyfill has no `Resource<T>`, `ResourceAny`, or `ResourceTable`, as Wasmtime has (`crates/wasmtime/src/runtime/component/resources/any.rs`, `resource_table.rs`).

The PDD must settle these questions:

1. **The derive's contract.** Decide how the derive checks a Rust type against a component type: structural equality, field and case names, renames, and when the check runs. Decide how it relates to `ComponentValue`: extend it, replace it, or sit beside it. Say whether it keeps the `Val` round trip or lifts and lowers directly, and give the cost of each, measured with the benchmark suite.
2. **Attribute and macro parity.** Mirror `#[component(record)]`, `#[component(variant)]`, `#[component(enum)]`, `#[component(name = ...)]`, and `flags!`, or state each difference and its reason.
3. **Resources.** Decide how `Resource<T>`, `ResourceAny`, and `ResourceTable` map onto `ResourceHandle`, `ResourceTypeId`, and `HostResource<T>`, including the shared type identity that PDD013 set. Decide how `own<T>` and `borrow<T>` fields in a derived type behave, and whether the current names stay, become aliases, or are replaced.
4. **Every value type.** Cover `map`, fixed-length lists, `stream`, `future`, and `error-context` in derived types.
5. **Both targets.** The derive and its generated code compile and behave the same natively and for `wasm32-unknown-unknown`.

6. **Two constraints the checkup of 2026-09-21 found (moved from 3200e7).**
   - `ResourceType` equality is by label alone (`src/types/resource_type.rs`). So two resources named `error` from different interfaces compare equal in `ValueType`. Identity at run time is by `ResourceTypeId`, and the mapping of `own<T>` and `borrow<T>` must rely on that instead.
   - The typed path converts through `Val` (`src/instance/typed_func.rs:90, 126-129`), at about forty bytes per `u8`. The `Lower` and `Lift` contract must lower a numeric list or a string without a `Val` per element.

The PDD follows `project/design/README.md`: plain English, the six sections, Goals and Non-goals that express scope, and Test Cases that a later card can lift as acceptance criteria. Do not name later PDDs.

## Acceptance criteria
- [ ] The PDD is formatted with `markdown format` and passes the `markdown` flake check.
- [ ] It answers questions 1 to 6, each with its reason and, where it follows Wasmtime, a citation.
- [ ] Its Test Cases cover:
  - a record and a variant crossing both directions as Rust types on both targets
  - a type mismatch refused at `typed` or `func_wrap` with a structured error
  - a resource passed as `Resource<T>` and as `ResourceAny`
  - a derived type with `own` and `borrow` fields
  - flags through `flags!`
- [ ] The owner accepts the PDD before any implementation card is filed.
