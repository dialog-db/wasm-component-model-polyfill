## What to build

Non-blocking findings from the independent review of 5b4e90 (browser host suspension with JSPI, landed `cf3cb439a`), in `rust/wcmp-wasm-core-web` and `rust/wcmp-wasm-core-contract`:

- **Weak refusal test.** `suspension.rs:240-247` asserts only `Err(Error::Trap(_))` for a suspension in a host frame. The browser's own `SuspendError` would also show up as a trap, so the test cannot tell a correct backend from a leaky one. Assert `TrapKind::Host` with the "cannot suspend" message on the inner call, and add a guest `try_table`/`catch_all` to prove no guest can catch it.
- **Store dropped mid-run.** Add a test where the store drops while a resumed call runs to its end, not only to its next suspension; this exercises `WebStore` dropping inside `end()`.
- **Probe timing.** `jspi.rs:58` resolves `WebAssembly.Suspending` at the first suspending `func_new`, not when the engine is made, a small departure from the PDD ("reads each JSPI function when it makes an engine").
- **Refused resume loses the call.** `resume(self)` consumes the handle, so a refused resume (wrong store, value check, resume inside a host function) drops the call. Consider an error that carries the handle back. This touches the core contract; the owner decides.
- **Conventions.** `flight.rs` has two public types (`Flight`, `Stop`).

## Acceptance criteria
- [ ] The host-frame refusal test asserts the kind and message and proves no guest catches it.
- [ ] A test drops the store while a resumed call runs to its end.
- [ ] The JSPI functions are read when the engine is made, or the crate docs say why not.
- [ ] The owner has decided on the refused-resume handle, and the code follows.
- [ ] `tests all` and `lint` pass.
