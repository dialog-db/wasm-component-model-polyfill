## What to build

The vendored Wasmtime tests move from `cb091c33cece` to `v50.0.0`, and the
spec tests move from `e5ee0af9c617` to `2f1e56f`. Wasmtime 50 pins
`5b724da`, but its runtime follows spec #726, and the tests of that behavior
start at `2f1e56f`. That commit also deletes `cancel-yield-loop.wast` and
`cancel-instance-wide-resume.wast`. The new files cover behavior this port changes: `same-instance-call`,
`realloc-may-leave`, `sync-lower-async-typed-entry-checks`, the next-switch
set (`threading-and-yields`, `sync-task-exit`, `variant-second-call`,
`default-flags-*`, `sync-callee-exit-drops-fiber`), and the spec's
`idle-drop`, `cancel-not-delivered`, and `forward`.

Wasmtime 50 names the direction in its copy trap texts (`423da9bcb`). The
polyfill's texts follow (`executor/copy.rs:485-492`, `error.rs:1613`,
`:1619`), and the harness drops the relaxation that mirrored the old texts
(`tests/conformance.rs:1368-1373`).

The comment in the harness that says Wasmtime's runner matches error text for
the spec tests is wrong. Wasmtime ignores the text for those tests
(`tests/wast.rs:220-224`). The polyfill keeps its strict check, and the
comment says so.
