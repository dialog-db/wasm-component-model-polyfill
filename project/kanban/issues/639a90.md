## What to build
Revise `block_on_host_task` in `src/store/store_context.rs`. PDD018 let a synchronous lower of a host `async` function succeed only when the first poll resolved the future or a provider filled the seam, and the function fails the call with the stack-switch cause when the slot is empty. Under the revised blocking rules the block runs through `SuspendSeam::suspend` on every target, with the blocked call's own future polled at every check of the condition, so the nested turn serves it: a future that is pending once and then ready, as one that yields once does, resolves inside the nested turn and the call returns its result through the synchronous lower's flat results. A future that stays pending leaves the store waiting, so the call fails with the stack-switch cause from an async-typed caller and with the cannot-block cause from a sync-typed task that has not returned, both from the seam's cause selection. The subtask's resolution is delivered as the synchronous lower returns, which releases the handles the guest lent. The provider path stays as it is. Update the docs on the function and on `LowerKind` so neither says the call fails as it always has, and say that the blocked task's future is polled from the condition.

## Acceptance criteria
- [ ] A synchronous lower of a host `async` function whose future is pending once and then ready returns its result, proved on a hand-written component.
- [ ] A future that stays pending fails with the stack-switch cause when the caller is an async-typed task, proved by a test.
- [ ] A future that stays pending fails with the cannot-block cause when the caller is a sync-typed task that has not returned, proved by a test.
- [ ] Handles lent for the call are released when the synchronous lower returns, proved by a test.
- [ ] `lint` passes and `tests all` is green on both targets, and any async directive that starts passing has its line removed from the expected-failure list.
