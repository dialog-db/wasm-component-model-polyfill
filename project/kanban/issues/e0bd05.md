## What to build

An expected failure of the fidelity suite matches the failure's reason, not
only its directive, so that a listed directive that fails for another
reason fails its script's test.

Today an entry names `<script>:<line>` and the harness accepts any failure
there (`rust/wcmp-wasm-core-fidelity/src/check.rs`). JavaScriptCore's list
(970834) holds 1995 entries, 1795 of them one cause: `call_indirect to a
signature that does not match`, which names more than one kind. A
regression on any of those lines, such as a trap of another kind or a host
error, would pass unseen. The review of 970834 raised it.

Let an entry say what the failure must show, for example the engine
message that the backend reports as `Other`, and hold the run to it. The
V8 list has the same shape and gains the same check.

## Acceptance criteria
- [ ] A listed directive that fails with a reason other than its entry's
      fails the script's test, and a test shows it.
- [ ] Both browser lists, and the native lists, state the reasons the check
      reads, and `tests fidelity web`, `tests fidelity webkit`, and the
      native fidelity lanes pass.
