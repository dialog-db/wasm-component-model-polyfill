## What to build

Non-blocking findings from the independent review of 127919 in `rust/wcmp-wasm-core`:

- `HostFunc` bodies and `ExternRef::new` require `Send + Sync` on `wasm32` too (`src/func/host_func.rs`, `src/values/extern_ref.rs`). Use the crate's `MaybeSend`/`MaybeSync` split, as the store and futures already do.
- `backend::RawHandle` and `backend::RawTypeHandle` let a host forge or read a handle, so `TypeHandle` is opaque by convention only. Hide them from the host API (for example `#[doc(hidden)]`), or state why they are public.
- `Memory::size` returns bytes, as the PDD says, while Wasmtime's `Memory::size` returns pages. Say so in its doc comment, or pick a name that cannot be misread.
- `BackendSuspendedCall::into_any` returns a `Box<dyn Any>`, which is not `Send`, so a native backend must downcast before it builds its `Send` future. Document it, or return `Box<dyn Any + Send>` natively.

## Acceptance criteria
- [ ] Each item is fixed or documented, with the choice stated in the commit or the doc comment.
- [ ] `tests all`, `lint` and `cargo package -p wcmp-wasm-core` pass.
