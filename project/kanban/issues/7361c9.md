## What to build
Map `Trampoline::BackpressureInc` and `BackpressureDec` in `src/executor/translate.rs` to specs in `src/executor/ir.rs` and build them in `src/executor/instantiate.rs`, resolving the trampoline's instance to an `InstanceId` the way `enter_sync_call_arguments` in `src/executor/intrinsics.rs` does. `backpressure.inc` adds one to the instance record's `backpressure` counter (`src/concurrency/instance_record.rs`) and traps with the backpressure-overflow cause when the counter reaches 65536; `backpressure.dec` subtracts one and traps with the same cause when the counter would fall below zero. Neither reads the may-leave flag, because the reference exempts them and the corpus proves that a realloc can call them. The gate already lives in `Scheduler::enter_implicit_thread` and `open_entry_gate`: a task of an `async` function type whose instance's counter is above zero waits at the gate until the counter returns to zero, and a synchronous export ignores the counter; make sure a `dec` that brings the counter to zero lets the next turn open the gate. `backpressure-overflow.wast`, `sync-call-context.wast`, and `sync-call-context-slots.wast` fail today only because these two trampolines are refused; they pass whole after this card, and so do the two components of `task-builtins.wast` that each define only one of the built-ins.

## Acceptance criteria
- [ ] `backpressure-overflow.wast` passes whole: the counter traps at both ends of its range with the backpressure-overflow cause and survives 65535 increments.
- [ ] `sync-call-context.wast` and `sync-call-context-slots.wast` pass whole: synchronous calls between components keep their context slots when the callee raises and lowers backpressure inside the call.
- [ ] A test queues two tasks through the store's records and proves that an `async`-typed task waits at the gate while the counter is above zero and starts when the counter returns to zero, and that a synchronous task ignores the counter.
- [ ] Both built-ins succeed when a realloc calls them, proved by a test.
- [ ] `tests all` passes on both targets, and any async directive that starts passing has its line removed from the expected-failure list.
