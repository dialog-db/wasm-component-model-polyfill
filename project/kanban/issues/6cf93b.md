## What to build

A host can run its own housekeeping once per turn of a store.

Some host libraries need to be polled to make progress. wgpu-core calls a
callback (a map's, or `on-submitted-work-done`'s) only when the host polls its
device after the work is done. `wasi-webgpu-wasmtime` polls only inside
`map-async`, so in the `wasi:webgpu` spike (`~/Git/github.com/cdata/wasi-webgpu-test`)
an `on-submitted-work-done` alone never resolved. A guest that read back right
after a submit waited for frames and mapped a throwaway buffer to make the
device poll (`rust/guest-probe/src/fingerprint.rs`). Each such host would
otherwise need a layer over each function, or a timer of its own.

Design a hook the embedder registers on the store, which the polyfill runs once
per turn, or when a turn would otherwise go idle with host tasks pending. It
gets the host data, and may wake host tasks.

## Acceptance criteria
- [ ] A hook registered on a store runs once per turn on both targets, and can
      reach the host data.
- [ ] A host future that waits on a callback the hook makes fire resolves with
      no other poll, on both targets.
- [ ] A store with no hook behaves as before: the concurrency tests pass
      unchanged.
- [ ] `lint` passes, and `tests all` is green on both targets with the
      conformance summary unchanged.

## Review notes


- 2026-10-18 (owner, recorded by the implementer): Deferred, for the
  reason d7cde2 was. Wasmtime has no per-turn hook, so a host that runs
  on both runtimes polls its device from a task of its own on Wasmtime
  anyway (for example a tokio task beside `run_concurrent`). The same
  works on the polyfill now that 06f71b gives a host task's first poll
  its own waker: a loop the host runs (a timer, or `spawn_local` in the
  browser) polls the device, and the callbacks wake the tasks that wait
  on them. The hook would be an ergonomic extension only.
