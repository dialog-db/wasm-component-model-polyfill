## What to build
PDD022's "The Cause of a Failed Block" now scopes rule 1 to one instance, as the reference and Wasmtime do. Found by card ee45f4's implementor and confirmed by its reviewer.

Today `store_data.rs` `any_must_not_block` scans `may_not_suspend` across every instance in the store, so a block anywhere fails with the cannot-block cause while any instance has a sync-typed call in progress. The reference traps a sync-typed call only when it blocks before it returns a value and no other thread of the same instance is ready (`CanonicalABI.md` "canon lift", lines 3558-3563 at e5ee0af). Wasmtime v49 keeps a `do_not_suspend` flag per instance and `switch_if_may_not_suspend` reads only the blocked thread's own instance (`concurrent.rs:2059-2073`). A start intrinsic that begins an async-typed callee clears that flag on the callee's instance until the callee returns or suspends (`concurrent.rs:3249-3262`). The store-wide scan (`any_may_not_suspend`, `concurrent.rs:2473-2500`) only names the error of an idle store (`concurrent.rs:1402-1415`): cannot-block if any instance must not suspend, else deadlock.

Effect in the corpus: `reentrance.wast:557`'s component gets the cannot-block cause when it runs alone, where the reference and Wasmtime permit the block (ee45f4's notes; `reentrance.wast:685` meets the callee left by line 429 first today).

Make rule 1 read the blocked thread's own instance, clear the flag on an async-typed callee's instance while a start intrinsic runs it (restore it when the callee returns or suspends), and keep the store-wide view only for naming an idle store's error. Keep the try part's "run the instance's own ready threads first" behavior.
