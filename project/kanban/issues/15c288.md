## What to build

PDD026, "The Todo Model". The business logic of the todo list, in Rust, in the service worker.

- Implement the `demo:todo/model` interface as host functions that route components import: `query`, `add`, `update`, `remove`, `toggle-all`, `clear-completed`.
- It trims titles, refuses an empty title (`empty-title`), assigns ids, filters, and counts. An unknown id is `not-found`.
- It stores the list in IndexedDB. Its functions are async because IndexedDB is async.
- Add the `demo:todo` WIT to the demo's source bundle.

## Acceptance criteria
- [ ] The todo model enforces its rules. Adding an empty title fails with `empty-title`. Adding a title with spaces at both ends stores the trimmed title.
- [ ] `query` filters by `all`, `active`, and `completed`, and its counts are right.
- [ ] `update` and `remove` of an unknown id fail with `not-found`.
- [ ] A new model over the same IndexedDB database reads the same list.
- [ ] `tests all` and `lint` pass.
