## What to build
The `wasmtime` subject. A native program runs each compiled scenario through Wasmtime's component API as a build step, before either polyfill lane, and writes the observations and the Wasmtime stage.

- Add `wasmtime-wasi` at the version the workspace pins for `wasmtime` (`=49.0.0-rc.1`) to `[workspace.dependencies]`.
- For each scenario: `Component::new`, a Wasmtime `Linker` with the p2 and p3 WASI imports from `wasmtime-wasi`, standard output captured in memory, instantiation, and each call from the expectations file, untyped.
- Define the fixed test interface on Wasmtime's `Linker`: one function that takes a string and returns it. Scenario 7 imports it later.
- A scenario at the `compile` stage runs nothing, and the Wasmtime stage is `compile`.
- Write the observations and the stage as build products, judged by the scenario model. Nothing here is committed.
- Add scenario 1's expectations file (its untyped call).

Zena's own flake pins a different Wasmtime. That version never enters these tests.

## Acceptance criteria
- [ ] Scenario 1 runs under Wasmtime in the build, and its observations and stage are a build product.
- [ ] A scenario whose program fails its expectations file under Wasmtime records a Wasmtime stage before `pass`.
- [ ] Standard output is captured in memory and compared with the expected output lines.
- [ ] Only the workspace's Wasmtime is used.
- [ ] `lint` passes.
