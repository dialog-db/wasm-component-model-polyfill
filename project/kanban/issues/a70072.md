## What to build
The review of card `657c60` accepted the two real-toolchain fixtures and named the value shapes the rich world does not reach. The `rich` fixture's widest export flattens to twelve, so no export or import exceeds `MAX_FLAT_PARAMS`, and the indirect *parameter* spill path is untouched (the indirect result path is exercised, since `drawing` returns twelve flats). No string anywhere in the fixture is multi-byte, so the UTF-8 lift and lower boundaries are untested by the one fixture built to test real bindings. Nothing reaches `char`, `u64`, `s64`, either float, a tuple, flags wider than thirty-two bits, `option<option<T>>`, or a bulk `list<u8>`. Extend the rich world and its assertions to cover those, keeping the existing shapes; the fixture's build script and its reproducibility are already settled, so this card is WIT and assertions. Two other items the review left: the card's optional second language toolchain was skipped because this flake's nixpkgs has neither `wasi-sdk` nor `componentize-py`, so a guest from a second language needs a pin decided first; and `wasm-tools` is on the PATH only inside the `fixtures` command, so inspecting a built fixture (`wasm-tools component wit rich/rich.wasm`) has no menu route.
