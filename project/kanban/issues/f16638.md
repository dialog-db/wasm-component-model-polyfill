## What to build
Chrome refuses a synchronous `new WebAssembly.Instance` on the main thread when the module is larger than 8 MB, as it refuses a synchronous `new WebAssembly.Module`. Card `3839ef` made every core module compile asynchronously, so a component with a module above 8 MB now compiles in the browser, but instantiation still goes through the synchronous constructor (vendor `instance.rs:50-56`) and fails. The existing test `it_loads_a_component_larger_than_the_synchronous_compile_limit` uses 1 MiB, under Chrome's limit, so it exercises neither path.

Instantiate core modules with `WebAssembly.instantiate(module, imports)` where the browser needs it, which returns a promise, and thread that through the polyfill's instantiation. The Component Model instantiates core modules in order and a later module's imports can name an earlier one's exports, so the asynchronous step has to keep that order.

Found by the implementor of card `3839ef`.

## Acceptance criteria
- [ ] A component with a core module larger than 8 MB instantiates and runs in the browser, proved by a web test that fails on the current code.
- [ ] `it_loads_a_component_larger_than_the_synchronous_compile_limit` uses a module above the limit, so it exercises the asynchronous compile.
- [ ] Native instantiation is unchanged.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.

## Review notes

- 2026-09-28: cancelled. PDD025 (Runtime Layer, drafted from f259d6) makes asynchronous instantiation first-class on every backend. Its criterion is a PDD025 test case (a module above 8 MB compiles and instantiates in Chromium). See f259d6.
