## What to build
The two review rounds of card `7feb91` accepted the one may-leave flag and left findings that need one card. First, one sentence in the doc at `src/executor/trampoline.rs:205-206` says the defining instance is reached through a lift "which gates on may-enter rather than may-leave"; the vendored spec has no may-enter flag on that path — the callee gate is `Task.enter_implicit_thread`'s backpressure wait (`definitions.py:420-432`), applied only to an async lift, and a destructor is lifted synchronously (`:2217-2220`); Wasmtime does `enter_sync_call_inline(def.instance)` (`crates/cranelift/src/compiler/component.rs:1144`). Reword to "which applies no may-leave gate of its own". Second, coverage: `task.return`, `thread.yield` and the waitable-set built-ins now read the shared global but no test drives a cannot-leave refusal through any of them (a pre-existing gap the card did not close). Third, a residual the owner should know is stated somewhere: `BoundaryCall` no longer restores the flag in `Drop`, so a panic that unwinds past a guard leaves the instance unable to leave for good in a release build (the debug assertion stands down while panicking); state that in the type's doc, or make the guard `#[must_use]`-shaped so a new call site cannot drop it silently.

## Acceptance criteria
- [ ] The doc at `trampoline.rs:205-206` states what the spec and Wasmtime do on the destructor path without naming a flag that does not exist.
- [ ] A test drives a cannot-leave refusal through `task.return`, through `thread.yield`, and through one waitable-set built-in, on both targets.
- [ ] The panic-past-a-guard residual is stated on `BoundaryCall`'s doc, or the guard type makes a silent drop a compile-time or debug-time error at every construction site.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
