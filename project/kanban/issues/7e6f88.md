## What to build
Make `Component::new`, `Linker::instantiate`, `Func::call`, and `TypedFunc::call` `async fn` as PDD005 states. On the web, compile core modules with `WebAssembly.compile` instead of the synchronous constructor, through the runtime layer (propose the trait extension upstream and carry it in the patched backend meanwhile). On native the futures complete without suspending. Update every test and the crate documentation example to await.

## Acceptance criteria
- [ ] Every public entry point that compiles, instantiates, or calls guest code returns a future.
- [ ] A component larger than Chrome's synchronous-compile limit loads on the main thread in the browser test lane.
- [ ] `tests all` passes on both targets.
- [ ] The crate documentation example compiles and runs as a doctest.


## Review notes

- Implemented on the host, 2026-09-15. `Component::new`,
  `Linker::instantiate`, `Func::call`, and `TypedFunc::call` are
  `async fn`. Native 216 tests, web 173, doctest green, `nix flake
  check` green, `smoke native` 6/6.
- In the browser, `Component::new` compiles every core module with
  `WebAssembly.compile` before the runtime layer's `Module::new`. The
  runtime layer's `WasmModule::new` is synchronous and its `Module`
  cannot wrap a backend module built elsewhere, so the vendored backend
  gained patch 6: `Engine::precompile(bytes)` compiles asynchronously
  and keeps the result keyed by the bytes, and `Module::new` takes it
  instead of calling the synchronous constructor. The upstream proposal
  is an asynchronous constructor on `WasmModule` itself; that belongs
  with the issue filing in 4599cd. Instantiation and calls complete
  without suspending on both targets; the signatures are in place for
  a guest that must yield.
- The futures are `Send` on native, checked by a test, so hosts on a
  multi-threaded runtime can spawn them.
- The browser lane loads a component whose core module carries a
  1 MiB data segment through the asynchronous path. For the record:
  the same test also passed through the synchronous constructor in the
  lane's Chromium 147 before the change, so headless Chromium 147 does
  not enforce a synchronous-compile limit on the main thread; the test
  still pins the asynchronous path against a browser that does.
- The smoke test's `run` is `async`; the native binary drives it on a
  current-thread Tokio runtime and the page schedules it with
  `wasm_bindgen_futures::spawn_local`. Every test and the crate
  documentation example await the entry points.
