## What to build

PDD026, "Elements: Rendering".

- **Authoring library.** `View` and `h`. A view is a tree. The library flattens it into the `list<node>` of PDD026 in document order, each node naming its parent's index. `h` puts `checked` and `value` in properties and every other key in attributes. A key option gives a node a stable identity among siblings.
- **Diff.** The host framework keeps the last view of each element and compares the new one with it inside the element's shadow root. It matches siblings by key when they have one and by position when they do not. Same tag: change attributes, properties, events, and text in place. Different tag: replace the DOM node. Remove unmatched nodes and insert new ones.
- **Children.** A view can name another element by its tag. That child is a separate custom element with its own instance and shadow root.
- **When.** Render after `connected` and after each `attribute-changed`.
- **Styles.** The host framework puts the result of `styles` in each shadow root of the tag. A constructed stylesheet shared by the tag's shadow roots is fine.

## Acceptance criteria
- [ ] An element renders and diffs. A test defines an element whose view depends on an attribute. After a change to the attribute, every node whose tag did not change is the same DOM object as before. Only its attributes or text changed.
- [ ] Keys preserve identity. A test renders a keyed list of five items and then reverses it. The five DOM nodes are the same objects as before, in the new order.
- [ ] Styles apply. The computed style of a node in an element matches the CSS that its `styles` returns.
- [ ] A view that names a child element's tag makes a child custom element with its own shadow root.
- [ ] `tests all` and `lint` pass.
