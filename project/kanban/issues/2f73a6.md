## What to build

PDD028, "Both Targets" and the first test case. The proof that one host core serves a component under both macros.

- **Test world.** A record, a variant, and a flags type; an imported resource that `with` maps; a `trappable` import and a `trappable` import with `trappable_error_type`; an async import; a plain import with the `store` flag that returns a future; an exported resource.
- **Host core.** One module with no runtime types.
- **Glue modules.** A Wasmtime glue module over `wasmtime::component::bindgen!` (natively) and a polyfill glue module over `wcmp::bindgen!` (both targets), each implementing the generated traits by calling the core. Their differences are the ones the PDD lists and no others.
- **Runs.** One guest component under the three: Wasmtime natively, the polyfill natively, the polyfill in the browser. Each run records each value that crosses and each error.

Place it beside the existing Wasmtime-side scenarios (`wcmp-scenario-wasmtime`) or in a new test crate; engineering decides.

## Acceptance criteria
- [ ] The same host core runs under both macros: one guest runs under each of the three, and the records of the three runs are equal.
- [ ] The test states the line count of each glue module.
- [ ] Each difference between the two glue modules is one that PDD028 "Both Targets" lists; a difference outside that list is filed as a card.
- [ ] `lint` passes, and `tests all` is green on both targets with the conformance summary unchanged.
