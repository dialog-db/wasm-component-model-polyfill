## What to build
Honor the `cancellable` immediate as Wasmtime 49 does. The reference removed it on 2026-09-04 (component-model #716), but Wasmtime 49 still reads it, and wit-bindgen's C generator still emits `[cancellable][thread-suspend]`, `[cancellable][thread-yield]`, and the four cancellable switch built-ins (`crates/c/src/lib.rs:750-780` at `2f795ab`). One guest binary must behave the same in the polyfill and in Wasmtime.

The translator keeps the immediate of `waitable-set.wait`, `waitable-set.poll`, and the thread built-ins, and passes it to each built-in. Today it drops it (`src/executor/translate.rs:493` and `:532`; `src/executor/thread_yield.rs:54`).

The rules follow Wasmtime (`concurrent.rs:4005-4103` at `v49.0.0-rc.1`):

- Every cancellable built-in first takes a pending request, if one exists, and returns the cancelled result at once. `waitable-set.wait` and `waitable-set.poll` return the task-cancelled event (6). The thread built-ins return 1.
- A cancellable `waitable-set.wait` that blocks can be woken by `subtask.cancel`. It returns the task-cancelled event.
- A cancellable yield, from `thread.yield` or from a promote that yields, is run first by `subtask.cancel`. It returns 1.
- A cancellable suspend, from `thread.suspend` or a switch that suspends, is not woken by `subtask.cancel`. When another thread resumes it, it returns 1 if the request is still pending.
- A built-in without the immediate never takes a request. Its result does not change.

A task that takes a request through a cancellable built-in is in `cancel-delivered`. Without a provider, a cancellable block waits in a nested turn whose readiness condition includes a pending request, so a request made by work inside the nested turn wakes it; a request from a frame below it cannot run, and the block fails with the stack-switch cause.

`cm/binary/binary.wast` 1186 through 1275 stay in the `validation` category, since the parser still reads the vestigial byte as the immediate.

This revises PDD022: the `cancellable` immediate of the thread built-ins is honored.

## Acceptance criteria
- [ ] Repository tests prove each rule on both targets, with a provider: a pending request makes each cancellable built-in return the cancelled result at once; a blocked cancellable `waitable-set.wait` wakes with the task-cancelled event; a ready cancellable yield runs first and returns 1; the request does not wake a cancellable suspend; a built-in without the immediate never takes a request.
- [ ] `lint` passes and `tests all` is green on both targets, any directive that starts passing has its line removed from the expected-failure list, and every line whose reason this card changes is refreshed from a live run.
