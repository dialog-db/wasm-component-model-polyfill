## What to build
Give every boundary context (`src/abi/context.rs`) a copy budget: Wasmtime's default of 128 MiB per crossing, spent by the bytes of every value a lift builds, and a trap when it is spent with Wasmtime's message `too much data is being copied between the host and the guest: fuel allocated for hostcalls has been exhausted`, filed as a new `AbiCause` variant in `src/error.rs`. The design calls the concept the copy budget; only the message keeps Wasmtime's wording, so the corpus matches it by substring. Each list, string, and map lift in `src/abi/lift.rs` charges the count of its elements times the size in bytes of the host value type it builds, as Wasmtime charges the size of its `Val`. A crossing is one context, so one call into the host, one `task.return`, and later one copy has one budget. The budget must land before the stream and future copies do: `streams-massive-send.wast` writes a nested list whose layers alias one another, which no host can materialize, and without the budget the polyfill attempts it. This card does not touch that corpus file; the closing corpus card proves it.

## Acceptance criteria
- [ ] A synchronous call with a list result over the budget fails with the budget cause and Wasmtime's message, and a result under it succeeds, proved by a repository test.
- [ ] A string lift and a map lift charge the budget the same way, each proved by a test.
- [ ] `lint` passes and `tests all` is green on both targets, and any directive that changes outcome has its line refreshed from a live run.

## Review notes
- 2026-09-23 reviewer `review-3fdd33-082d0fb7` on tip `97c8dff`: **needs-changes**. Gates green in the reviewer's VM (`tests all` four lanes, native 887, web 878, conformance 0 unexpected and 0 stale, `lint` 13/13). Blocking: (1) under the default `EngineConfig` a list never reaches the copy budget. `lift.rs:283-284` counts the element bound (`DEFAULT_MAX_LIST_ELEMENTS`, `1 << 22`) before charging the budget; `size_of::<Val>()` is 32 natively and 24 on wasm32, so natively the two limits tie at 4 194 304 elements and in the browser the bound trips first. A probe with a `list<u8>` one element past the budget gave `ListElementLimit` on both targets, never `CopyBudgetSpent`. The criterion-1 test passes only because it sets `max_list_elements(usize::MAX)` (`tests/baseline_copy_budget.rs:86`), and its module doc (`:12-16`) blames only the browser. `streams-massive-send.wast` would hit the element-bound message on both targets, so the closing corpus card could not pass as designed. (2) The outcome depends on the target, against the design's "the behavior is the same on both targets": `size_of::<(Val, Val)>()` is 64 natively and 48 on wasm32, and a map of 2 097 153 `u8 -> u8` entries is refused natively and accepted in the browser; no doc says so. Agrees with Wasmtime (`options.rs:515-528`, `values.rs:226/369/1019/1058`, `typed.rs:1530/1777/2155`): the 128 MiB budget, the exact message, `checked_mul`/`checked_sub` so a refused charge spends nothing, list/map/string/fixed-length list/typed numeric `Vec<T>` charges, no charge for records, tuples, variants, flags or transcoders. No uncharged lift and no double charge; one budget per crossing holds. Shrinking the 300 MiB typed test is justified (Wasmtime refuses it too). Minor: typed `Vec<non-numeric T>` and `HashMap` are charged through `Val` (more conservative than Wasmtime); alignment is checked before the charge; there is no counterpart of `Store::set_hostcall_fuel`, so a host cannot raise the budget. Test gaps: every integration test runs with the element bound off; nothing tests charge-before-reservation (the alloc counter in `baseline_typed_direct` could); no coverage of the flat host-import path, `task.return`, fixed-length lists, or a typed `Vec` refusal.
- 2026-09-23 owner decisions on the blocking findings: (1) the copy budget replaces the element bound. Retire `EngineConfig::max_list_elements`, `DEFAULT_MAX_LIST_ELEMENTS`, and `AbiCause::ListElementLimit`; the budget is the one guard, and a host can raise it through a setter that mirrors Wasmtime's `Store::set_hostcall_fuel`. The public API break is accepted. (2) Charge a fixed cost per element on both targets: 32 bytes per list element and 64 bytes per map entry (the 64-bit `Val` and `(Val, Val)` sizes), not `size_of` of the host type, so the budget trips at the same count in a browser as natively.
