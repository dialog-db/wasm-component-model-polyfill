## What to build

Follow-up from the second review of the PDD027 series, about how errors name a resource type.

1. **The declared-name map leaks.** Review 1 made a resource type that a component declares render with its declared name, `ResourceType::component(n, resource i, "thing")`. The names sit in a process-wide map (`rust/wcmp/src/types/resource_type.rs`, `declared_names`), filled at translation (`src/component/project.rs`, `declare`), and nothing removes them. A browser tool that compiles components again and again, such as the Zena tool, grows the map without bound. Keep the names with the component instead, for example on its translated types, and look them up when an error is rendered.
2. **Host identities are named by their Rust type.** Link-time identity errors and conversion errors (`src/linker/resolve.rs`, `src/resource/resource_any.rs`, `resource_type_mismatch`) render a host identity as `ResourceType::host::<path::Thing>()`. `baseline/resources.rs` asserts that form. c79ad4's "What to build" asks for the name the component declares at the error's position, though this was not an acceptance criterion there. Name the declared resource where the error has a declared position, and keep the Rust type beside it.

## Acceptance criteria
- [ ] Compiling the same component many times leaves the process's memory flat. A test shows that the names live and die with the component.
- [ ] An error at a declared handle slot names the resource as the component declares it. A link-time identity error names the declared resource as well as the host's identity.
- [ ] `lint` passes, and `tests all` is green on both targets with the conformance summary unchanged.
