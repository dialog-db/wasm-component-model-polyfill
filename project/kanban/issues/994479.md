## What to build

Findings from the independent review of 5c1595 (downstream build and packaging, landed `46bc98f57`):

- **Wasmi backend not packaged.** PDD025 (Publication, and the downstream test case) says `cargo package` succeeds for each crate of the runtime layer. `wcmp-wasm-core-wasmi` came after the card was written and is not in `publishedCrates`; the reviewer checked that adding it packages and verifies on both targets.
- **The `[patch]` guard is a regex.** The quoted-key table `['"patch".crates-io']` passes it (`flake.nix:1053`), and `[replace]` or a `.cargo/config.toml` `[patch]` inside `rust/wcmp-downstream` are not checked. Parse the manifest (an eval-time assert on `builtins.fromTOML`) or check `cargo metadata` sources.
- **No wasm32 clippy.** `lint`'s clippy runs natively only, so the wasm32 code of `wcmp-wasm-core-web` and the `cfg(wasm32)` paths of `wcmp` are never linted; the `dead_code` warning on `Flight::is_suspended` (`rust/wcmp-wasm-core-web/src/flight.rs:114`) goes unseen. Add clippy for `wasm32-unknown-unknown` and fix the warning. (The switch review also found a `clone_on_copy` in the web tests that `lint` missed.)
- **Downstream lock refresh.** With `--locked`, `rust/wcmp-downstream/Cargo.lock` goes stale whenever a published crate's dependencies change; give it a documented refresh (a menu command or `tests regenerate`).
- **Downstream runs nothing.** The downstream only builds; a native test that calls its `engine()` would prove it links at run time.
- **Optional.** Exclude `tests/` from the `wcmp` package (8.6 MiB unpacked); a menu command to build one flake check.

## Acceptance criteria
- [ ] The Wasmi backend packages and verifies on both targets in the `package` check.
- [ ] The guard rejects any `[patch]` or `[replace]` in the downstream, however spelled.
- [ ] `lint` runs clippy for wasm32 with `-D warnings`, and it passes.
- [ ] The downstream lock has a documented refresh, and a native test runs the downstream.
- [ ] `tests all` and `lint` pass.
