## What to build

debug`, `tests webkit no-provider`, and `tests fidelity webkit` (970834).

The lanes (a23124) run the web debug archive in WebKitGTK's MiniBrowser on
a headless Weston, one browser per test binary, in about two minutes on
the owner's host once the archive is built. They fail today on the
WebKit-only tests that fbbef9, 4b5a17, and 1429ec carry, so they cannot
gate a run yet.

Add them to the `web debug` group of `.github/workflows/test.yml`, which
builds the same archive, and to `tests all`. The lanes exist on Linux
only, so `tests all` runs them only there. Check on a runner that the
headless Weston starts (the runner may have no `/run/user/<uid>`, and the
script falls back to `/tmp`) and that WebKitGTK and Weston come from a
binary cache rather than a build.
