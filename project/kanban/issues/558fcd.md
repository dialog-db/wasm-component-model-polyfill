## What to build
PDD020 (around line 176) says that delivering a subtask's resolution releases every handle the caller lent for the call, and PDD020 (around line 399) and PDD014 state the subtask-lender rule for host tasks and host calls. For a guest-to-guest prepared call the lend is recorded elsewhere: `transfer_borrow` in `src/executor/intrinsics.rs` lends to the current scope, which `start_call` has set to the callee's *task* before the start function runs, so the caller's lend ends at the callee's task exit — for a callback export that `task.return`s and keeps running, later than the reference's `Subtask.deliver_resolve` — and `release_subtask`'s `undo_lends(Scope::Subtask)` is a no-op on that path (proved: with it disabled, a post-failure drop of the lent owning handle still succeeds). Four doc sites credit the cancellation wrongly: `start_call.rs` around lines 449-451 (`release_subtask`) and 432-435 (`abandon`), `callback_task.rs` around lines 227-230, and `tests/baseline_async_start_call.rs` around lines 26-27 and 587-590. Decide with the design whether a guest-to-guest call's lends should sit on the subtask (released at delivery, as the reference does) or stay on the callee's task (released at its exit), implement the chosen rule so the docs and the code agree, and add a test that pins when the lend ends for a callback callee that returns and keeps running.

The same rule should say what a lend counts. `src/resource/tables.rs:455-457` refuses to lend a `Borrow` entry, and `transfer_borrow` and `lift.rs:416-426` lend only owning entries, so a caller that drops a borrow entry while an asynchronous subtask still holds it is not refused here. The reference's `add_lender` counts any handle and `canon_resource_drop` traps on `num_lends != 0` (`definitions.py:2267-2270`); Wasmtime's `resource_lend` skips the count for a borrow, so the polyfill matches the tie-break and departs from the reference. State the departure and its reason in the same place the lend rule is stated. The checkup that found this filed the defining-instance borrow lift and the host borrow lower as their own cards under the same label; this card owns the written rule they cite.

## Owner decisions (2026-09-21)
A lend lives on the subtask and ends when the caller takes delivery of the resolution, as the reference's `Subtask.deliver_resolve` does, for every crossing. Guest to guest: the lend the caller's lift records goes on the subtask, not on the callee's task, and `release_subtask`'s `undo_lends(Scope::Subtask)` becomes the live path. Host to guest, which no document states today: a host lend ends when the host's call yields its result, on return for `Func::call` and when the awaited future resolves for `call_concurrent`, so a callback callee that returns and keeps running holds no host handle past its `task.return`. A borrow entry is not counted as lent, as Wasmtime does and the reference does not; the rule states that departure and its reason.
