## What to build
PDD020 (around line 176) says that delivering a subtask's resolution releases every handle the caller lent for the call, and PDD020 (around line 399) and PDD014 state the subtask-lender rule for host tasks and host calls. For a guest-to-guest prepared call the lend is recorded elsewhere: `transfer_borrow` in `src/executor/intrinsics.rs` lends to the current scope, which `start_call` has set to the callee's *task* before the start function runs, so the caller's lend ends at the callee's task exit — for a callback export that `task.return`s and keeps running, later than the reference's `Subtask.deliver_resolve` — and `release_subtask`'s `undo_lends(Scope::Subtask)` is a no-op on that path (proved: with it disabled, a post-failure drop of the lent owning handle still succeeds). Four doc sites credit the cancellation wrongly: `start_call.rs` around lines 449-451 (`release_subtask`) and 432-435 (`abandon`), `callback_task.rs` around lines 227-230, and `tests/baseline_async_start_call.rs` around lines 26-27 and 587-590. Decide with the design whether a guest-to-guest call's lends should sit on the subtask (released at delivery, as the reference does) or stay on the callee's task (released at its exit), implement the chosen rule so the docs and the code agree, and add a test that pins when the lend ends for a callback callee that returns and keeps running.

## Acceptance criteria
- [ ] A test proves when a handle lent through a guest-to-guest prepared call is given back for a callback callee that `task.return`s and then continues, and the rule is stated once in the docs the four sites now contradict.
- [ ] `lint` passes and `tests all` is green on both targets with the conformance summary unchanged.
